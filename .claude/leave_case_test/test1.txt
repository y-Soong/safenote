# ■ 엔진의 실제 계산 규칙 (먼저 읽어주세요)
#   1) 월차(STATUTORY_MONTHLY)
#      = 입사+1개월, +2개월 … 만근 완성일마다 1일씩 'per-월 누적', 상한 min(근속개월, 11).
#      ★ 부여기준(AXIS)·처리방식(KEEP/RESET)과 무관하게 항상 누적된다. (코드: computeMonthlyPeriods, line 178 "처리방식·AXIS 무관")
#   2) 본연차(STATUTORY_ANNUAL) = 15일
#      · 입사일 기준  : 근속(경력가산 포함) 12개월 이상이면 부여.
#      · 회계연도 기준 : 입사 후 '회계연도 시작일'을 1번이라도 지나면(crossedFiscalStarts>=1) 부여 = flat 15.
#   3) 비례부여(PRORATE) = (입사일 ~ '다음' 회계연도 시작일 일수 ÷ 365) × 15, 올림(AXIS4).
#      ★ '첫 부분기간'(회계 시작 0회 도래)에서만 적용. 한 번이라도 지나면 비례가 아니라 flat 15.
#   4) 근속가산 = 3년차부터(2년 간격). ★ 이번 문서는 전부 근속 1년 미만 → 전부 0.
#
# ■ 입사일 변경 처리방식 3종
#   - KEEP_AND_BACKFILL  : 기존 부여 유지 + '유효기간 내 과거 본연차/근속가산' 누락분만 소급 INSERT.
#   - KEEP_AND_APPLY_NEW : 기존 부여 유지 + 과거 소급 없음.
#   - RESET_ALL          : 기존 법정부여를 소프트 취소(STATUS=CANCELED) 후 '새 입사일'로 전체 재계산.
#
#   ★★ 핵심 1 — 이번 문서는 전부 근속 1년 미만이라 '소급할 과거 본연차/근속'이 아예 없다.
#       그리고 월차는 처리방식과 무관하게 per-월 누적된다.
#       ⇒ 이 문서의 모든 행에서 BACKFILL 과 APPLY_NEW 결과는 '항상 동일'해야 한다.
#         (둘을 다르게 적은 칸은 §8.5.6 '정책 의도'와는 맞지만 '현재 엔진 동작'과는 불일치 → 정정 필요)
#   ★★ 핵심 2 — 월차 동작:
#       · 미래로 변경 : KEEP은 기존 부여 유지(안 줄어듦) / RESET만 새 입사일로 재계산(줄어듦).
#       · 과거로 변경 : KEEP/RESET '모두' 새로 생긴 과거 달을 채움(늘어남). ← KEEP도 늘어난다!
#   ★★ 핵심 3 — 회계연도 케이스는 '한 줄 = 현재 시점 1회 부여 결과'로 봐야 한다.
#       월차 + 본연차15(또는 첫기간이면 비례)만 나온다. '비례 + flat15 + 차년도'를 한 줄에 합산하지 말 것.

# 기존 입사일 : 2025-07-16
# 현재일 : 2026-05-25
# 근속 : 10개월

1. 연차 부여 기준
	1. 입사일 - 월차만 부여
		: 근속 10개월 - 연차 10
		# [검토] ✅ 맞음.  월차 = min(근속10, 11) = 10.

	2. 회계연도 기준 - 월차만 부여
		: 근속 10개월 - 연차 10
		# [검토] ⚠️ 회계연도 시작일(AXIS2)에 따라 달라짐 — 전제가 빠져 있음.
		#   · 회계시작이 입사~현재 사이에 '아직 안 지난' 경우(예: 7/1 시작): 월차 10만 → 10 (맞음)
		#   · '지난' 경우(예: 1/1 시작 → 2026-01-01 도래): 월차 10 + 본연차 15 = 25
		#   엔진은 회계시작이 1번이라도 도래하면 AXIS3와 무관하게 본연차 15를 준다.
		#   '월차만'은 첫 부분기간(회계시작 미도래) 안에서만 성립.

	3. 회계연도 기준 - 비례 부여(올림)
		: 근속 10개월(비례부여 6개) - 연차 21개, (35개 ? , 10 + 15 + 10)
		# [검토] ❌ 모델이 엔진과 다름.
		#   · 엔진 비례 = (입사일 ~ '다음' 회계연도 시작 ÷ 365) × 15, 올림.
		#     예) 회계 7/1 시작 + 입사 2025-07-16 → 다음 시작 2026-07-01 → 약 350일
		#         (350/365)×15 = 14.4 → 올림 15  (즉 신입은 거의 1년치가 나옴, '6'이 아님)
		#   · 비례는 '첫 부분기간'에서만. 회계시작이 지났으면 비례가 아니라 flat 15.
		#   · '10+15+10' 같은 '월차+본연차15+비례' 동시 합산은 엔진에 없음(같은 기간에 비례와 flat15가 같이 나오지 않음).
		#   정확값: 한 줄=한 시점 결과로 보면 [월차 10] + [비례(첫기간) 또는 flat15(도래후)]. 회계시작일 주시면 재계산.

	4. 회계연도 기준 - 차년도 일괄 부여
		: 근속 10개월 - 25
		# [검토] ⚠️ '한 줄 = 한 시점' 기준으로 보면:
		#   · 첫 부분기간(회계시작 미도래) 시점: 월차만 = 10. (본연차 15는 '다음 회계연도 시작'에 별도 부여)
		#   · 회계시작 도래 후 시점: 월차 10 + 본연차 15 = 25.
		#   25는 '회계시작이 도래한 뒤' 시점에서만 맞음(두 부여 시점을 합친 누적값).

#   · KEEP(둘 다): 기존 10건을 '취소하지 않고 유지'. 새 입사일의 8개월(202510~202605)은 이미 다 존재 → 신규 0 → 10 유지.
#   · RESET     : 기존 10건 취소 후 새 입사일로 8개월 재발급 → 8.

		2. 기존 부여 유지 + 신규 부여만 변경된 입사일로 계산 : 10개     # [검토] ✅ (BACKFILL과 동일)
		3. 모든 부여 삭제 후 재계산 : 8개                              # [검토] ⚠️ 월차 기준 8 맞음. 단 회계시작 도래했으면 본연차 15 포함될 수 있음.

		1. 입사일 수정 방식 기존 부여 유지 + 누락분 소급 부여 : 25개   # [검토] ⚠️ KEEP은 기존 부여 유지값. (회계시작 도래 후면 월차10+본연차15=25 가능)
		2. 기존 부여 유지 + 신규 부여만 변경된 입사일로 계산 : 25개     # [검토] ✅ BACKFILL과 동일(둘 다 25) — 이 행은 일치.
		3. 모든 부여 삭제 후 재계산 : 23개                            # [검토] ⚠️ 새 입사일(근속8)로 재계산. 월차8 + (도래했으면)본연차15. 회계시작 전제 필요.

#   · 새로 생긴 달 = 202507 1건. ★ per-월 누적은 처리방식 무관 → KEEP/RESET '모두' 202507을 채워 11이 된다.
#   · 즉 이 블록의 월차 결과는 처리방식과 무관하게 전부 11. (APPLY_NEW만 10으로 적은 건 오류)

		2. 기존 부여 유지 + 신규 부여만 변경된 입사일로 계산 : 10개     # [검토] ❌ 11이어야 함. 월차 per-월 누적은 KEEP 종류와 무관하게 새 달(202507)을 채움.
