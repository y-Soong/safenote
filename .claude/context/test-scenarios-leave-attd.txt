# 연차·근태 요청 테스트 쿼리 (요청유형별 세팅 / 원복)

작성일: 2026-05-24. 실 DB(MySQL, cmpnyCd='001') 기준. 로컬/개발 DB에서만 실행.

[공통 전제]
- 회사 001 / 사업장 00001 / 요청자 = 윤순기(20260400013, 부서 n1)
- 처리(승인·반려)는 매니저로 로그인해서 한다 → 김여진(20260400012, master, 사업장 00001)
  · Attd_10 '근태 보정' / '초과근무 상신' 탭: 매니저 + 같은 사업장이면 노출 (월/부서 무관)
  · Attd_10 '연차 상신' 탭: 결재자(APPROVER_USER_CD)=로그인 사용자일 때 노출 → 결재자=김여진으로 세팅함
- 근무관리(Attd_07)에서 교차 확인 시: 사업장 00001 / 부서 n1(중곡사업장) / 월 2026-10
- 사용 날짜(생성/사용): A=2026-10-06, B=2026-10-07, C=2026-10-08
- 사용 날짜(수정): D=2026-10-13(근태수정), E=2026-10-15(초과근무수정), F=2026-10-14→2026-10-18(연차수정)
- 같은 영역을 다시 테스트하려면 해당 원복(A-1 ~ F-1)을 먼저 돌린 뒤 세팅을 재실행한다.

[PRAFTA-025 추가분 — 수정 요청 D/E/F]
- D 근태수정(REQ_TYPE='02')은 기존 백엔드가 이미 처리(접수함이 01/02 노출). 본 작업에선 테스트 데이터만 추가.
- E 초과근무수정('04')·F 연차수정('06')은 본 작업(PRAFTA-025)에서 백엔드 승인/반려 처리를 신규 구현했다.
  · 04: 접수함 '초과근무' 그룹에 노출, 승인 시 기존 OT(TARGET_ID) 시각 UPDATE(허용구간 재검증).
  · 06: 결재 인박스에 노출, 최종 승인 시 기존 사용기록(TARGET_ID) 일자/일수 in-place 갱신 + 부여 재동기화
        + 근무계획 연차블록 이동. 반려는 기존 휴가를 건드리지 않음(수정은 승인 시에만 반영).
- 수정 시나리오 원복은 (1)'수정 원복'(승인으로 바뀐 값을 수정 전으로 UPDATE) + (2)'전체 정리'(테스트 생성물 제거)로 구성.
- 원복 블록 첫 줄의 `SET SQL_SAFE_UPDATES = 0;` 은 Workbench safe update mode(Error 1175) 회피용.
  블록을 따로 실행하면 그 SET 줄을 같이 실행할 것(세션 한정, 재접속 시 자동 원복).
