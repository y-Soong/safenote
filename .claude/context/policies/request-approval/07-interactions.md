# **7. 인터랙션 정의**

## **7.1 행 클릭·상세 진입**

- 리스트 행 클릭 시 우측 상세 패널에 해당 요청 로드. 행에는 좌측 4px Primary 인디케이터 표시.

- 상세 패널 로딩 동안에는 ⑤ 관리자 결정 영역을 스켈레톤으로 — 잘못된 결정 방지.

- 상세 패널 닫기는 따로 두지 않음 (항상 노출). 다만 좁은 해상도에서는 우측 패널이 풀스크린으로 전환 (반응형).

## **7.2 선점(처리 잠금) — 공통 §9**

- 상세 패널 진입 시 즉시 선점. 다른 관리자에게는 본 행이 "처리중 — {관리자명}"으로 표시, 체크박스 disabled.

- 완료(승인/반려/닫기)·로그아웃·세션 종료·브라우저 종료 시 즉시 해제. 타임아웃 없음, 강제 해제 없음.

- 타관리자가 본 행을 열면 ⑤ 관리자 결정 영역은 read-only + "{관리자명}이 처리 중" 배너.

## **7.3 본인 결재 — 정책 §9.5**

- 요청자 = 승인권자인 경우: 정책 §9.5의 "자기 승인 원칙" 적용. 자체근태승인여부 ON인 노드의 본인 건은 자동 승인. 상위 공동 처리 범위에서는 본인 건 자동 승인 금지.

- 본 화면에서 "본인 결재 차단" 행은 ⑤ 관리자 결정 비활성화 + "이 요청은 본인의 결재 권한 범위가 아닙니다. 상위 관리자에게 처리가 위임됩니다." 안내.

## **7.4 마감 차단**

- 스케줄 수정·연차: 스케줄 마감 후이면 그 자체가 정책 위반이므로 ② 검증·제약 영역에서 "마감 후 신청" 경고 + ⑤ 비활성화.

- 초과근무: 사후 상신 기한(=근태 마감일) 도달 시 동일하게 차단. 단, "근태 보정으로 예외 처리 가능" 링크 노출.

- 근태 보정: 근태 마감 전까지만 처리. 마감 후이면 "마감 해제 후 처리" 안내(§1.4) — 마감 관리 화면 링크.

## **7.5 충돌 경고 — §9.6.2**

- 스케줄 ↔ 연차 ↔ 출퇴근 기록 간 충돌이 감지되면 ② 검증·제약에 Amber 경고 카드 + 충돌 대상 링크.

- 연차 신청 후 출근 기록이 들어왔거나, 스케줄 수정으로 기존 연차 시간 단위 구간을 침범하는 등의 케이스.

## **7.6 시간 조정 후 승인**

- 스케줄·근태 보정·초과근무 탭에서만 적용. 연차 탭에는 없음.

- "조정 후 승인" 선택 시 시간 입력 필드 활성화. 시스템 계산값을 기본 채움(초과근무), 또는 원본 로그 추정값(근태 보정).

- 인라인 검증: §5(1일 2구간·2회 출근), §6.6(스케줄 2구간 겹침 금지), §10.2(표준화 단위). 위반 시 [처리하기] 버튼 비활성화 + 인라인 에러.

## **7.7 일괄 처리**

- 체크박스 다중 선택 → 동일 탭·동일 상태(대기)·차단행 미포함이어야 활성.

- 일괄 승인은 "요청대로 승인"만 가능 — 시간 조정이 행마다 다르므로 일괄에서는 허용하지 않는다.

- 일괄 반려: 사유 입력 모달(10자 이상 필수, 모든 선택건에 동일 사유 적용). 공통 정책서 §13.3 확인 모달 패턴 적용.

- 단축키: A(승인) / R(반려) / J·K(행 이동) — 시안 단축키 유지. 차단행을 만나면 자동 스킵.

## **7.8 알림·실시간 갱신**

- 새 요청 도착 시 탭 배지 카운트 + 알림 배너 카운트 자동 증가 (폴링 또는 푸시). 행을 즉시 추가하지는 않고 "새 요청 N건 — 새로고침" 토스트 노출 — 처리 중 행이 갑자기 위치 이동하는 것 방지.

- 승인/반려 시 토스트(우측 하단) + 결과 알림이 §10 채널로 요청자에게 전송됨.
