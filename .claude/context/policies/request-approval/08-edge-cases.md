# **8. 예외 케이스**

| **상황** | **처리** |
| --- | --- |
| 요청자가 본인의 결재권자 (자체근태승인 ON 노드) | §9.5 자기 승인 원칙으로 자동 승인 — 본 화면에 도달하지 않음. 처리 이력은 "자동 승인 (본인)"으로 표기. |
| 요청자가 본인의 결재권자 (상위 공동 처리 범위) | 자동 승인 금지. 본 화면에서 "본인 결재 차단" 상태로 표시되고 상위 결재권자에게 노출. |
| 다른 관리자가 선점 중 | 읽기 전용. 누가 선점 중인지 표시. 다른 행은 정상 처리 가능. |
| 마감 기간의 요청 | 정책상 신청 자체가 불가했어야 하나, 마감 시점 이후 도착한 트랜잭션을 위해 ② 차단 + 안내 배너 표시. |
| GPS 미확인이 섞인 보정 요청 | 승인 시 GPS 미확인 자동 해소(§7.3). 행 메타에 "GPS 미확인 해소" 칩 표기. |
| 초과근무 사후 상신이 마감일 직전 들어옴 (D-0) | 처리 가능하나, 마감 컬럼에 D-0/Danger. 알림 배너에 "마감일 도래 — 처리 필요 N건" 강조. |
| 동일 일자에 두 종류 요청 동시 대기 (예: 스케줄 수정 + 초과근무) | 스케줄 수정을 먼저 처리하도록 정렬 가중치 부여. 충돌 가능성을 ② 검증·제약에 표시. |
| 연차 결재단계 다단 — 중간 승인자만 통과 | 현 결재 단계에 해당하는 승인권자만 본 화면에 노출. 처리 이력 타임라인에 단계 표시(1/2단 완료, 2/2단 대기 등). |
| 일괄 승인 중 1건이 검증 실패 | 전체 트랜잭션 rollback이 아니라 행 단위 처리 결과 분리(N건 성공 / M건 실패) — 실패 건은 사유와 함께 상단 토스트. |
| 요청 처리 후 근로자가 모바일에서 취소 요청 | v1에서는 요청 후 취소 불가 — 반려·재신청 플로우로 처리(정책 §9.5 이력 보존 원칙 유지). 향후 검토. |
