# PRAFTA 정책서 (마스터 INDEX)

PRAFTA 서비스의 모든 비즈니스/도메인 정책의 단일 출처(Single Source of Truth). 모든 에이전트는 작업 시작 전 본 INDEX와 관련 하위 INDEX를 정독한다.

## 디렉토리 구조

```
.claude/context/policies/
├── README.md                   ← 본 파일 (마스터 INDEX)
├── CHANGELOG.md                ← 정책서 변경 이력
├── common/                     ← PRAFTA + SAFETY NOTE 공통 (v1.1)
│   ├── INDEX.md
│   └── 01-overview.md ~ 13-ui-ux.md
├── attd/                       ← 근태관리 (v1.0)
│   ├── INDEX.md
│   └── 01-overview.md ~ 16-scenarios.md
└── request-approval/           ← 요청승인관리 재기획 (v0.1)
    ├── INDEX.md
    └── 01-overview.md ~ 12-changelog.md
```

## 정책서 우선순위 (충돌 시 적용)

**같은 주제에 대해 두 정책서가 다르게 말하면 위에 적힌 쪽이 이긴다.**

1. **요청승인관리 재기획서 (v0.1)** — 단일 출처 선언 영역(§1.2): 요청 승인 화면, 사후 상신 기한, 탭 구성 등.
2. **공통 정책서 (v1.1)** — 권한·조직·사업장·계정·인증·보안 등 공통 주제.
3. **근태관리 정책서 (v1.0)** — 근태 도메인 전용 규칙(§9.6, §9.3.1 등은 우선순위 1번에 의해 일부 무효화됨).
4. **기술 정책서 (`developer.md`, `security.md`, `qa.md`, `CLAUDE.md`)** — 비즈니스 규칙과 충돌 시 비즈니스 정책서가 우선. 기술 정책서는 구현 방식만 다룬다.

충돌 의심 시 사용자에게 즉시 보고. 임의 해석 금지.

## 에이전트별 정책서 참조 규칙

각 에이전트의 정책서(`.claude/agents/*.md`)에 상세 규칙이 있다. 핵심만 요약:

- **planner**: 작업 분해 전 관련 정책서 섹션을 모두 정독. 요구사항 번호에 해당 정책서 섹션 출처 명시(예: "공통 §5.6.2", "재기획서 §3.2").
- **developer**: planner가 적은 출처 섹션만 정독. 추가 정책 의문이 생기면 사용자에게 확인 요청(임의 해석 금지).
- **security**: 인증/세션/PII 작업 시 `common/03-account-auth.md`, `common/11-security-privacy.md` 필수 정독. 권한 작업 시 `common/08-permissions.md`.
- **qa**: 비즈니스 룰 엣지 케이스 점검 시 planner가 적은 정책서 섹션 정독. 충족도 표의 "근거" 칸에 정책서 섹션 함께 표기.

## 정책서 갱신 절차

1. 사용자가 docx 원본을 갱신 (예: `PRAFTA_공통_정책서_v1_2.docx`).
2. 사용자가 갱신 사실을 에이전트에게 알린다.
3. 에이전트(또는 사용자)가 `extract-text`로 마크다운 추출 후 본 디렉토리 분할 갱신.
4. `CHANGELOG.md`에 변경 내역 추가.
5. `INDEX.md`의 키워드 매핑 갱신.

## 참고: docx 원본

원본 docx는 별도 보관(예: `.claude/context/policies/_source/`)하거나 사용자 로컬에 둔다. 에이전트는 docx를 직접 읽지 않고 분할된 .md만 참조한다.
