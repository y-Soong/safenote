## 9. 근로자 요청 · 관리자 승인

### 9.1 개요

근로자는 모바일 앱에서 스케줄 수정 요청, 초과근무 상신, 연차 신청을 할 수 있다. 관리자는 관리자 웹 또는 관리자 앱에서 이를 승인/반려한다.

### 9.2 스케줄 수정 요청

| 항목 | 내용 |
| --- | --- |
| 신청 주체 | 근로자 (모바일 앱) |
| 신청 조건 | 해당 일자 스케줄 존재 + 스케줄(근태) 마감 전. **시간 방향 제한 없음(과거·현재·미래 모두 신청 가능)** |
| 필수 입력 | 수정 대상 일자, 변경 내용(시간/유형), 사유 |
| 처리 방식 | 대기 → 관리자 승인 시 반영 / 반려 시 기존 유지 |
| 마감 제한 | 마감 후 신청 불가 |
| 수정 경합 | 대기 상태인 동안 관리자 직접 수정 불가 |
| 이력 보존 | 요청/승인/반려 이력(사유 포함) 보존 |

> 변경 이력: 2026-05-31 (prafta-app-013) — 모바일 앱 신청 시점을 미래로만 제한하던 종전 게이팅을 폐기하고, 스케줄 존재 + 미마감이면 과거·현재·미래 모두 신청 가능으로 명시. (앱 게이팅 산출 = `AppAttd01ServiceImpl.computeWeekActions` / 오늘·일상세 동일 산출)

### 9.3 초과근무 상신

#### 9.3.1 기본 규칙

| 항목 | 내용 |
| --- | --- |
| 신청 주체 | 근로자 (모바일 앱) |
| 상신 시점 | **사후(과거·현재)만 허용. 사전(미래) 상신 차단.** |
| 신청 조건 | **해당 일자에 출근 기록 1건 이상 존재** + 근태 마감 전. 오늘 진행 중(근무중·전 구간 미완료)이면 비활성. |
| 상신 기한 | 해당 일자의 **근태 마감 전까지** (D+5일 사후 기한은 폐기 — 요청승인관리 재기획서 §3.2) |
| 필수 입력 | 근무 일자, 시작/종료 시간, 사유 |
| 처리 방식 | 대기 → 승인 시 추가근무로 정산 반영 / 반려 시 미반영 |
| 이력 보존 | 요청/승인/반려 이력(사유 포함) 보존 |

> 변경 이력: 2026-05-31 (prafta-app-013) — ① 상신 시점을 "사전/사후 모두" → "사후(과거·현재)만, 미래 차단"으로 변경. ② 신청 조건에 "출근 기록 존재"를 명시(종전 앱 게이팅은 전 구간 완료(`completed`)를 요구했으나, 본 결정은 출근 기록 존재(`hasAttendance`)로 완화하되 오늘 근무중은 제외). ③ D+5일 사후 기한 서술 폐기, 마감 전까지로 통일(§3.2 정합).

#### 9.3.2 상신 기한 의의

현장에서 급작스럽게 발생하는 초과근무는 사전 상신이 어려운 경우가 많다. 이를 반영해 **근무일 이후(사후) 상신을 허용**하되, 그 기한은 **해당 일자의 근태 마감 전까지**로 한다.

- 근무일 D에 초과근무 발생 → 해당 월(또는 사업장 마감 단위)의 **근태 마감 전까지** 상신 가능.

- 마감 이후에는 상신 불가 (마감 해제 또는 근태 보정 절차를 따른다).

- **미래(아직 도래하지 않은 일자)에 대한 사전 상신은 불가.** 출근 기록이 존재해야 상신할 수 있다.

#### 9.3.3 초과근무 발생 케이스

| 케이스 | 처리 |
| --- | --- |
| 조기 출근 (스케줄 시작 전 출근) | 스케줄 구간 밖 시간은 초과근무 상신 |
| 연장 (스케줄 종료 후 퇴근) | 스케줄 구간 밖 시간은 초과근무 상신 |
| 휴일·스케줄 없는 날 근무 | 전량 초과근무 상신 |
| 스케줄 구간 수 초과 출근 | 초과분 전체 초과근무 상신 |

> 위 케이스 모두 **해당 일자에 출근 기록이 존재**해야 상신 가능하다(사후 상신 전제).

#### 9.3.4 관리자 승인 액션

- 요청대로 승인: 상신된 시간 그대로 반영

- 시간 조정 후 승인: 관리자가 승인 시간을 조정하여 반영 (시스템 계산 참고값 함께 표시)

- 반려: 사유 필수 입력

> **초과근무 유형 비저장/비표시 (prafta-043):** 초과근무는 유형(연장/야간/휴일)을 입력·저장·표시하지 않는다. 시스템은 유형 구분 없이 단일 '초과근무'로만 관리한다. 위 9.3.3 표는 초과근무 "발생 시나리오"를 설명할 뿐 저장형 유형값(OT_TYPE)을 정의하지 않으며, 종전 OT_TYPE 컬럼은 prafta-043에서 전면 파기되었다.

### 9.4 연차(휴가) 신청

| 항목 | 내용 |
| --- | --- |
| 신청 주체 | 근로자 (모바일 앱) |
| 신청 조건 | **해당 일자에 출근 기록이 없을 것** + 근태 마감 전. **시간 방향 무관(과거·현재·미래 모두 신청 가능)**. 스케줄 존재 여부 무관. |
| 스케줄 없는 날 | 스케줄이 없는 날(`!hasSchedule`)은 **full-day(온전한 하루) 연차만** 신청 가능. 반차·시간차(시간 단위) 연차 불가. |
| 필수 입력 | 휴가 종류, 대상 일자(구간), 사유(연차 타입별) |
| 증빙 | 연차 타입 설정에 따라 증빙 파일 첨부 |
| 처리 방식 | 대기 → 승인 시 휴가 적용 및 출근 차단 / 반려 시 미적용 |
| 마감 제한 | 마감된 기간 신청 불가 |
| 이력 보존 | 요청/승인/반려 이력(사유 포함) 보존 |

> 변경 이력: 2026-05-31 (prafta-app-013) — ① 종전 "스케줄 존재 필수" 조건을 완화: 스케줄 유무와 무관하게 신청 가능하되, **출근 기록이 있으면 신청 불가**(이미 출근한 날은 연차 대상 아님). ② 시간 방향 제한 폐기(과거·현재·미래 모두). ③ 스케줄 없는 날은 full-day 연차만 허용을 명시(앱 응답 힌트 `leaveFullDayOnly = !hasSchedule`; "full-day만" 강제는 연차 신청 폼 구현 시 적용 — 현재 폼은 stub, follow-up).

### 9.5 관리자 승인/반려 공통 규칙

- 승인/반려 사유 입력 필수 (이력 보존)

- 선점(처리 잠금) 적용: 동시 처리 방지

- 자기 승인 원칙: 요청자=승인권자면 자동 승인 가능, 단 상위 공동 처리 범위에서는 본인 건 자동 승인 금지

- 처리 결과는 근로자에게 알림 전송

→ 선점 정책은 공통 정책서 9장 참조

### 9.6 요청 승인 관리 화면

관리자 웹의 통합 승인 화면은 3개 탭으로 구성된다.

- 스케줄 수정 요청 탭

- 초과근무 상신 탭

- 연차 상신 탭

#### 9.6.1 공통 기능

- 필터: 조직, 사용자명, 요청 상태, 기간

- 일괄 승인/반려

- 체크박스 선택

- 우측 상세 패널

- 처리 이력 타임라인

#### 9.6.2 엣지 케이스 처리

| 상황 | 처리 |
| --- | --- |
| 본인 결재 차단 | 요청자=승인권자 시 자동 승인 또는 차단 (9.5 자기 승인 원칙) |
| 마감 기간 차단 | 마감된 기간의 요청은 처리 불가, 배너 표시 |
| 다른 관리자 선점 | 읽기 전용으로 표시, 선점자 정보 노출 |
| 충돌 경고 | 스케줄/휴가/출근 기록 간 충돌 시 경고 표시 |

#### 9.6.3 상세 패널 구성

- 기본 정보 (요청자, 요청일시, 상태)

- 요청 내용 비교 (Before/After)

- 검증/제약 정보

- 사유 및 증빙

- 처리 이력 타임라인

- (초과근무) 계산 비교 3단: 시스템 계산값 / 상신값 / 승인값

- (연차) 영향도 정보: 현재 스케줄, 승인 시 상태, 잔여 연차, 충돌 여부
