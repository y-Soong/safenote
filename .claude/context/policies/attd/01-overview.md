## 1. 개요

### 1.1 목적

본 정책서는 PRAFTA 근태관리 모듈의 운영 기준을 정의한다. GPS·모바일 기반 출퇴근, 스케줄 운영, 휴가, 근로시간 산정, 마감 처리 등 근태 전 영역의 일관된 운영 기준을 수립한다.

### 1.2 적용 범위

- 전 임직원(정규/비정규직), 현장 근로자, 승인권자, 근태 담당자

- 일일계정 사용자(비정규직/일용직)

- 관리자 웹(마스터 관리, 승인, 마감, 리포트) 및 모바일 웹앱(출퇴근, 요청, 승인)

### 1.3 공통 정책서와의 관계

권한·조직·사업장·계정·선점·보안 등 공통 주제는 PRAFTA 공통 정책서에 정의되어 있으며, 본 정책서는 이를 전제로 한다. 중복을 피하기 위해 공통 주제는 참조 형태로 연결한다. **일일계정 및 슬롯 관리**는 공통 정책서 §5에 정의되어 있으며, 집행 화면은 "일일계정관리"이다.

### 1.4 핵심 운영 원칙

- 원장(출퇴근 원본 로그)은 삭제·변조하지 않는다.

- 스케줄은 계획 데이터이며, 정산 값은 정책 규칙(정규/추가근무 산정, 자동 휴게)으로 산출한다.

- 변경은 요청 → 승인/반려 → 반영 순으로, 모든 이력을 보존한다.

- 마감 후 수정은 마감 해제 → 수정/승인 → 재마감으로만 처리한다.

- 1일 최대 2구간 근무, 1일 최대 2회 출근 제한 (5장 참조)

- 휴게시간은 자동 공제만 운영한다. (수동 입력·예외 승인 없음)

- 휴가 승인일·시간 단위 휴가 구간은 노무 수령 거부 적용 (출근 차단)

- GPS 미확인은 등록은 허용하되 확인 필요로 관리한다. (근태 마감 전 해소)

### 1.5 용어

| 용어 | 정의 |
| --- | --- |
| 스케줄 | 근로자의 계획 근무 데이터. 일자별 근무 유형과 구간 정보 포함. |
| 근무 유형 | 정규 근무를 정의하는 유형. 근무명·시작/종료 시간·휴게시간·유급 여부 등. |
| 교대 스케줄 | 복수 근무 유형을 반복 패턴으로 조합한 교대 근무 계획. |
| 1구간 / 2구간 | 1일 근무가 연속된 1구간이냐, 분리된 2구간이냐를 구분. 최대 2구간까지 허용. |
| 출퇴근 원본 로그 | 근로자가 등록한 출근/퇴근 시각. 삭제 불가의 원장 데이터. |
| 근태기록 | 정산용 근로시간 기록. 로그 + 스케줄 + 승인된 변경 + 자동 휴게를 종합해 산출. |
| 추가근무(초과근무) | 정규 근무 외에서 수행한 근무. 승인 필수. |
| 스케줄 마감 | 기간 스케줄의 확정. 생성/수정 제한. |
| 근태 마감 | 기간 근태의 최종 확정. 정산 기준 확정. |
| GPS 미확인 | 위치 확인 불가 상태로 등록된 출퇴근. 근태 마감 차단 사유. |
| 근태 보정 | 출퇴근 누락·중복·오류 등을 요청-승인으로 확정하는 절차. |
