# prafta-app-015 — 2구간 스케줄 출근 시 1구간/2구간 명시 선택

작업 영역: 모바일 앱(`PRAFTA/prafta-app-frontend` + 필요 시 백엔드 `PRAFTA/prafta-backend` app 영역)

## 배경 / 문제

현재 2구간(야간 2교대 등) 스케줄이 배정된 날 셀프 출근을 찍으면, 서버가 **현재 시각이 1구간 시작/2구간 시작 중 어디에 더 가까운지**(`isSecondSlotTimeWindow`, 원형 최단거리)로 어떤 구간 출근인지를 **자동 추정**한다.

- 관련 코드: `PRAFTA/prafta-backend/.../app/attd/attd01/service/impl/AppAttd01ServiceImpl.java` §5.5 분기(약 930~975행), `isSecondSlotTimeWindow`(약 1388행).
- 결과적으로, 1구간 시작이 00:00 같은 스케줄에서는 낮 시간 첫 출근이 "2구간 시도"로 오판되어
  `ATTD_400_084`("1구간 출근 데이터 없이 2구간 출근하는 게 맞나요?") 소프트 차단 메시지가 떠 사용자가 혼란을 겪는다.
- 실제 재현: `USER_CD='20260400013'`, 2026-06-03, 스케줄 `SCH_CD='00005'`(2구간: 1구간 00:00~07:00 / 2구간 13:00~18:00). 낮에 첫 출근 시 위 메시지 발생.

## 요청 (사용자 의도)

2구간이 존재하는 스케줄인 경우, 출근 시점에 **사용자가 1구간 / 2구간을 직접 선택**할 수 있게 한다. 시각 기반 자동 추정에 의존하지 않는다.

세부 요구:

1. **구간 선택 기능**: 1구간·2구간이 모두 존재하는 스케줄에서 출근할 때, 어느 구간으로 출근하는지 사용자가 선택한다.
2. **순서 자유화**: 2구간 근무를 먼저 등록하고 그 후에 1구간 근무를 등록하는 것도 가능해야 한다(현재처럼 1구간 선행을 강제하지 않음).
3. **1구간 누락 허용**: 정말 1구간을 누락하고 2구간만 찍는 경우도 열어 둔다(2구간 단독 등록 허용 — 기존 Case C 의도와 동일하되, 자동 추정이 아니라 사용자 선택으로).
4. **중복 등록 차단(버튼 비활성화)**: 특정 구간을 이미 출근 등록했으면 그 구간 버튼을 비활성화한다. 예) 1구간을 먼저 선택해 찍었으면 다시 1구간을 등록할 수 없게 비활성화. (각 구간 최대 1회.)

## 제약 / 참고

- 백엔드 1벌(`PRAFTA/prafta-backend`)을 앱(app FE)이 사용. app 엔드포인트 프리픽스 `/appApi`. JWT 세션 클레임/IDOR 가드 유지.
- WORK_SEQ 채번: 구간 선택에 따라 1구간=WORK_SEQ 1, 2구간=WORK_SEQ 2로 매핑(순서 무관하게 선택된 구간이 곧 WORK_SEQ가 되도록). 기존 `existing+1` 채번 및 §5.5 자동 추정 로직과의 정합성/회귀를 planner가 검토.
- 하루 최대 2회 출근 캡(prafta-app-014)·야간 자정보정·표준화/지각조퇴 판정 등 기존 정책과 충돌하지 않게 한다.
- 1구간 스케줄(단일 구간)·스케줄 없는 날은 기존 동작 유지(구간 선택 UI 미노출).
- 프론트 영향 파일(추정): `src/views/attd/MyAttendanceView.vue`, `src/views/main/MainView.vue`, 액션시트 컴포넌트. 백엔드: `AppAttd01ServiceImpl`, `CheckInParam`/`CheckInRequest`, `AttdErrorCode`, attd01 상태/응답 DTO(구간별 출근가능/버튼 활성 플래그).
- 정책서: 근태관리 §5.1~§5.5 (특히 §5.5 야간 2구간). planner가 INDEX 경유로 관련 섹션 정독 후 출처 명시.
