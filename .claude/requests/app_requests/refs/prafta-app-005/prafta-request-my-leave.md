# 작업 요청서: 사용자 본인 연차 현황 화면 (모바일 앱)

## 1. 개요

### 1.1 배경

근태관리 정책서 v1.1에서 연차 영역이 전면 재정비되면서 법정 휴가와 법정 휴가 외를 분리 집계하는 체계가 확립되었다(§8.2, §8.9). 관리자 웹에는 "연차 현황" 화면과 "직원별 연차 상세" 화면이 존재하지만(§8.9), 모바일 앱에는 본인의 연차 현황을 확인하는 화면이 없다.

기존 모바일 앱에서는 메인 홈 카드 KPI("잔여 연차 12 / 20일")와 연차 신청 폼 §3.4.1 잔여 일수 표시만 있어, 사용자가 본인의 연차 부여·사용·잔여를 종합적으로 확인할 수 있는 단일 화면이 부재한다. 본 화면은 그 진입점이 된다.

### 1.2 화면 위치

- IA 경로: 메인 > 근태 조회 > 잔여 연차 상세
- 진입 경로:
  - 메인 홈 "근태 조회" 카드의 "잔여 연차" KPI 탭
  - 본인 근태 조회 화면에서의 연차 관련 진입 (선택 — planner 확정)
  - 연차 신청 폼의 "잔여 일수" 카드 탭 (선택 — planner 확정)
- 화면명(헤더 타이틀): **연차 현황** (관리자 화면의 §8.9 "연차 현황" 명칭과 정합)

### 1.3 화면 구성 (단일 화면 + 1개 콜아웃 + 1개 액션)

- 단일 스크롤 화면 (탭 없음, 세그먼트 토글 1개로 그룹 전환)
- 표시 영역
  - 그룹 토글 (전체 / 법정 / 법정 외)
  - 소멸 임박 콜아웃 (조건부, 닫기 가능)
  - 메인 잔여 카드 (큰 숫자 + 진행 바 + 범례)
  - 3분할 KPI (부여 / 사용 / 사용예정)
  - 메타 카드 (입사일 / 근속 / 사용률)
- 푸터 액션: 연차 신청하기 (Primary 1개)

### 1.4 시안 파일

- `prafta_my_leave_v1.html` — 4개 케이스
  - 케이스 1: 기본 (정상 잔여)
  - 케이스 2: 소멸 임박 경고 노출
  - 케이스 3: 잔여 0일
  - 케이스 4: 법정 외 토글 활성

## 2. 핵심 정보 모델

### 2.1 화면이 표현하는 3가지 정보 단위

| 정보 단위 | 화면 영역 | 데이터 출처 |
|---|---|---|
| 그룹 집계 (전체 / 법정 / 법정 외) | 메인 카드 + 3분할 KPI | 본인 연차 부여·사용·예정 합산 |
| 소멸 임박 알림 | 조건부 콜아웃 (최상단) | 만료일 D-30 이내 + 잔여 > 0 |
| 본인 메타 (입사·근속·사용률) | 메타 카드 (하단) | 사용자 기준 정보 |

### 2.2 그룹 정의 (정책서 §8.9.2)

| 그룹 | 정의 | GRANT_TYPE |
|---|---|---|
| 법정 | 시스템이 자동 부여한 연차 | `STATUTORY_*` (연차 부여 정책 §8.6에 따른 자동 부여) |
| 법정 외 | 관리자 수동 부여 + 포상·약정 휴가 | `MANUAL_*` / `BONUS_*` |
| 전체 | 법정 + 법정 외 합산 | (위 합산) |

본 화면은 **그룹 합산만 표시**한다. 타입별(예: 포상휴가, 경조사 휴가 등) 분리 표시는 본 화면 범위 외이며, 추후 별도 화면이 필요할 경우 확장한다(시안 작성 시 사용자 확정).

### 2.3 핵심 수치 4종 정의

| 수치 | 정의 | 출처 정책 |
|---|---|---|
| 부여(GRANTED) | 그룹별 누적 부여 일수. 정책 변경 전 부여분 포함 (§8.8.1) | §8.6 / §8.9.2 |
| 사용(USED) | 이미 처리 완료된 사용 일수 (승인된 연차 중 휴가일이 도래해 차감 확정된 분) | — |
| 사용예정(PLANNED) | **승인 + 대기 상태의 미래 연차 신청 합산** (시안 작성 시 사용자 확정) | — |
| 잔여(REMAINING) | 부여 − 사용 − 사용예정 | — |

**사용예정의 정의 (확정 사항)**:
- 승인 완료된 미래 신청 + 승인 대기 중인 신청 모두 포함
- 반려·취소된 신청은 제외
- 사용자가 "내가 신청해둔 것 모두를 잔여에서 차감해서 보고 싶다"는 의도에 따른 정의
- 단, 신청이 대기 중일 때도 잔여에서 차감되어 보이므로, 신청이 반려되면 잔여가 다시 늘어남 (UX 측면에서 정책서에 명시 필요 — planner 확인)

### 2.4 상태값 정의

| 상태 | 조건 | UI |
|---|---|---|
| 정상 잔여 | 잔여 > 0 | 메인 카드 숫자 Primary Green, 푸터 [연차 신청하기] 활성 |
| 잔여 0 | 잔여 == 0 | 메인 카드 숫자 Primary Text(검정), 푸터 [연차 신청하기] 비활성 |
| 소멸 임박 | D-30 이내 만료 + 잔여 > 0 | 최상단 Warning 콜아웃 노출 (닫기 가능) |
| 소멸 임박 + 잔여 0 | — | 발생 불가 (잔여 0이면 소멸 대상도 0) |

### 2.5 진행 바 시각화 규칙

진행 바는 부여 일수를 100%로 두고 다음 3 영역으로 분할한다:

| 영역 | 비율 | 색 |
|---|---|---|
| 사용 | USED / GRANTED | `--color-primary` (#16A34A) |
| 사용예정 | PLANNED / GRANTED | `--color-primary-tint-border` (#DCFCE7) |
| 잔여 | REMAINING / GRANTED | `--color-border-light` (#F3F4F6) — 배경 그대로 |

부여가 0일 때(법정 외 미부여 등)는 진행 바를 회색 단일색으로 표시하고 "부여된 연차가 없습니다" 표시 (planner 확정).

## 3. 비즈니스 규칙 (정책서 출처 명시)

### 3.1 데이터 조회 범위

- 본인 데이터만 조회 (사용자 ID = 인증 토큰의 사용자)
- 조회 기준 시점: 현재 시각
- 조회 대상 부여: 활성 상태(GRANT.STATUS = ACTIVE 또는 IN_USE)
- 만료(EXPIRED), 취소(CANCELED) 상태 부여는 제외 (관리자 화면의 "사용 이력" 테이블에는 포함되지만 모바일에서는 표시 안 함)

### 3.2 그룹 토글 동작

- 토글 3개 (전체 / 법정 / 법정 외) 중 1개만 활성
- 진입 시 기본값: **전체**
- 토글 전환 시 메인 카드의 라벨이 그룹명 반영:
  - 전체: "잔여 일수"
  - 법정: "법정 잔여 일수"
  - 법정 외: "법정 외 잔여 일수"
- 토글 전환 시 모든 수치(메인 카드 / 진행 바 / 3분할 / 사용률)가 해당 그룹 집계로 갱신
- 메타 카드(입사일/근속)는 그룹과 무관하게 항상 동일

### 3.3 소멸 임박 콜아웃 노출 조건

콜아웃 노출 조건: 다음 모두 만족
- 활성 부여 중 만료일이 30일 이내인 부여가 1건 이상 존재
- 해당 부여의 잔여(GRANTED − USED − PLANNED) > 0

콜아웃 표시 내용:
- 타이틀: "N일 후 소멸되는 연차 X일"
- N = 가장 임박한 부여의 D-day
- X = 30일 이내 만료 부여들의 잔여 합산

**닫기 동작 (확정 사항)**: 세션 한정 닫기
- 닫기 버튼(X) 탭 시 즉시 콜아웃 제거 (애니메이션은 fade-out 200ms)
- **세션 한정**: 화면을 나갔다 다시 들어오면 다시 표시됨
- 영구 dismiss / N일 dismiss 기능은 없음
- 클라이언트 메모리 또는 SessionStorage에 상태 보관 (서버 호출 불필요)

### 3.4 그룹 토글 × 콜아웃 관계

- 콜아웃은 "전체" 토글에서만 노출 검토 (법정/법정외 그룹 토글에서는 비표시)
- 사유: 사용자는 그룹 단위로 소멸 관리하지 않고, 임박 알림은 전체 단위에서 한 번만 봐도 충분
- planner 검토 후 정책 확정 필요 (만약 그룹별 노출도 필요하다면 그룹별 합산 잔여를 계산)

### 3.5 푸터 액션 [연차 신청하기]

- 진입: 연차 신청 폼 화면 (`prafta_request_forms_v8.html` 내 연차 신청 폼)
- 활성 조건: 잔여(REMAINING) > 0
- 비활성 조건: 잔여 == 0 → 버튼 disabled (도움말 텍스트 없음 — 비활성 UI만으로 충분)
- 비활성 상태에서는 탭 시 아무 반응 없음 (확인 모달이나 토스트 미노출)

### 3.6 진입 동선과 캐시

- 메인 홈 잔여 연차 KPI 카드와 본 화면의 수치는 동일 데이터 소스를 사용해야 한다 (불일치 방지)
- 본 화면 진입 시 항상 최신 데이터 조회 (캐시 사용 안 함, GET 1회)
- 화면 노출 중 백그라운드 갱신은 별도 처리하지 않음
- Pull-to-refresh 지원 여부는 planner 확정 (다른 화면들과의 일관성)

### 3.7 메인 홈 "잔여 연차 N/M일"과의 일치

메인 홈의 KPI는 다음 매핑을 따른다:
- N (큰 수치) = **전체 그룹의 잔여 일수**
- M (작은 수치, "/ 20일") = **전체 그룹의 부여 일수**

본 화면의 케이스 1 메인 카드와 정확히 일치해야 한다.

### 3.8 0.5일 단위 처리

- 정책서 §8.7에 따라 휴가 사용 단위는 1일 / 0.5일 / 0.25일 / 0.125일 다중 선택 가능
- 부여·사용·예정·잔여 모두 소수점 표기 가능 (예: 12.5일)
- 표기 규칙:
  - 정수 → 정수 표기 ("12일")
  - 소수 있음 → 소수 1자리 표기 ("12.5일")
  - 0.125일 단위는 시간 환산이 더 직관적이므로 향후 확장 (현 화면은 일 단위만)

## 4. 화면별 상세 명세

### 4.1 공통 UI 요소

- 헤더: 좌측 ← 백 버튼 / 중앙 "연차 현황" / 우측 빈 영역 (디자인 가이드 §3.2)
- 본문 배경: `--color-bg` (#F9FAFB)
- 카드: `--color-surface` (#FFFFFF) + `--color-border` (#E5E7EB) 1px + `--radius-lg` (14px)
- 푸터: 흰 배경 + 상단 `--color-border-light` 1px

### 4.2 그룹 토글 (세그먼트)

- 구조: 3개 항목 (전체 / 법정 / 법정 외)
- 컨테이너: `--color-border-light` 배경 + `--radius-md` (10px) + padding 3px
- 활성 항목: `--color-surface` 배경 + `--shadow-sm` + `--color-text-primary` text
- 비활성 항목: transparent 배경 + `--color-text-secondary` text
- 항목 폰트: 13px / 600 weight
- 항목 높이: 36px (3px padding 포함)
- 터치 영역: 컨테이너 width / 3 ≥ 44px (320px 폭에서도 만족)

### 4.3 소멸 임박 콜아웃 (조건부)

- 노출 조건: §3.3
- 컨테이너:
  - 배경: `--color-warning-tint` (#FFFBEB)
  - 보더: 1px solid #FCD9A4 (warning-tint-border, 디자인 가이드에 미정의 — planner 토큰 추가 검토)
  - radius: 12px
  - padding: 12px 8px 12px 14px
- 좌측 아이콘: ⚠️ (alert-triangle) 20px, color `--color-warning` (#F59E0B)
- 본문: "N일 후 소멸되는 연차 X일", 14px / 700 weight, color `#B45309` (warning-text)
- 우측 닫기 버튼:
  - 32×32 (콜아웃 내부 컴팩트 영역, hit area 32px → 디자인 가이드 §7.1 최소 44px 미달이지만 콜아웃이 충분히 크므로 절충 — planner 검토)
  - X 아이콘 18px, color `#B45309`
  - 탭 시 콜아웃 전체 fade-out 200ms 후 제거

### 4.4 메인 잔여 카드

- 카드 padding: 20px 16px
- 라벨 (예: "잔여 일수"):
  - 13px / 500 weight / `--color-text-secondary`
  - margin-bottom: 4px
- 큰 숫자 행:
  - 큰 숫자: 36px / 700 weight / `font-variant-numeric: tabular-nums`
  - 색: 잔여 > 0 → `--color-primary` / 잔여 == 0 → `--color-text-primary`
  - 단위 "일": 15px / 500 weight / `--color-text-secondary`
  - "/ 20일": 13px / 400 weight / `--color-text-secondary`
  - margin-bottom: 14px
- 진행 바:
  - height: 8px / `--radius-full` / overflow hidden
  - 배경: `--color-border-light`
  - 사용 영역: `--color-primary`
  - 사용예정 영역: `--color-primary-tint-border`
  - margin-bottom: 12px
- 범례:
  - 3항목 (사용 N일 / 사용예정 N일 / 잔여 N일)
  - 12px / `--color-text-secondary`
  - 색상 점 8px + 라벨 6px gap

### 4.5 3분할 KPI

- 카드 padding: 16px
- 3열 grid (1fr 1fr 1fr)
- 셀 내부: 라벨 (12px / secondary) + 값 (18px / 700 / primary text)
- 셀 구분선: 2번째·3번째 셀 좌측에 1px `--color-border-light` (height: 셀 높이 − 12px)
- 0일 표시 시 값은 `--color-text-tertiary`로 흐리게 (시각적 노이즈 감소)

### 4.6 메타 카드 (입사일 / 근속 / 사용률)

- 카드 padding: 14px 16px
- 3개 행, 행 사이 1px `--color-border-light` 구분선
- 각 행: 좌측 라벨 (13px / secondary) + 우측 값 (13px / 600 / primary text)
- 행 내부 padding: 6px 0

| 항목 | 표시 |
|---|---|
| 입사일 | YYYY-MM-DD |
| 근속 | "1년 8개월" (정책서 §1.5 — 입사일 기준 차이를 년·월로 환산) |
| 사용률 | "40%" (USED / GRANTED × 100, 소수점 0자리) |

**경력 인정이 있는 경우**: 입사일 행 아래에 "경력 인정 N개월" 보조 라벨을 표시 (관리자 §8.9.2 정합). planner 확정.

### 4.7 푸터 [연차 신청하기]

- 높이: 48px, `--radius-md` (10px), 16px / 600 weight
- 활성: `--color-primary` 배경 + 흰 글씨 + `+` 아이콘
- 비활성: `--color-border` 배경 + `--color-text-tertiary` 글씨 + 아이콘 동일 (회색)
- 푸터 padding: 12px 16px
- 푸터 배경: `--color-surface` + 상단 1px `--color-border-light`

## 5. 백엔드 API 명세 (필수 endpoint)

### 5.1 GET /api/app/leave/my/summary

**용도**: 본 화면 전체 데이터 1회 조회

**요청 파라미터**: 없음 (인증 토큰의 사용자 ID 사용)

**응답 구조**:
```json
{
  "user": {
    "name": "김여진",
    "hireDate": "2024-09-18",
    "serviceMonths": 20,
    "serviceCreditMonths": 0
  },
  "groups": {
    "TOTAL": {
      "granted": 20,
      "used": 6,
      "planned": 2,
      "remaining": 12,
      "usageRate": 40
    },
    "STATUTORY": {
      "granted": 15,
      "used": 6,
      "planned": 2,
      "remaining": 7,
      "usageRate": 53
    },
    "NON_STATUTORY": {
      "granted": 5,
      "used": 0,
      "planned": 0,
      "remaining": 5,
      "usageRate": 0
    }
  },
  "expiringSoon": {
    "exists": true,
    "daysUntilExpiry": 3,
    "totalRemainingDays": 5,
    "expiryDate": "2026-05-28"
  }
}
```

**필드 설명**:
- `groups.{GROUP}.granted/used/planned/remaining`: 각 그룹의 4종 수치 (§2.3)
- `usageRate`: 정수 백분율 (소수점 0자리, 반올림)
- `expiringSoon.exists`: §3.3 노출 조건 충족 여부
- `expiringSoon.daysUntilExpiry`: 가장 임박한 부여의 D-day (D-3 = 3)
- `expiringSoon.totalRemainingDays`: 30일 이내 만료 부여들의 잔여 합산
- `expiringSoon.expiryDate`: 가장 임박한 부여의 만료일 (UI 표시 안 함, 디버깅·확장용)

**계산 로직** (planner가 백엔드 개발자에게 전달):
- `planned` = 본인의 연차 신청 중 상태가 `APPROVED` 또는 `PENDING`이고 휴가일이 오늘 이후인 신청의 일수 합산 (§2.3 확정 사항)
- `remaining` = `granted` - `used` - `planned`
- `usageRate` = `round(used / granted * 100)`. `granted == 0`이면 0
- `expiringSoon`은 STATUTORY + NON_STATUTORY 모두 합산하여 계산 (그룹 토글과 무관, §3.4)

## 6. DB 구조 검토 및 추가 작업 필요 사항

### 6.1 GRANT_TYPE 분류 매핑

정책서 §8.9.2에서 GRANT_TYPE을 STATUTORY_* / MANUAL_* / BONUS_*로 분류한다. 본 API의 그룹 매핑은 다음을 따른다:

| API 그룹 | GRANT_TYPE prefix |
|---|---|
| STATUTORY | `STATUTORY_*` |
| NON_STATUTORY | `MANUAL_*`, `BONUS_*` |

**확인 필요**: 현재 DB에 GRANT_TYPE 컬럼이 존재하는지, prefix 컨벤션이 일치하는지 백엔드 개발자가 확인.

### 6.2 PLANNED 계산을 위한 신청 상태 매핑

§2.3 사용예정 정의에 따라 `tb_user_attd_req`(또는 연차 신청 테이블)에서 다음 조건의 레코드를 합산:
- `REQ_TYPE = LEAVE` (연차 신청)
- `STATUS IN ('APPROVED', 'PENDING')` (시안 작성 시 사용자 확정 — 승인 + 대기 모두 포함)
- 휴가 시작일 >= 오늘 (미래분만)

**확인 필요**: 본인 근태 조회 화면 작업(`prafta-request-my-attendance.md`)에서 정의된 신청 상태값과 정합성 확인. CANCELED, REJECTED는 제외.

### 6.3 만료일(EXPIRY_DATE) 컬럼 존재 여부

§3.3 소멸 임박 계산을 위해 GRANT 테이블에 만료일이 명확히 기록되어 있어야 한다. 정책서 §8.6.2 6번 axis(연차 유효기간 12개월/24개월)에 따라 부여일 + 유효기간으로 계산되며, 이 값이 컬럼으로 저장되어 있는지 확인 필요.

## 7. 정책서 출처 확인 필요 사항 (planner 작업)

다음 항목들은 시안 작성 시 사용자와 협의해 확정된 내용이지만, 정책서에 명시되어 있지 않거나 추가 명시가 필요할 수 있다:

1. **사용예정의 정의** (§2.3): "승인 + 대기 모두 포함" — 정책서 §9에 명시 또는 보강 필요
2. **소멸 임박 콜아웃의 dismissal 정책** (§3.3): 세션 한정 닫기 — UX 정책이며 정책서 명시 불필요할 수 있음. planner 판단
3. **그룹 토글 × 콜아웃 관계** (§3.4): "전체 토글에서만 노출" — 본 작업의 UX 결정. 정책서에 반영하지 않음
4. **그룹 합산만 표시** (§2.2): 타입별 분리 표시 미지원 — 본 작업의 범위 설정. 추후 확장 가능성 정책서 §8.9.5에 직원별 연차 상세는 부여 이력 시계열 표시가 있어 모바일에서도 별도 화면으로 분리 가능
5. **푸터 [연차 신청하기] 동선** (§3.5): 본 화면 → 연차 신청 폼 직접 진입. 메인 홈·근태 조회에서의 진입과 별개로 추가된 진입점. 정책서 §9에 진입 동선 명시 검토

## 8. 비기능 요구사항

### 8.1 디자인 시스템 준수

- 색상/폰트/간격은 모두 CSS 변수만 사용 (하드코딩 금지)
- 공통 컴포넌트 우선 사용 (`src/components/common/`)
- 모바일 first (360~414px 기준 폭)
- 터치 영역 최소 44×44px (디자인 가이드 §7.1)
  - 단, 콜아웃 내부 닫기 버튼은 32×32 (절충, planner 검토)
- 아이콘은 Tabler Icons 또는 inline SVG (시안에서는 inline SVG 사용 — webfont 로딩 의존성 회피)

### 8.2 성능

- 단일 API 호출 (`GET /api/app/leave/my/summary`)
- 진입 시 1회 조회, 캐시 없음 (메인 홈 KPI와의 일치성 확보)
- 그룹 토글 전환 시 추가 API 호출 없음 (서버 응답에 3개 그룹 모두 포함)

### 8.3 접근성

- 색상으로만 정보 전달 금지: 진행 바는 색 + 범례 텍스트 보조
- 숫자는 `tabular-nums` 적용 (정렬 일관성)
- 닫기 버튼은 `aria-label="닫기"` 명시
- 그룹 토글은 `role="tablist"` 또는 시각적 토글 패턴 (planner 결정)

### 8.4 에러 처리

- 네트워크 오류 / 401 / 403 / 500 등 표준 패턴 (prafta 기존 화면 패턴 따름)
- 부여 데이터가 전혀 없는 신규 입사자 케이스: 모든 수치 0, 진행 바 회색 단일, "연차 신청하기" 비활성 (planner 케이스 추가 검토 — 시안은 4개 케이스만 작성됨)

## 10. 결정 사항 요약 (시안 작성 시점)

본 시안은 사용자와의 협의를 거쳐 v1로 확정됨. 주요 결정 사항:

1. **관리자 화면(§8.9) 대비 모바일 단순화**: 본인 1명의 데이터만 표시, 3그룹 동시 표시가 아닌 토글 전환 방식
2. **그룹 표시 방식**: 전체를 메인으로, 법정/법정외는 토글로 전환 (A안 채택)
3. **사용예정 정의**: 승인 + 대기 모두 포함
4. **사용 이력 리스트 미포함**: 요약만 표시 (A안 채택). 향후 별도 화면으로 확장 가능
5. **그룹 합산만 표시**: 타입별 분리(포상/경조사 등) 표시 안 함
6. **소멸 임박 콜아웃**: 본인 해당분이 있을 때만 조건부 노출
7. **콜아웃 안내문구 단순화**: "N일 후 소멸되는 연차 X일" 한 줄. 만료 날짜와 추가 설명 텍스트 제거
8. **콜아웃 닫기 버튼**: X 아이콘으로 닫기 가능. **세션 한정 닫기**(화면 재진입 시 다시 표시)
9. **잔여 0일 시 푸터**: 버튼 비활성화만으로 충분. 별도 도움말 텍스트 제거
10. **화면 헤더 타이틀**: "잔여 연차" → "연차 현황" (관리자 화면 §8.9 명칭과 정합)
11. **아이콘 구현**: inline SVG 사용 (Tabler webfont CDN 의존성 회피)
