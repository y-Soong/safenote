# 작업 요청서: 사용자 본인 근태 조회 화면 (모바일 앱)

> **버전**: 1.0
> **작성일**: 2026-05-23
> **대상 에이전트**: planner
> **참조 산출물**: `prafta_my_attendance_v8.html` (오늘/이번주/이번달 화면 시안, 총 10개 화면 케이스)

---

## 1. 개요

### 1.1 배경
PRAFTA 모바일 앱에서 사용자가 본인의 근태 정보를 **일/주/월 단위**로 조회할 수 있는 화면을 신규로 구축한다.

기존 시장의 시프티(Shiftee) 같은 서비스가 제공하는 사용자용 본인 스케줄 조회 화면을 벤치마킹하되, PRAFTA의 핵심 차별점인 **스케줄 + 실 근태 + 표준화 적용 시간을 동시에 노출**하는 3중 정보 구조로 설계한다. 사용자가 "이때가 내 스케줄이었는데 실제 출퇴근은 이렇게 처리됐고, 정산은 이 시간으로 잡힌다"를 한눈에 파악할 수 있어야 한다.

### 1.2 화면 위치
- **앱 네비게이션**: 하단 탭바 "근태" 탭에서 진입하는 화면 (현재 활성 탭)
- **파일 위치**: `prafta-web-frontend/src/views/attd/MyAttendanceView.vue`

### 1.3 화면 구성 (3개 세그먼트 탭)
1. **오늘 탭**: 오늘의 근태 카드 1장 + 푸터 액션
2. **이번주 탭**: 7일 카드 리스트 + 주 합계 + 카드 탭 시 바텀시트
3. **이번달 탭**: 월간 캘린더 + 선택일 상세 카드

### 1.4 시안 파일
구체적 UI는 `prafta_my_attendance_v8.html` 참조. 총 10개 화면 케이스를 담고 있다:
- 오늘 5개: 1구간 근무중 / 1구간 퇴근완료 / 출퇴근 사업장 다름 / 2구간 / 퇴근 미등록
- 이번주 1개 + 바텀시트 2개(과거 일자 / 미래 일자)
- 이번달 2개: 오늘 선택 / 처리 필요(7일) 선택

## 2. 핵심 정보 모델

### 2.1 화면이 표현하는 3가지 정보 단위

모든 시간 정보는 다음 3행 구조로 표현한다:

| 행 | 의미 | 데이터 출처 |
|---|---|---|
| **스케줄** | 사전 등록된 근무 계획 시간 | `tb_user_work_plan` + 근무코드의 시간 정의 |
| **근태** | 실제 출퇴근 등록 시각 | `tb_user_attd_mgmt` (WORK_SEQ로 1구간/2구간 구분) |
| **표준화** | 표준화 규칙 적용 후 정산 시간 | `tb_attd_std_time_rule` 적용 결과 |

용어 통일:
- 근무 전 일자 → "스케줄"
- 근무 중/완료 일자 → "근태"
- 정산값 → "표준화"

### 2.2 상태값 정의

오늘 탭에서 사용하는 상태값은 3종으로 통일:
- `근무중` — 출근만 등록, 퇴근 전
- `출근 전` — 스케줄은 있으나 출근 등록 전
- `2구간 근무` — 교대근무 타입(2구간 스케줄)일 때 (1·2구간 진행 상태와 무관하게 표시)

### 2.3 캘린더 셀 색상 코딩 (이번달 탭)
- **근무**: 옅은 그린 (스케줄이 잡힌 평일)
- **연차**: 옅은 앰버 (본인 연차 사용일)
- **휴무**: 옅은 회색 (주말 / 공휴일 / 평일 휴무 통합)
- **처리 필요**: 옅은 붉은색 + 우상단 경고 점 (퇴근 미등록·출근 미등록 등 보정이 필요한 과거 일자)

오늘 표시는 outline(테두리), 선택은 진한 배경 + 흰 글씨로 분리한다.

## 3. 비즈니스 규칙 (정책서 출처 명시)

### 3.1 수정 요청 가능 조건 (정책서 §7.4, §9 근거 — planner가 정확한 섹션 매핑 필요)

| 상태 | 수정 요청 | 퇴근하기 | 비고 |
|---|:---:|:---:|---|
| 근무중 | ✗ 비활성 | ✓ 활성 | 안내: "근무 중에는 근태 수정을 요청할 수 없어요." |
| 퇴근 완료 (출퇴근 모두 등록) | ✓ 활성 | ✗ 비활성 | 안내: "출퇴근 기록과 근태가 다르면 수정 요청해 주세요." |
| 출퇴근 사업장 다름 | ✓ 활성 | ✗ 비활성 | 안내문구 없음. 근태 행에 퇴근지 warning 톤 표시만 |
| 2구간 진행 중 (1구간 완료, 2구간 미완료) | ✗ 비활성 | ✓ 활성 (2구간 출근 등) | 안내: "2구간 근무까지 모두 끝난 뒤에 수정 요청을 등록할 수 있어요." |
| 2구간 완료 | ✓ 활성 | ✗ 비활성 | |
| 퇴근 미등록 (당일 내, 스케줄 종료 후) | ✗ 비활성 | ✓ 활성 | 안내: "퇴근은 오늘 안에만 가능해요." |

**[질문 사항 #1 — planner가 비즈니스 정책서에서 확정 필요]**
- 퇴근하기 가능 기한이 "당일 자정까지"라는 가정으로 시안을 작성했으나, 정책서에 명시된 기한이 다를 수 있음 (예: D+1, 다음 출근 등록 직전까지). 정책서 §7.4 또는 관련 섹션에서 확정 후 반영.
- 정책서에 없으면 사용자에게 명확화 질문 필요.

### 3.2 초과근무 신청 흐름 (퇴근 미등록 케이스)
- 퇴근 미등록 상태에서는 [수정 요청]과 [퇴근하기]만 노출. [초과근무 신청] 버튼은 노출하지 않음
- 사용자가 퇴근 후 또는 보정 요청 처리 후 근태가 확정된 상태에서, **이번주 화면의 바텀시트**를 통해 초과근무를 신청
- 정책서 §9.3에 따라 사후 신청 기한은 **근무일 + 5일**

### 3.3 이번주 카드 탭 → 바텀시트 액션 매트릭스

바텀시트는 4개 액션을 **항상 노출**하되, 일자 상태에 따라 활성/비활성을 제어한다 (안내 문구 없음).

| 일자 상태 | 1. 스케줄 수정 | 2. 근태 보정 | 3. 초과근무 신청 | 4. 연차 신청 |
|---|:---:|:---:|:---:|:---:|
| 과거 (근태 마감 전, 완료) | ✗ | ✓ | ✓ | ✗ |
| 과거 (출퇴근 누락·오류) | ✗ | ✓ | ✗ (보정 후 활성) | ✗ |
| 과거 (근태 마감 후) | ✗ | ✗ | ✗ | ✗ |
| 오늘 (근무중) | ✗ | ✗ | ✗ | ✗ |
| 오늘 (완료) | ✗ | ✓ | ✓ | ✗ |
| 미래 (스케줄 마감 전) | ✓ | ✗ | ✗ | ✓ |
| 미래 (스케줄 마감 후) | ✗ | ✗ | ✗ | ✓ |
| 미래 휴무일 | ✓ | ✗ | ✗ | ✗ |

**[질문 사항 #2 — planner가 비즈니스 정책서에서 확정 필요]**
- 휴무일에 연차 신청 가능 여부 — 정책상 휴무일에 연차를 신청하는 게 의미가 없을 수 있음. 정책서 확인 필요
- "스케줄 마감 전/후"의 기준 시각 — 정책서 §9.2 또는 관련 섹션에서 확정

### 3.4 공휴일 + 연차 처리
- **공휴일에 연차 사용 가능** (교대근무자 케이스 고려)
- 이번주 화면에서 공휴일 + 연차 겹침 시: 두 배지를 함께 노출 (`연차` + `부처님오신날`)
- 캘린더에서: 연차 톤(앰버) 우선 적용
- 안내 워딩: "휴가일이라 오늘은 푹 쉬어요. 출근 등록은 어려워요."

### 3.5 GPS / 사업장 위치 표시
- GPS 정상 → **사업장 위치만** 표시 (예: "출근 중곡사업장")
- GPS 비정상 → "GPS 확인필요" 폴백 워딩
- 출퇴근 사업장이 다른 경우 → 퇴근지에 warning 톤 + "퇴근 성수사업장" 형태로 표시. 별도 안내 문구는 없음

### 3.6 표준화 적용 표시
- 출퇴근 모두 등록 완료 → 표준화 시간만 표시 (적용 기준 텍스트 생략)
- 퇴근 전 / 산정 불가 → `-` (하이픈)만 표시. "퇴근 후 산정" 같은 부가 텍스트 금지
- 정책서 §5 (시안 작업 시 캡처한 "출퇴근 시간 표준화" 화면 참조) 기반

### 3.7 합계 시간 계산
- **이번주 합계**는 총 합계만 표시 (각 일자별 시간 합계 표시 없음)
  - 예정 근로시간 + 실 근로시간 두 가지
- **실 근로시간은 완료된 근무만 합산** (진행 중·미래·미등록 제외)
- 시각적 표시: "이번주 합계 — 완료된 근무만"
- **이번달 합계**: 캘린더 헤더 아래에 한 줄로 "예정 163h 30m · 실 72h 45m (완료분)"

## 4. 화면별 상세 명세

### 4.1 공통 UI 요소
- **헤더**: 좌측 뒤로가기 / 중앙 "내 근태" / 우측 알림 아이콘 (뱃지)
- **세그먼트 컨트롤**: 오늘 / 이번주 / 이번달 (3등분, 활성 시 흰 배경 + 그림자)
- **하단 탭바**: 홈 / 근태(활성) / 안전 / TBM

### 4.2 오늘 탭

#### 4.2.1 카드 구조
1. 날짜 헤더: "2026년 5월 20일" (큰 글씨) + "수요일 · 중곡사업장" (작은 글씨, 우측 정렬 없음 동일 라인)
2. 상태 행: 상태 배지 + 근무 타입명 (예: `근무중` ST001 정규근무)
3. 정보 3행:
   - 스케줄: `09:30 ~ 18:00` / 휴게 90분 · 7시간
   - 근태: `09:28 ~ -` / 출근 중곡사업장
   - 표준화: `-`
4. 인라인 알림 (있는 경우): 회색/info/warning/danger 톤
5. 푸터: [수정 요청] + [퇴근하기] 또는 케이스별 변형

#### 4.2.2 케이스별 변형
- **2구간**: 카드 안에 1구간 / 2구간 구분선으로 분리하여 각각 3행 표시. 푸터의 Primary 버튼은 진행 단계에 맞춰 변경 ("2구간 출근")
- **출퇴근 사업장 다름**: 근태 행에 `tw.a.wr` 클래스 적용(warning 톤). 안내 문구 없음
- **퇴근 미등록**: 근태 행에 `tw.a.m` 클래스(danger 톤), 퇴근 시각을 "미등록"으로 빨간색 표시. 안내문구 "퇴근은 오늘 안에만 가능해요."

#### 4.2.3 푸터 액션
- [수정 요청] + [퇴근하기] 2개 버튼 (좌 Tertiary, 우 Primary)
- 버튼 텍스트는 고정, 활성/비활성만 제어
- 한 화면당 Primary 1개 원칙 (Tertiary는 비활성 시 회색)

### 4.3 이번주 탭

#### 4.3.1 구조
1. 주 네비게이션 카드: `<` 2026.05.18 ~ 05.24 `>`
2. 요일 카드 7장 (월~일):
   - 좌측: 요일(11px) + 날짜(15px) — 토요일은 info 색, 일요일은 danger 색
   - 중앙: 근무 타입 배지 + 근무명 (한 줄) / 시간 요약 (한 줄)
   - 우측: chevron-right (탭 가능 인디케이터)
3. 주 합계 카드 (하단):
   - 좌: 예정 근로시간 / 우: 실 근로시간 (Primary 색)
   - 헬퍼 텍스트: "이번주 합계 — 완료된 근무만"

#### 4.3.2 시간 요약 표기
- 일반: `스케줄 09:30~18:00 · 근태 09:25~18:08` (근태 시간은 Primary 색)
- 지각·이상: `스케줄 09:30~18:00 · 근태 09:42~18:02 (지각)` (근태 시간은 warning 색)
- 2구간: `스케줄 07:00~13:00 / 17:00~21:00` (구간 사이 `/`로 구분)
- 미래 (근태 미생성): `스케줄 07:00~15:00` (근태 부분 미표시, '예정' 단어 사용 금지)
- 휴무일: 시간 요약 없이 "휴무" 텍스트만 (다른 요일 디자인과 통일, 칩/배지 형태 금지)
- 휴무 + 공휴일: "부처님오신날 (공휴일)" 또는 "휴무 · 부처님오신날" 형태
- 연차 + 공휴일: `연차` 배지 + `부처님오신날` 배지 (둘 다 표시)

#### 4.3.3 카드 탭 동작
- 카드 어디든 탭 시 바텀시트 노출
- 바텀시트 내용:
  - 핸들 (drag indicator)
  - 헤더: "5월 19일 (화)" + 닫기 X
  - 메타: 근무 타입 + 시간 요약 (1줄)
  - 액션 4개 (스케줄 수정 / 근태 보정 / 초과근무 신청 / 연차 신청)
  - 각 액션은 좌측 아이콘 + 액션명 1줄 + chevron-right (활성 시) / 비활성 시 회색 + chevron 숨김
  - **안내 문구 없음** (액션명만)

### 4.4 이번달 탭

#### 4.4.1 구조
1. 캘린더 카드:
   - 월 네비게이션: `<` 2026년 5월 `>`
   - 월 합계: "예정 163h 30m · 실 72h 45m (완료분)"
   - 범례: 근무 / 연차 / 휴무 / 처리 필요 (4종 색상 칩)
   - 7열 그리드 캘린더 (요일 헤더 + 6주 셀)
2. 선택일 상세 카드 (캘린더 하단):
   - 오늘 탭과 동일한 카드 구조 (날짜 / 상태 / 3행 정보)
   - 2구간일 경우 1구간 + 2구간 모두 표시

#### 4.4.2 셀 디자인 규칙
- `.cal-d`: 기본 셀 (1:1 비율, 8px 둥근 모서리)
- `.cal-d.wk`: 근무일 (옅은 그린 배경, 진한 그린 마커 점)
- `.cal-d.lv`: 연차일 (옅은 앰버 배경)
- `.cal-d.of`: 휴무일 (옅은 회색 배경)
- `.cal-d.ac`: 처리 필요 (옅은 붉은색 배경 + 우상단 작은 경고 점)
- `.cal-d.out`: 이전/다음 달 (투명, 흐린 텍스트)
- `.cal-d.td`: 오늘 (outline 강조)
- `.cal-d.sel`: 선택 (진한 그린/앰버/회색/붉은색 배경 + 흰 글씨)

#### 4.4.3 처리 필요 셀 선택 시
- 상세 카드에 처리 필요 케이스 표시 (시안의 화면 10 참조)
- 푸터에 빠른 액션 표시: [근태 보정] + [초과근무 신청] (transparent 배경, 카드 아래 inline)

## 6. 비기능 요구사항

### 6.1 디자인 시스템 준수
- 색상/폰트/간격은 모두 CSS 변수만 사용 (하드코딩 금지)
- 공통 컴포넌트 우선 사용 (`src/components/common/`)
- 모바일 first (360~414px 기준 폭)
- 터치 영역 최소 44×44px (디자인 가이드 §3 준수)

### 6.2 성능
- 오늘 탭: 단일 API 호출
- 이번주/이번달 탭: 단일 API 호출 (7일 또는 31일분 일괄)
- 탭 전환 시 캐시 활용 (이미 조회한 주/월은 재호출 최소화)

### 6.3 접근성
- 색상으로만 정보 전달 금지 (예: 처리 필요는 색 + 경고 점 + 텍스트 보조)
- 시간 표시는 `tabular-nums` 적용으로 정렬 일관성

### 6.4 에러 처리
- 네트워크 오류 / 401 / 403 / 500 등 표준 패턴 (prafta 기존 화면 패턴 따름)

## 8. 참고: 작업 진행 중 발생한 결정 사항 (요약)

본 시안은 사용자와의 8회 이터레이션을 거쳐 v8로 확정됨. 주요 결정 사항:

1. **시프티 화면 벤치마킹** → PRAFTA만의 3행 정보 구조로 차별화 (스케줄/근태/표준화)
2. **오늘 탭의 액션 배치**: 화면 상단의 정보 영역과 분리하여 푸터에 액션 (Primary 1개 원칙)
3. **상태값**: 다양한 케이스를 통합 → 3종(근무중/출근 전/2구간 근무)으로 단순화
4. **이번주 시간 합계**: 일자별 표시 제거, 총 합계만. 진행 중 근무 제외
5. **이번주 액션**: 카드 안 버튼 → 카드 탭 시 바텀시트로 이동 (정보 밀도 감소)
6. **바텀시트 액션 4종 고정 노출**: 안내문구 없이 활성/비활성만 제어
7. **이번달 캘린더**: 1구간/2구간/야간 구분 → 근무/연차/휴무/처리 필요 4종 단순화
8. **공휴일에 연차 사용 가능**: 교대근무자 케이스 고려
9. **처리 필요 시각화**: 옅은 붉은색 + 경고 점 (사용자가 한 달 단위로 누락 인지)
