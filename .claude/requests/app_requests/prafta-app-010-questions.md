## ① 해결 / 확정 (착수 가능)

### [확정] Q1 → D1. PII 표시 = 마스킹 + 수정 진입 시에만 복호화 프리필
- 결정: 메인/조회(`/appApi/mypage/profile`)는 **마스킹**만 반환(휴대폰 LAST4 `010-****-8295`, 이메일 `t***@test.com`, 생년월일 `1993-**-**`). "개인정보 수정" 진입 시에만 별도 엔드포인트(`/appApi/mypage/profile/edit`)가 서버 복호화 전체값을 프리필.
- 보안 메모: 복호화 응답은 `Cache-Control: no-store`. 프론트는 폼 로컬 ref만, store 영속화 금지(webview 로그/캐시 평문 잔존 방지).
- 영향: 010-01(마스킹) + 010-01b(복호화) 2엔드포인트로 분리. plan §4 반영.

### [확정] Q2 → D2. 결재선 프리셋 = 앱 전용 신규 모듈 (web user04 재사용 폐기)
- 결정: web `com.prafta.web.*` API 재사용 금지. 앱 전용 신규 모듈 `com.prafta.app.mypage.mypage01`에 controller/service/mapper XML/DTO 전부 신규 작성. **테이블 `tb_aprv_line_preset`/`_d`만 공유**(신규 테이블 금지). user04 SQL/로직은 "참고"만, web 코드 호출·의존 금지.
- 결재자 후보 검색도 앱 전용 신규 엔드포인트(`/appApi/mypage/approval-candidates`). web `/user04/approval-candidates` 호출 금지.
- 전수조사: 현재 앱이 web 전용 API를 직접 호출하는 화면은 **0건**(전부 `/appApi`/`/comApi`). 본 작업의 web 분리 대상은 프리셋 모듈 신규뿐.
- 영향: 010-05 전면 교체. plan §2.5 패키지 확정안 신설.

### [확정] Q3 → D3+D4. comApi 공통 레이어 재사용 + 휴대폰 검증만 앱 전용 신규
- D3: `/comApi/*` 공통 레이어(login/baseinfo/auth)는 app·web 공용이므로 재사용 유지. **로그아웃은 기존 `/comApi/login/logout` 재사용**(010-06 BE 신규 불필요).
- D4: 휴대폰 변경 검증은 예외. 기존 `/comApi/login/verify-phone-auth`는 검증 성공 시 로그인 토큰을 발급하는 부작용이 있어 마이페이지에서 사용 불가 → `/appApi/mypage/mobile/{request-verification,verify}` 앱 전용 신규(토큰 미발급, 성공 시 단발성 verificationToken만 반환). SMS 발송 인프라(게이트웨이/`tb_sms_auth_code`)는 재사용.
- 영향: 010-03 앱 전용 2엔드포인트 확정, 010-06 BE 신규 제거.

### [확정] Q6 → D6. 성별 = SYS004 시스템코드 100:남성 / 200:여성
- 결정: `tb_user.GENDER`에 SYS004 코드(`tb_syst_val_d`) 100/200 저장. NULL(미설정) 허용. select는 앱 회원가입(JoinUser)과 동일 systCode 드롭다운 재사용.
- 영향: 010-01 응답에 genderCode/genderNm 동반, 010-02 검증 `genderCode ∈ {100,200,null}`. ProfileEditView select 옵션 SYS004 조회.

### [확정] Q13 → D5. 탈퇴 시 연차 자동취소 미구현
- 결정: 회원 탈퇴 처리에서 `tb_user_attd_req` 연차건을 건드리지 않는다. 퇴사일 기준 사용연차 정산은 **별도 페이지로 개발 예정**.
- 탈퇴 처리 범위(010-07): `ACCOUNT_STATUS='03'` + PII 마스킹(USER_NM `김○○`, MBL/EMAIL/BIRTH 암호화필드 처리) + `WITHDRAWAL_DATE` + `tb_del_user` 기록 + 토큰 폐기. 프리셋 hard delete 유지. **연차/결재 자동처리·결재자 알림 제외.**
- 영향: 010-07 트랜잭션에서 연차 자동취소(①)·결재자 알림(구 Q14) 제거.

### [확정] Q11. 탈퇴 마스킹 규칙 + tb_del_user 기록 형태
- 결정(권장안 채택): `tb_user`는 USER_NM을 `김○○`로 마스킹(첫 글자만 노출), MBL/EMAIL/BIRTH 암호화필드 무효화. `tb_del_user`에는 마스킹된 USER_NM 저장(전용 컬럼 없음 → 기존 USER_NM 사용). 원본 평문 보존처 없음.
- 비고: 탈퇴 마스킹 공통 규정의 정책서 §11 신설은 후속 권장(본 작업에서는 위 규칙으로 진행).

### [확정] Q4. 이메일 변경 (인증 불요)
- 인증 없이 즉시 변경, 미입력 허용(공통 §3.1 선택입력). EMAIL_ENC/HMAC/DOMAIN 동시 갱신은 BE 처리.

### [확정] Q5. 이름 변경 정책
- 인증 없이 즉시·무제한 변경, 이력 보존 불필요. §11.3은 "사용자 상태 변경"만 감사 대상이라 이름 변경은 감사 비대상.

### [확정] Q12. 마이페이지 알림 아이콘 미노출
- 공지/알림 도메인 미구축이므로 마이페이지 헤더에 알림 아이콘 미노출. 도메인 구축 후 일괄 도입. (헤더 골격은 알림 아이콘 없이 작성.)

## ② 백엔드 동작 분기 (확정값으로 진행, developer가 기존 인프라 정합 확인)

### Q7. 생년월일 변경 시 만 14세 미만 차단
- 진행값: 별도 연령 정책이 없으면 **"미래 일자만 차단"**(연령 하한 미적용). 회원가입에 연령 검증이 있으면 그 값과 정렬. developer가 JoinUser 검증 확인.

### Q8. 인증번호 시도 횟수 제한
- 진행값: 기존 SMS 인증 인프라의 제한값과 동일하게 정렬. 별도 없으면 **5회**. (앱 전용 verify가 인프라 카운터를 공유.)

### Q9. 비밀번호 변경 실패/잠금 정합
- 진행값: 마이페이지 "현재 비밀번호 검증"도 **기존 로그인 실패 카운트/잠금 인프라(PWD_FAIL_CNT/PWD_LOCK_YN/PWD_LOCK_EXPIRE_DTIME) 공유**. 신규 잠금 로직 신설 금지. developer가 로그인 검증 컴포넌트 재사용.

### Q10. 비밀번호 변경 후 다른 디바이스 세션
- 진행값: 1차는 **현재 세션 유지, 타 디바이스 미처리**. 전체 세션 강제 로그아웃은 후속 보안 강화로 분리.

## ③ 남은 보류 (본 작업 범위 외 / 별도 작업)

### [보류] 퇴사일 기준 사용연차 정산 (별도 페이지)
- D5 결정에 따라 회원 탈퇴와 분리. **별도 페이지로 개발 예정.** 본 작업(010-07)은 연차/결재 자동처리를 하지 않는다.

### [보류] comApi 공통 레이어의 앱·web 분리
- D3로 `/comApi/*`는 공용 common 레이어로 재사용 유지 확정. 향후 common 레이어 자체를 앱/web으로 더 쪼갤지는 본 작업 범위 외(현재 분리 불필요).

### [보류] 비활성 결재자 "확인 필요" 배지
- 프리셋 응답(steps)에 결재자 활성여부 필드가 없어 1차 미노출. 표시가 필요하면 앱 프리셋 응답 확장을 별도 작업으로.

### [보류] 탈퇴 시 결재자 알림 (구 Q14b)
- D5로 탈퇴 시 연차 자동취소 자체를 제외했으므로 결재자 알림도 본 작업 범위 외. (연차정산 별도 페이지에서 필요 시 검토.)

### [보류] 비밀번호 변경 후 전체 세션 강제 로그아웃 (Q10 강화안)
- 보안 강화 후속.

### [보류] 탈퇴 사유 수집 / 재가입 대기기간 / 비밀번호 정기 변경 강제 (요청서 §7.4/§7.7/§7.8)
- 정책 확정 후 별도 작업. 본 작업 범위 외 유지.
