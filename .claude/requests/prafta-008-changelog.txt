1. 요청 요약
================================================================================
백엔드 ApiException(예: AttdErrorCode.ATTD_404_010)이 던진 에러 메시지가 사용자에게
보이길 원하나, 프론트의 `err?.response?.data?.message || err?.message || getMessage(...)`
패턴 때문에 의도대로 안 나온다고 함. 모든 화면을 점검해 백엔드 메시지가 최우선으로
보이도록 수정 요청.

================================================================================
2. planner 조사로 확정된 사실
================================================================================
- 백엔드는 메시지를 response.data.message에 정상 직렬화한다(원인 아님).
- 인용된 프론트 패턴은 이미 백엔드 메시지를 최우선(첫 OR 항)으로 둔다 — 대다수 화면은
  이 패턴이라 정상 동작 중이었음.
- 진짜 문제: 일부 화면이 보안정책 SEC-013(prafta-007에서 적용)으로 백엔드 메시지를
  의도적으로 폐기하고 일반 메시지만 표시(예: AttdDayDetailPop.vue). + 일부는 옵셔널
  체이닝 없는 무방비 native alert.

  메시지를 쓰므로 직접 노출해도 안전 → prafta-007의 SEC-013 일반화는 되돌림.

  둘 다 점검.

6. 미반영 / 후속 권장 (자동 수정하지 않음)

  enum(Auth/Login/Common/Baim 등)에도 "사용자 노출 OK / 보안 민감 일반화" 분류 주석·
  규율을 명문화하고 신규 enum 추가 시 보안 리뷰 체크 항목으로 고정 권장.

  불일치. 동작 정확성 관점 정리 권장.
[security 관찰 — 본 작업 무관] Baim06ServiceImpl이 일부 ApiException 생성 시
  detailMessage에 userNm(PII)을 직접 삽입 → 응답 message로 노출. prafta-010 산출물이
  아닌 baim06 모듈 기존 코드. 별도 작업으로 PII 노출 점검 권장.
