# prafta-019 재검토 · 작업 분해 계획서 (마스터)

> 원본 `prafta-019.md`(시간차 연차 + 결재 흐름 초안)를 현재 스키마·정책·코드와 대조 검토한 결과,
> **단일 요청 → 서로 의존하는 5개 작업(A~E)로 분해**한다. 본 문서는 그 인덱스 + 결정 로그 + 잘라낸 항목을 담는다.
>
> ⚠️ 원본 `prafta-019.md`는 "prafta를 모르는 AI"와 만든 초안으로, 아래 결정 로그로 **대체(supersede)** 된다. 개발 착수 시 원본이 아니라 A~E 문서를 따른다.

## 1. 결정 로그 (확정)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 결재자 결정 방식 | **사용자가 신청 시 결재라인 직접 구성** (초안의 NODE 자동 상향추적 로직 폐기). 사전·사후 동일. |
| 2 | 결재 여부 판단 | **"결재 여부 Y/N" 플래그 하나**로만 판단. Y→라인 태움, N→즉시 확정. 회사정의=`tb_leave_type_mgmt.APRV_USE_YN`(기존), 법정=`tb_leave_policy`에 Y/N 컬럼 **신규 추가**. |
| 3 | `APRV_STEP_CNT` / `HR_FINAL_APRV_YN` | **컬럼 + 프론트 입력 UI 삭제**. |
| 4 | 사후 신청 기한 | **근태 마감 연계** (근태 마감 전까지만 사후 신청 가능). 초안의 `BAIM_LEAVE_BACKDATE_LIMIT`(회사별 N일) **폐기**. |
| 5 | SYS025 재정의 | **B안(깨끗한 재정렬)**: `00=1일 / 01=반차 / 02=시간차2시간 / 03=시간차1시간 / 04=시간차30분`. 연차는 미개발·테스트데이터뿐이라 careful 매핑 불요(착수 시 운영데이터 없음 1회 확인). |
| 6 | 시간차 차감 개념 | **고정분수(0.25/0.125) 폐기 → 절대시간 단위 + 그날 스케줄 기준 동적 환산**. 차감 = `신청분 ÷ 그날 1일 소정근로분`, `decimal(8,5)`. (prafta-017 사용단위 로직 **보완**) |
| 7 | 사용단위 정책의 집 | **도메인 둘로 분리**. 회사정의=타입별 `USE_UNIT_TYPE`(SYS025 단일값), 법정=`tb_leave_usage_policy`. 초안의 BAIM_VAL 이관 **폐기**. |
| 8 | 법정연차 시간차 | 법정연차도 시간차로 쪼개 사용 **포함**. `tb_leave_usage_policy`를 SYS025 00~04에 1:1로 재모델. |
| 9 | 직급 | `tb_user`에 `RANK_CD varchar(10)` **신규**. 직급 코드·데이터는 `tb_baim_val_m/d`에 신규 코드그룹(다음 가용 `COMxxx`) + **기본 직급 세트 시드**(`SORT_IDX`로 순서). 관리 화면은 기존 Baim_02(공통코드 관리) 활용. |

## 2. 초안에서 잘라낸 / 바로잡은 항목

| 초안 내용 | 처리 | 이유 |
|---|---|---|
| NODE 상향 순차 자동 결재(`buildApprovalChain`, PARENT_NODE 추적, SELF_ATTD_APPRV_YN/MAIN·SUB_ADMIN 자동판정) | **폐기** | 결재라인을 사용자가 직접 구성하는 모델로 변경(결정 #1) |
| `BAIM_LEAVE_BACKDATE_LIMIT`(회사별 사후 N일) | **폐기** | 사후 기한을 근태 마감으로 대체(결정 #4) |
| `BAIM_LEAVE_USE_UNIT`(회사 전체 단일 다중선택) | **폐기** | 사용단위는 도메인별로 이미 분리됨(결정 #7) |
| `ALLOW_*` 4컬럼 DROP 후 BAIM 이관 | **변경**: `tb_leave_usage_policy` 유지·재모델 | `ALLOW_HALF_DAY`는 PRAFTA-018 §8.5.3에 묶임. QUARTER/HOURLY만 시간차 토글로 교체(결정 #8) |
| SYS025 `ON DUPLICATE KEY UPDATE` 시드 | **변경**: 깨끗한 재정의(B안) | 코드 의미 충돌 방지(결정 #5) |
| `tb_user_leave_grant.GRANT_DAYS → decimal(5,2)` | **제거** | 부여는 일 단위, 정밀도 상향 근거 없음. `USED_DAYS`만 `decimal(8,5)` |
| 휴게 가로지름 거부 / 1일 환산 / 시작시각 근무내 | **참조로 축약** | 이미 정책 §8.5.9에 명시된 기존 규칙 (신규 아님) |
| 대상 모듈 "attd06" | **정정** | attd06=교대근무. 실제: attd03/05/07/09 |

## 3. 작업 분해 · 의존성 · 순서

| 코드 | 작업 | 핵심 산출물 | 의존 |
|---|---|---|---|
| **A** | 시간차 연차 사용단위 (SYS025 재정의 + `tb_leave_usage_policy` 재모델 + 동적 차감 유틸 + 타입화면 정리) | DDL, attd03, baim07/common-leave | 독립 |
| **B** | 사용자별 직급관리 (`tb_user.RANK_CD` + BAIM_VAL 직급 시드 + User_01 배정) | DDL, BAIM 시드, web/user, User_01 | 독립 |
| **C** | 근태 마감 (신규 테이블 + 마감/해제 로직 + Attd_07 연결) | 신규 테이블, attd07 | 독립(정책 정독 선행) |
| **D** | 연차 요청별 결재라인 (신규 User_04 화면 + 라인 저장 테이블 + SYS043) | User_04(신규), `tb_user_attd_req_approval`, SYS043 | **B** |
| **E** | 연차 신청·결재 흐름 본체 (Y/N 판단·라인 태움·사전/사후·시간차 검증·차감·출근차단) | 법정 결재Y/N 컬럼, 휴게시각 컬럼, attd05/07/09 | **A·C·D** |

## 4. 공통 전제 / 주의

- **운영 DB 확인 의무**: SYS025 현재값(`01~04`), 직급 코드그룹 다음 가용 `COMxxx`, 운영 연차 데이터 유무는 **착수 시 MCP/운영DB로 1회 확인** 후 진행 (스키마 스냅샷엔 데이터 없음).
- **정책 우선순위**: 요청승인관리 재기획서 > 공통 정책 > 근태 정책 > 기술 정책. 충돌 시 비즈니스 정책 우선.
- **DTO/SQL 규칙**: CLAUDE.md 준수 (대문자 컬럼·leading comma·`#{}` 바인딩·`SELECT *` 금지·스키마 100% 일치).
- 각 작업요청서는 planner가 정책 INDEX 경유로 관련 섹션을 정독한 뒤 작업으로 분해한다.
