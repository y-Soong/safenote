1. DB 직접 변경 내역 (ALTER / 코드성 마이그레이션)
================================================================================

본 작업(prafta-010-1)에서 신규로 수행한 DDL/마이그레이션 없음.

[권장 DDL — 미실행]
  tb_user_attd_req.TARGET_ID 컬럼 코멘트가 현 스키마상 "(SYS032: 01~06)" 등
  요청유형 코드를 가리키는 것처럼 되어 있으나, TARGET_ID 의 실제 의미는
  "이 요청이 귀결될 TB_USER_ATTD_MGMT.ATTD_ID" 이다(수정요청=기존 ATTD_ID,
  생성요청=사용자측 요청 시점 사전 채번 ATTD_ID).
  코멘트 정정을 권장하나 본 작업에서는 실행하지 않는다. 권장 DDL 예시:

    ALTER TABLE tb_user_attd_req
      MODIFY COLUMN TARGET_ID varchar(20) NULL
      COMMENT '이 요청이 귀결될 ATTD_ID (수정요청=기존 ATTD_ID, 생성요청=사전 채번 ATTD_ID)';

  ※ 위 DDL 은 미실행 상태이며, 실행 여부/정확한 코멘트 문구는 별도 승인 후 진행.

  --- PRAFTA-010-1-023 (코드 무수정 — 검증 결과 기록) ---
  검증 결과(이전 developer 조사 + 본 세션 재확인):
    1) 2차 이력 적재 정상.
       - 승인: Attd07ServiceImpl.updateUserAttdRequest 8단계에서
         InsertUserAttdHistsCommand.from(...) 으로 HIST_TYPE='01' 적재.
       - 반려: rejectUserAttdRequest 6단계에서 forReject(...) 로
         HIST_TYPE='07' 적재(BEF_/AFT_ 전부 NULL).
       => 이력 코드 수정 불필요.
    2) 생성요청 BEF 처리 정상.
       - 생성요청은 oriCheckIn/oriCheckOut(BEF_ 계열)이 NULL 이며,
         InsertUserAttdHistsCommand.from(...) 이 그 NULL 을 그대로 적재한다
         (승인 전 상태 없음 = 정상).
    3) SYS032 코드그룹 분석.
       - SYS032 는 단일 코드그룹(01~06=요청유형, 07=관리자반려)을
         REQ_TYPE 과 HIST_TYPE 이 공유한다.
       - REQ_TYPE 실데이터는 enum 문자열(ATTD_CREATE / ATTD_MODIFY 등)로
         저장되므로, 스키마 코멘트의 "(SYS032: 01~06)" 표기는 부정확하다.
    4) 요청 시점(1차 이력)용 별도 HIST_TYPE 코드 없음.
       - 1차 이력(사용자 요청 시점 이력) 적재는 본 작업 범위 외(모바일 기능).
       => PRAFTA-010-1-021 테스트 데이터에 1차 이력 행을 포함하지 않는다.
