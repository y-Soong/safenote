# prafta-019-C · 근태 마감

> **목적**: 사후 신청 기한의 기준이 될 **근태 마감** 기능을 도입한다. (연차 사후 신청은 "근태 마감 전까지"만 허용 — 결정 #4)
> **의존**: 독립(단, 정책 정독 선행 필요). 작업 E가 사후 기한 판정에 사용. 참조: `prafta-019-plan.md`
>
> ⚠️ 현재 근태 마감 테이블·로직이 **전무**(greenfield). 범위가 크므로 planner가 관련 정책을 정독한 뒤 상세 설계할 것.

---

## 1. 범위 (포함)

### 1.1 근태 마감 신규 테이블

- 회사/사업장 단위로 특정 기간(월/마감기준)의 근태를 마감 상태로 관리하는 테이블 신규 설계.
- 컬럼 후보(planner 확정): 회사코드, 사업장코드, 마감 기준월(또는 기간), 마감 상태, 마감 일시, 마감자, (해제 시) 해제 일시/해제자, 표준 메타.
- 정책서 §13(근태 마감)·재기획서 §9.4(마감 기준일 데이터 연동)와 컬럼·규칙 정합.

### 1.2 마감 / 해제 로직

- **마감 시**: 해당 기간의 사후 신청(연차/초과/보정) 차단.
- **해제 시**: 재수정 → 재마감 플로우(재기획서 §1.4).
- **자동 마감 금지**(재기획서 §3.3) — 마감 도래해도 차단 사유 잔존 시 "마감 지연" 상태 표시. 강제 마감 미도입.
- 마감 기준일 = 사업장 마스터 `attendanceCloseRule`을 휴일 마스터로 영업일 변환(재기획서 §9.4).

### 1.3 Attd_07 연결

- `src/views/attd/Attd_07.vue`(근무 관리)에 마감/해제 진입점 + 마감 상태 표시.
- 백엔드 `web/attd/attd07/**`에 마감 조회·처리 API.

## 2. 범위 외

- 연차 사후 신청이 이 마감을 **참조**하는 로직 → **E**.
- 임금 정산 연동은 v1 스코프 외(재기획서 §3.4).

## 3. 영향 파일

- 테이블: 근태 마감 신규(이름 planner 확정)
- 백엔드: `web/attd/attd07/**`
- 프론트: `src/views/attd/Attd_07.vue`

## 4. 정책 출처

- 근태 §12(스케줄 마감), §13(근태 마감 — 선행 조건/차단 조건)
- 요청승인관리 재기획서 §3.3(자동마감 금지), §9.4(마감 기준일 연동)

## 5. 주의

- 마감 단위(월 단위 vs 임의 기간), 마감 권한(AUTH_*), 마감 후 예외 처리 절차는 정책 정독 후 확정.
- 본 작업은 다른 작업 대비 설계 비중이 크다 — 필요 시 "정책 정합 설계" 단계를 먼저 분리.
