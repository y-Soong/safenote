## 1. W-07: TBM 진행 콘솔 (메인)

이 화면은 TBM 진행 중 관리자가 머무는 메인 화면. **3개 영역으로 구성**.

### 1.1 화면 구성

```
┌─────────────────────────────────────────────────────────────┐
│  5월 1주차 TBM             [IN_PROGRESS]    [⏹ 교육 종료]  │
│  시작: 08:05  │  경과: 12분 30초  │  비번: 입실 123456 / 종료 654321 │
├──────────────────────────────────┬──────────────────────────┤
│                                  │  참여자 (30명)        🔍 │
│  [현재 슬라이드]                  │  ┌────────────────────┐ │
│  ┌────────────────────────────┐ │  │ ✓ 홍길동           │ │
│  │                            │ │  │ ✓ 김철수    ⚠️    │ │
│  │  지게차 안전 영상           │ │  │ ✓ 박영희           │ │
│  │  [▶ 재생]                  │ │  │ ✓ 김일용 [QR]      │ │
│  │                            │ │  │ ...                │ │
│  │                            │ │  └────────────────────┘ │
│  └────────────────────────────┘ │  [+ 일용직 QR 스캔]      │
│                                  │                          │
│  [⏮ 이전 슬라이드] [⏭ 다음]      │  요약                    │
│                                  │  정규직 25 / 일용직 5    │
│  슬라이드 1 / 5                   │  이상 신호 2명            │
└──────────────────────────────────┴──────────────────────────┘
```

### 1.2 영역별 정의

#### 영역 A: 헤더 (상단)

| 표시 정보 | 설명 |
|---|---|
| 세션 제목 | 수정 불가 |
| 상태 배지 | OPENED / IN_PROGRESS (실시간 갱신) |
| 시간 정보 | 시작 시각, 경과 시간 (1초마다 갱신) |
| 비밀번호 표시 | **관리자만 보임**, 입실/종료 비번 |
| "교육 종료" 버튼 | IN_PROGRESS 상태에서만 활성, 클릭 시 W-10 |

**비밀번호 영역 사용성:**
- 큰 폰트로 명확히 (구두 전달 시 보기 쉽게)
- 복사 버튼 (📋)
- 재발급 버튼 (선택, 비번 노출 의심 시)
- 종료 비번은 IN_PROGRESS 상태에서 노출 (그 전엔 숨김 또는 흐리게)

#### 영역 B: 콘텐츠 영역 (좌측 메인)

진행 중인 콘텐츠 표시 + 슬라이드 제어.

**OPENED 상태 (교육 시작 전):**
```
┌─────────────────────────────────────────┐
│  교육 시작 대기 중                       │
│                                         │
│  현재 30명 입실 완료                     │
│                                         │
│  [▶ 교육 시작]                          │
│                                         │
│  ⓘ 시작하면 신규 입실이 차단됩니다       │
└─────────────────────────────────────────┘
```

**IN_PROGRESS 상태:**
- 현재 표시 중인 콘텐츠 (영상 player, 이미지, PDF 등)
- 또는 "교육 내용" 텍스트 (콘텐츠 미선택 시)
- 슬라이드 인덱스 표시
- 좌우 이동 버튼

#### 영역 C: 참여자 모니터링 (우측, W-08)

§2에서 상세 다룸.

### 1.3 슬라이드 제어 동작

**관리자가 [⏭ 다음 슬라이드] 클릭:**
```
1. 클라이언트가 다음 콘텐츠 정보 계산
2. POST /api/web/tbm/sessions/{no}/sync-state 호출
   { currentContentNo, currentSlideIndex, syncStateCd: 'PLAYING' }
3. 서버가 TB_EDU_SESSION_STATE UPSERT
4. SSE로 모든 참여자에게 'session.state' 푸시
5. 관리자 본인 화면도 갱신
```

**키보드 단축키:**
- ← / → : 슬라이드 이동
- 스페이스 : 영상 재생/일시정지
- ESC : 풀스크린 모드 해제 (관리자도 풀스크린 가능)

### 1.4 데이터 바인딩

**세션 정보 조회:** `GET /api/web/tbm/sessions/{eduSessionNo}` (`03_BACKEND_SPEC_WEB.md §5.2`)
**교육 시작:** `POST /api/web/tbm/sessions/{eduSessionNo}/start` (`§6.1`)
**슬라이드 변경:** `POST /api/web/tbm/sessions/{eduSessionNo}/sync-state` (`§6.2`)
**참여자 명단:** `GET /api/web/tbm/sessions/{eduSessionNo}/attendances/live` (`§6.3`)
**교육 종료:** `POST /api/web/tbm/sessions/{eduSessionNo}/end` (`§6.6`)

**SSE 구독:** `GET /api/web/tbm/sessions/{eduSessionNo}/sse` (`§6.8`)

### 1.5 SSE 이벤트 처리 (관리자 측)

| 이벤트 | 처리 |
|---|---|
| `attendance.updated` | 참여자 명단 부분 갱신 (새 입실/종료/이상) |
| `session.ended` | 다른 디바이스에서 종료된 경우 화면 전환 (rare case) |

### 1.6 폴링 대안

SSE 구현 부담 시 폴링으로 대체 가능:
- 3초 간격 `GET /attendances/live`
- 다만 트래픽 부담 + 즉시성 떨어짐
- **권장: SSE**

### 1.7 사용성 요구사항

- **풀스크린 모드**: 영상 재생 시 자동 풀스크린 (현장 시연용)
- **자동 일시정지**: 영상 종료 시 자동으로 다음 슬라이드 안내
- **연결 끊김 알림**: SSE 끊기면 빨간 띠 표시 + "재연결 시도 중..."
- **종료 확인**: "교육 종료" 클릭 시 미종료자 명단 모달 (W-10)

### 1.8 진입/이탈 처리

**진입 시:**
- 권한 체크 (개설자 본인 또는 safe)
- 세션 STATUS_CD 검증 (OPENED 또는 IN_PROGRESS만)
- SSE 연결
- 참여자 명단 초기 로딩

**이탈 시 (다른 페이지 이동, 탭 닫기 등):**
- 세션은 그대로 (IN_PROGRESS 유지) — **단순 화면 이탈은 종료 아님**
- SSE 연결 해제
- 다시 들어오면 현재 상태 그대로 복원 (서버가 진실 소스)

## 2. W-08: 입실자 모니터링 (W-07 우측 영역)

### 2.1 화면 구성

```
┌────────────────────────────┐
│  참여자 (30명)         🔍 │
│  [전체▼] [이상신호 ☐]      │
├────────────────────────────┤
│  ✓ 홍길동   생산1팀  08:01 │
│  ✓ 김철수   생산1팀  08:02 │
│    ⚠️ 백그라운드 1회 (1분)  │
│  ✓ 박영희   생산2팀  08:02 │
│  ✓ 김일용  [QR] 일용직 08:03│
│  ⚠️이상한   생산1팀  08:05 │
│    📍 GPS 이탈 감지        │
│  ...                       │
├────────────────────────────┤
│  [+ 일용직 QR 스캔]         │
├────────────────────────────┤
│  요약                       │
│  정규직: 25명               │
│  일용직: 5명                │
│  이상 신호: 2명             │
└────────────────────────────┘
```

### 2.2 참여자 행 표시

| 요소 | 표시 |
|---|---|
| 상태 아이콘 | ✓ (정상) / ⚠️ (이상 신호) / ✕ (미이수, 사후 처리됨) |
| 이름 | userNm |
| 소속/배지 | 정규직: deptNm / 일용직: `[QR]` 배지 |
| 입실 시각 | `08:01` |
| 이상 신호 (서브 라인) | "백그라운드 N회 (총 X분)" 또는 "GPS 이탈 감지" |

### 2.3 이상 신호 시각화

| 신호 | 표시 | 임계값 |
|---|---|---|
| 백그라운드 진입 | "백그라운드 N회 (M분)" | N ≥ 1 |
| GPS 이탈 (AUTO 모드) | "📍 GPS 이탈 감지" | 반경 초과 |
| 네트워크 끊김 | "🔌 네트워크 끊김 N회" | N ≥ 3 |
| 종료 미처리 | "⏳ 종료 미처리" | 세션 COMPLETED 후 |

**색상 코드:**
- 정상: 회색 (기본 텍스트)
- 경미 이상 (백그라운드 1~2회): 노랑 배경
- 심각 이상 (GPS 이탈 등): 주황 배경 + 빨간 아이콘

### 2.4 필터링

- **전체 / 정규직 / 일용직** 셀렉트
- **이상 신호만** 체크박스
- **검색**: 이름 검색

### 2.5 행 클릭 시

- 행 클릭 → 참여자 상세 모달 또는 인라인 펼치기
- 표시 정보: 이벤트 타임라인 (간이), 디바이스 토큰, GPS 좌표, 서명 미리보기 (있으면)
- 액션 (필요 시): "강제 종료 처리" (W-11 모달로)

### 2.6 데이터 바인딩 및 갱신

**초기 로딩:** `GET /api/web/tbm/sessions/{no}/attendances/live`

**실시간 갱신 방식:**
- SSE `attendance.updated` 이벤트 수신 → 해당 참여자만 부분 갱신
- 또는 폴링 3~5초 간격
- **이상 신호 변화는 백엔드가 집계해서 제공** (클라이언트는 계산 X)

### 2.7 "일용직 QR 스캔" 버튼

클릭 시 → W-09 모달 열림.

### 3.2 QR 스캔 라이브러리

권장 라이브러리:
- **html5-qrcode** (가장 안정적)
- 또는 **zxing-js**
- Vue3 래퍼 컴포넌트 작성 또는 기존 사용 시 재사용

**브라우저 권한:**
- 카메라 권한 요청
- HTTPS 필수
- 거부 시 "수동 입력" 폴백

### 3.3 데이터 바인딩

**스캔 직후 미리보기 (선택):** `POST /api/app/tbm/qr/preview`
- 또는 입실 처리 시 한 번에 검증

**입실 처리:** `POST /api/web/tbm/sessions/{no}/qr-attendance/enter`
- 본 모달은 모바일 관리자(M-12)도 같은 흐름. 웹에선 데스크탑 카메라 사용

### 3.4 종료 모드 흐름

3.1~3.2와 유사하지만:

│  │      여기에 서명해주세요              │   │
│  │                                     │   │

**서명 처리:**
- 캔버스에 그리기 (Vue3 + signature_pad 라이브러리 권장)
- 빈 서명 차단
- 확인 시 PNG로 변환하여 `multipart/form-data` 전송
- 호출: `POST /api/web/tbm/sessions/{no}/qr-attendance/{attendanceNo}/exit`

### 3.5 사용성 요구사항

- **연속 스캔**: 입실 처리 후 자동으로 다음 QR 스캔 화면으로 (관리자 빠르게 처리)
- **음성/진동 피드백**: QR 인식 성공 시 ding 사운드 + 진동 (모바일)
- **카메라 전환**: 모바일은 전면/후면 전환 버튼
- **오프라인 큐잉**: 네트워크 끊김 시 로컬 큐 → 복구 시 일괄 전송 (선택, MVP 외)

## 4. W-10: 종료 처리 화면

### 4.1 화면 구성

**관리자가 "교육 종료" 클릭 시 표시되는 모달:**

```
┌─────────────────────────────────────────────────────────┐
│  교육 종료 확인                                   [X]   │
├─────────────────────────────────────────────────────────┤

│                                                          │
│  📊 현재 상태                                            │
│  • 총 참여자: 30명                                       │
│  • 종료 완료: 28명                                       │
│  • 미종료자: 2명                                         │
│                                                          │
│  ⚠️ 이상 신호가 감지된 인원이 있습니다 (2명)              │
│                                                          │
│  ┌───────────────────────────────────────────────┐    │
│  │  미종료자 명단                                  │    │
│  │  ─────────────────────────────────────────    │    │
│  │  ☐ 김철수 - 백그라운드 5회 (총 8분)             │    │
│  │  ☐ 이상한 - GPS 이탈 감지                       │    │
│  └───────────────────────────────────────────────┘    │
│                                                          │
│  [○ 미종료자 그대로 두기] (개별 처리 W-11)               │
│  [● 미종료자 일괄 처리]                                  │

```

### 4.2 시나리오 분기

**시나리오 A: 미종료자 없음**
- 종료 확인 다이얼로그만 표시
- "교육 종료" 클릭 시 즉시 종료

**시나리오 B: 미종료자 있음 + 모두 종료 처리**
- 라디오 선택: "미종료자 일괄 처리" + 이수/미이수 선택 + 사유 입력
- "교육 종료" 클릭 시 백엔드가 강제 종료 일괄 적용 + 세션 종료

**시나리오 C: 미종료자 있음 + 개별 처리 원함**
- 라디오 선택: "미종료자 그대로 두기"
- 세션은 COMPLETED로 종료
- 미종료자는 EXIT_AT IS NULL 상태로 남음
- 관리자가 추후 W-11에서 개별 처리

### 4.3 데이터 바인딩

**호출:** `POST /api/web/tbm/sessions/{no}/end` (`03_BACKEND_SPEC_WEB.md §6.6`)

```json
{
    "forceEndOptions": {
        "applyToNotExited": true,
        "defaultCompletionStatus": "COMPLETED",
        "defaultReason": "관리자 일괄 처리 - 현장 확인 완료"
    }
}
```

또는 `forceEndOptions` 생략 시 미종료자 그대로.

### 4.4 종료 후 자동 이동

- 종료 성공 → W-13 (출결 상세) 또는 W-12 (이력) 자동 이동
- 또는 W-07 그대로 유지 (COMPLETED 상태로 표시)

### 6.1 SSE Composable 예시 (참고)

```typescript
// useSseConnection.ts (개념)
export function useSseConnection(sessionNo: number) {
  const eventSource = ref<EventSource | null>(null)
  const connectionState = ref<'CONNECTING' | 'CONNECTED' | 'DISCONNECTED'>('CONNECTING')

  function connect() {
    const url = `${API_BASE}/api/web/tbm/sessions/${sessionNo}/sse`
    eventSource.value = new EventSource(url, { withCredentials: true })

    eventSource.value.addEventListener('attendance.updated', (e) => {
      const data = JSON.parse(e.data)
      // 참여자 명단 부분 갱신
    })

    eventSource.value.addEventListener('error', () => {
      connectionState.value = 'DISCONNECTED'
      // 자동 재연결 로직
      setTimeout(connect, 3000)
    })

    eventSource.value.onopen = () => {
      connectionState.value = 'CONNECTED'
    }
  }

  function disconnect() {
    eventSource.value?.close()
    eventSource.value = null
  }

  onMounted(connect)
  onUnmounted(disconnect)

  return { connectionState }
}
```

⚠️ JWT 토큰을 SSE 헤더로 전달하려면 EventSource 폴리필 또는 fetch-event-source 라이브러리 필요할 수 있음. Claude Code가 인증 방식 확인.

6. **연결 끊김 재시도 정책** — exponential backoff 등
