# 앱 작업지시서 - 근로자 TBM 플로우 (M-01 ~ M-10)

> 본 문서는 TBM 모듈의 **근로자(정규직) 앱 화면 10개**를 정의합니다.
> 백엔드 API는 `04_BACKEND_SPEC_APP.md §4~§7` 참조.
> 환경: Flutter + Vue WebApp 번들 (APK), Android 우선, 향후 iOS 검토.

---

## 0. 본 문서에서 다루는 화면

| 화면 ID | 이름 | 설명 |
|---|---|---|
| M-01 | TBM 메인 (3탭) | 교육시작전/진행중/완료 3탭 구조 |
| M-02 | 교육시작전 탭 | 입실 가능한 TBM 목록 |
| M-03 | 입실 비밀번호 입력 | 비번 + GPS 검증으로 입실 |
| M-04 | 입실 대기 화면 | 관리자가 교육 시작할 때까지 대기 |
| M-05 | 교육 진행 화면 | SSE 동기화된 콘텐츠 표시 |
| M-06 | 첨부자료 풀스크린 모달 | 자료 클릭 시 풀스크린 |
| M-07 | 교육 종료 처리 | 종료 비번 입력 팝업 |
| M-08 | 서명 화면 | 캔버스 서명 |
| M-09 | 교육진행중 탭 | 본인이 진행 중인 TBM 복귀용 |
| M-10 | 교육완료 탭 | 본인 이수 이력 |

## 1. M-01: TBM 메인 (3탭 구조)

### 1.1 화면 구성

```
┌──────────────────────────────────┐
│  ← TBM                          ⚙ │  ← 헤더
├──────────────────────────────────┤
│ [교육시작전] [진행중] [완료]      │  ← 탭 바
├──────────────────────────────────┤
│                                  │
│                                  │
│        탭 내용 영역               │  ← 선택 탭 화면 표시
│                                  │
│                                  │
└──────────────────────────────────┘
```

### 1.2 탭 구성

| 탭 | 화면 | 뱃지 표시 |
|---|---|---|
| 교육시작전 | M-02 | 입실 가능한 TBM 수 |
| 진행중 | M-09 | 본인이 입실하고 종료 안 한 TBM 수 (보통 0 또는 1) |
| 완료 | M-10 | (없음) |

### 1.3 진입 시 동작

- 앱 부팅 시 또는 푸시 알림 탭 시 진입
- 기본 탭: **교육시작전** (가장 자주 사용)
- 단, 푸시 알림으로 진입 시 해당 TBM이 있는 탭으로 자동 이동
- 본인이 IN_PROGRESS인 TBM이 있으면 **진행중** 탭으로 자동 이동 (UX 보완)

### 1.4 권한

- 999999 (일반 사용자) 또는 그 이상
- 본인 회사·사업장 데이터만 표시 (백엔드 필터링)

## 3. M-03: 입실 비밀번호 입력

### 3.1 화면 구성

```
┌──────────────────────────────────┐
│  ← 5월 1주차 TBM 입실             │
├──────────────────────────────────┤
│                                  │
│  📌 관리자가 알려준                │
│     입실 비밀번호를 입력하세요     │
│                                  │
│  ┌──────────────────────────┐   │
│  │   ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐  │   │
│  │   │ ││ ││ ││ ││ ││ │  │   │
│  │   └─┘└─┘└─┘└─┘└─┘└─┘  │   │
│  └──────────────────────────┘   │
│                                  │
│  📍 위치 확인 중...                │
│  (또는 ✓ 위치 확인됨)              │
│  (또는 ⚠️ 위치 확인 불가 -        │
│       관리자 모드)                │
│                                  │
│         [입실하기]               │
│                                  │
│  ⓘ 본인 폰으로만 입실 가능합니다  │
└──────────────────────────────────┘
```

### 3.2 비밀번호 입력 UI

- **6자리 분리 입력** (PIN 스타일)
- 각 칸 입력 시 자동 다음 칸 포커스
- 키보드: 숫자 키패드
- 자동 입력 (Autofill) 차단

### 3.3 GPS 수집

- 화면 진입 시 자동으로 `navigator.geolocation.getCurrentPosition` 호출
- **상태 표시**:
  - 수집 중: "📍 위치 확인 중..."
  - 성공: "✓ 위치 확인됨"
  - 실패: "⚠️ 위치 확인 불가" (세션이 MANUAL 모드면 OK, AUTO 모드면 입실 시도 시 에러)
- **권한 거부 시**: 안내 모달 "위치 권한이 필요합니다. 설정에서 허용 후 다시 시도하세요."

### 3.4 "입실하기" 동작

```
1. 비밀번호 6자리 입력 완료 확인
2. GPS 좌표 확보 (없으면 null로 전송)
3. POST /api/app/tbm/sessions/{no}/enter
   { entryPwd, userGpsLat, userGpsLng }
   Header: X-Device-Token
4. 응답 처리:
   - 200 → M-04 (입실 대기) 이동
   - 401 비번 불일치 → 입력 칸 흔들기 + "비밀번호가 일치하지 않습니다"
   - 403 GPS 반경 이탈 → "교육 장소에서 {N}m 떨어져 있습니다"
   - 409 이미 입실 → M-04 또는 M-05로 이동
   - 409 상태 위반 (교육 시작됨) → "이미 교육이 시작되어 입실할 수 없습니다"
```

### 3.5 데이터 바인딩

**호출:** `POST /api/app/tbm/sessions/{eduSessionNo}/enter` (`04_BACKEND_SPEC_APP.md §5.1`)

### 3.6 에러 처리 디테일

| 에러 코드 | 메시지 | 사용자 행동 |
|---|---|---|
| `COMMON_401_001` | "비밀번호가 일치하지 않습니다" | 재입력 |
| `COMMON_403_002` | "교육 장소에서 {distance}m 떨어져 있습니다" | 이동 후 재시도 |
| `COMMON_403_003` | "본인 디바이스가 아닙니다" | 본인 디바이스 사용 |
| `COMMON_409_001` | "교육이 이미 시작되어 입실할 수 없습니다" | 다음 회차 대기 |
| `COMMON_409_002` | "이미 입실한 교육입니다" | 진행 화면(M-05)으로 자동 이동 |

## 4. M-04: 입실 대기 화면

### 4.1 화면 구성

```
┌──────────────────────────────────┐
│  ← 5월 1주차 TBM                  │
├──────────────────────────────────┤
│                                  │
│  ✓ 입실 완료                      │
│  ─────────────                   │
│                                  │
│         [관리자 아이콘]            │
│                                  │
│  👨‍💼 김안전 관리자이             │
│     교육을 시작하면              │
│     자동으로 시작됩니다           │
│                                  │
│  ⏳ 대기 중...                    │
│                                  │
│  현재 30명 입실 완료              │
│                                  │
│  ─────────────                   │
│  [화면 끄기 방지 ON]              │
│                                  │
└──────────────────────────────────┘
```

### 4.2 SSE 구독

화면 진입 시 SSE 연결:
- `GET /api/app/tbm/sessions/{no}/sse`
- 이벤트 수신:
  - `session.started` → 자동으로 M-05 이동
  - `session.cancelled` → "세션이 취소되었습니다" 안내 후 M-02 복귀
  - `attendance.updated` → 입실 명단 카운트 갱신 (선택)

### 4.3 백그라운드 처리

- **앱 백그라운드 진입 시**: SSE 연결 유지 시도 (모바일은 제한적)
- **포그라운드 복귀 시**: SSE 재연결 + 현재 세션 상태 재조회
  - 만약 이미 IN_PROGRESS → M-05로 자동 이동
- **푸시 알림 백업**: 백엔드가 `session.started` 시 푸시도 함께 발송 (앱이 백그라운드여도 알림)

### 4.4 화면 끄기 방지

- Wake Lock API 또는 Flutter wakelock_plus 패키지 활용
- 사용자가 토글 가능
- 배터리 소모 경고 (선택)

### 4.5 데이터 바인딩

**호출:** `GET /api/app/tbm/sessions/{no}/my-view` (`04_BACKEND_SPEC_APP.md §5.2`)
**SSE:** `GET /api/app/tbm/sessions/{no}/sse`

## 5. M-05: 교육 진행 화면

### 5.1 화면 구성 (텍스트 메인 + 자료 미리보기)

```

├──────────────────────────────────┤
│                                  │

│  오늘 TBM 주제는 지게차 안전입니다.│
│                                  │
│  주요 위험요인:                   │
│  • 추돌 사고                      │
│  • 작업 반경 내 인원              │
│                                  │
│  대책:                            │
│  • 후방 카메라 작동 확인          │
│  • 안전 통로 확보                 │
│                                  │
│  ─────────────                   │
│  📎 첨부 자료                     │
│                                  │
│  ┌────┬────┬────┐               │
│  │📹  │🎬  │📄  │               │
│  │지게차│안전│PDF │               │
│  │안전 │교육 │자료 │               │
│  └────┴────┴────┘               │
│                                  │
│  현재 표시 중: 지게차 안전 영상    │
│                                  │
└──────────────────────────────────┘
```

### 5.2 영역 구성

| 영역 | 내용 |
|---|---|
| 헤더 | 세션 제목 + 진행 상태 |
| 교육 내용 (메인) | HTML 렌더링 (리치 텍스트) — 스크롤 가능 |
| 첨부 자료 (보조) | 작은 카드 그리드 (썸네일 + 제목) |
| 현재 표시 표시줄 | 관리자가 SSE로 푸시한 현재 콘텐츠 강조 |

### 5.3 HTML 렌더링

- `v-html` 또는 안전한 HTML 렌더링 라이브러리 사용
- **XSS 방지**: DOMPurify로 sanitize
- 허용 태그: p, br, strong, em, u, ul, ol, li, h1~h3, a (target=_blank)
- 이미지 태그는 콘텐츠 본문에서 차단 (별도 첨부자료 영역으로)

### 5.4 SSE 동기화

수신 이벤트별 처리:

| 이벤트 | 동작 |
|---|---|
| `session.state` | `currentContentNo` 변경 시 해당 카드 강조 + (옵션) 자동으로 풀스크린 모달 열기 |
| `session.ended` | M-07 (종료 비번 입력) 자동 이동 |
| `session.cancelled` | M-02 복귀 + 안내 |

### 5.5 첨부 자료 카드

- 그리드 3열 (모바일 좁은 화면은 2열)
- 각 카드: 썸네일 + 제목 + 미디어 타입 아이콘
- **클릭 시 M-06 풀스크린 모달** 열기
- 현재 관리자가 선택한 콘텐츠는 강조 표시 (배경 색 또는 테두리)

### 5.6 이벤트 보고

화면 진입/이탈, 백그라운드 진입/복귀 등 이벤트 자동 보고:

```
[화면 진입]
  → POST /events { eventTypeCd: 'START' }

[백그라운드 진입]
  → POST /events { eventTypeCd: 'BACKGROUND_IN' }

[포그라운드 복귀]
  → POST /events { eventTypeCd: 'BACKGROUND_OUT' }

[콘텐츠 조회 시작]
  → POST /events { eventTypeCd: 'CONTENT_VIEWED', eventData: { contentNo, durationSec } }
```

**오프라인 큐잉:**
- 이벤트는 로컬 SQLite 또는 메모리 큐에 즉시 저장
- 1~5초 배치 또는 즉시 전송
- 네트워크 끊김 시 큐에 누적
- 복구 시 일괄 전송

### 5.7 데이터 바인딩

**초기 로딩:** `GET /api/app/tbm/sessions/{no}/my-view` (`04_BACKEND_SPEC_APP.md §5.2`)
**SSE:** `GET /api/app/tbm/sessions/{no}/sse`
**이벤트 보고:** `POST /api/app/tbm/attendances/{ano}/events` (`§6.2`)

## 6. M-06: 첨부자료 풀스크린 모달

### 6.1 화면 구성

```
┌──────────────────────────────────┐
│                            [X]   │  ← 우측 상단 닫기
│                                  │
│                                  │
│       [영상/이미지/PDF 풀화면]    │
│                                  │
│                                  │
│                                  │
│  ─────────────                   │
│  지게차 안전 영상                 │
│  2024년 OO공장 지게차 추돌 사례    │
└──────────────────────────────────┘
```

### 6.2 미디어 타입별 표시

| 타입 | 표시 방식 |
|---|---|
| VIDEO | HTML5 video player (controls=true, autoplay=true, playsinline=true) |
| YOUTUBE | YouTube iframe embed |
| IMAGE | 풀스크린 이미지 (핀치 줌 지원, photo viewer) |
| PDF | PDF.js 또는 네이티브 PDF 뷰어 (Flutter pdfx 등) |

### 6.3 닫기 동작

- 우측 상단 X 버튼 클릭
- 모바일 백 제스처 또는 백 버튼
- 닫으면 M-05로 복귀
- **현재 슬라이드 유지**: 관리자가 슬라이드 변경했어도 사용자가 닫을 때까지 풀스크린 유지

### 6.4 영상 재생 정책

- 매번 0초부터 시작 (단순함)
- 사용자가 일시정지/재생 가능
- 다른 콘텐츠 선택 시 현재 영상 정지

### 6.5 사용성

- **화면 회전**: 영상은 가로 모드 권장 (Flutter orientation lock)
- **상태바 자동 숨김**: 영상 풀스크린 시
- **자동 종료 후 동작**: 영상 끝나면 자동 닫기 또는 사용자 대기

### 6.6 데이터 바인딩

미디어 파일 URL은 M-05에서 미리 로드한 콘텐츠 정보에서 사용. 별도 API 호출 X.

콘텐츠 시청 이벤트 보고:
```
POST /api/app/tbm/attendances/{ano}/events
{
  "eventTypeCd": "CONTENT_VIEWED",
  "eventData": { "contentNo": 123, "durationSec": 45 }
}
```

## 7. M-07: 교육 종료 처리

### 7.1 화면 구성 (모달)

```
┌──────────────────────────────────┐
│  교육 종료                  [X]   │
├──────────────────────────────────┤
│                                  │
│  📌 관리자가 알려준                │
│     종료 비밀번호를 입력하세요     │
│                                  │
│  ┌──────────────────────────┐   │
│  │   ┌─┐┌─┐┌─┐┌─┐┌─┐┌─┐  │   │
│  │   │ ││ ││ ││ ││ ││ │  │   │
│  │   └─┘└─┘└─┘└─┘└─┘└─┘  │   │
│  └──────────────────────────┘   │
│                                  │
│         [다음 →]                  │
│                                  │
└──────────────────────────────────┘
```

### 7.2 진입 경로

- 관리자가 교육 종료 → SSE `session.ended` → 자동 진입
- 또는 사용자가 직접 "종료" 버튼 (M-05 우측 상단) → 진입

### 7.3 비번 검증

- 입력 후 "다음" 클릭
- **클라이언트 측 검증 X** (서버에서만 검증)
- 서버 검증 후 M-08 (서명 화면) 이동
- 비번 불일치 시 "비밀번호가 일치하지 않습니다" + 입력 칸 흔들기

### 7.4 종료 비번 검증과 서명 분리 vs 통합

**옵션 A: 분리 (M-07 → M-08)**
- 7단계: 비번 입력 → 검증 → 8단계: 서명 → 제출
- 두 번 API 호출

**옵션 B: 통합 (M-07 + M-08을 한 화면)**
- 비번 입력 + 서명을 한 화면에서
- 한 번에 제출

**권장: B (통합)** — 사용자 단계 줄임, 단일 트랜잭션.

### 7.5 데이터 바인딩

옵션 B 기준, 본 화면은 M-08과 한 흐름. 데이터 바인딩은 §8 참조.

## 8. M-08: 서명 화면

### 8.1 화면 구성

```
┌──────────────────────────────────┐
│  ← 교육 종료 - 서명               │
├──────────────────────────────────┤
│                                  │
│  ✓ 종료 비밀번호 확인됨            │
│                                  │
│  📝 서명해주세요                  │
│                                  │
│  ┌──────────────────────────┐   │
│  │                          │   │
│  │                          │   │
│  │     [서명 캔버스]          │   │
│  │                          │   │
│  │                          │   │
│  └──────────────────────────┘   │
│                                  │
│  [지우기]            [완료]      │
│                                  │
│  ⓘ 서명은 교육 이수 증빙으로      │
│     영구 보관됩니다.              │
└──────────────────────────────────┘
```

### 8.2 서명 캔버스

- **라이브러리**: signature_pad (HTML5) 또는 Flutter signature 패키지
- 화면 가로 모드 권장 (서명 공간 넓힘)
- **선 굵기**: 적절히 조정 (모바일에선 약간 굵게)
- **빈 서명 차단**: 캔버스에 그린 흔적이 없으면 "완료" 버튼 비활성

### 8.3 "완료" 동작

```
1. 캔버스를 PNG로 변환 (toDataURL 또는 toBlob)
2. multipart/form-data 구성:
   - exitPwd: M-07에서 입력한 비번
   - signatureFile: PNG 파일
3. POST /api/app/tbm/sessions/{no}/exit
4. 성공 시:
   - 토스트 "교육이 완료되었습니다"
   - M-10 (완료 탭)으로 이동
   - 출결 정보 갱신
5. 실패 시 에러 메시지 표시
```

### 8.4 서명 가이드 안내

- 화면 상단에 본인 서명 안내
- (Phase 2) 외국인 노동자 대상 다국어

### 8.5 데이터 바인딩

**호출:** `POST /api/app/tbm/sessions/{eduSessionNo}/exit` (`04_BACKEND_SPEC_APP.md §7.1`)

multipart/form-data:
```
exitPwd: "654321"
signatureFile: <binary PNG>
```

응답:
```json
{
    "attendanceNo": 1001,
    "exitAt": "2026-05-01T08:15:00",
    "completionStatusCd": "COMPLETED"
}
```

### 8.6 사용성 요구사항

- **자동 회전**: 가로 모드 자동 회전 (서명 편의)
- **실수 방지**: "지우기" 버튼 + 캔버스 초기화 가능
- **포커스**: 캔버스 진입 시 즉시 그리기 가능 (별도 클릭 불필요)
- **터치 정밀도**: stylus 입력 지원 (Apple Pencil 등)

## 14. Claude Code 작업 시 우선 확인 사항

1. **Flutter ↔ Vue WebApp 통신 방식** — postMessage, JS bridge 등
2. **푸시 토큰 발급/관리** — 기존 Prafta 푸시 인프라
3. **카메라/GPS/파일 권한 처리** — Flutter native 측 패턴
4. **서명 캔버스 라이브러리** — Flutter signature vs HTML5 signature_pad
5. **PDF 뷰어** — Flutter pdfx vs PDF.js
6. **오프라인 SQLite** — 이벤트 큐잉용 (선택)
7. **딥링크 처리** — 푸시 알림 → 화면 진입

위 사항 확인 후 차이가 있으면 사용자와 협의.
