## 0.1 ⚠️ 기존 구현과의 모델 차이 (반드시 확인)

**Prafta에 이미 구현된 TBM 교육자료 등록 화면**(스크린샷 기준)은 다음 모델:

```
교육자료 마스터 (1)
  ├ 제목, 카테고리(예: 사고사례자료), 설명
  └ 교육자료 세부항목 (N)
       ├ 자료 타입 (동영상/유튜브 URL/이미지)
       ├ 사용여부, 정렬순서
       ├ 파일 또는 URL
       └ 자료설명
```

본 문서의 **`01_DDL_SPEC.md`는 단일 자료 모델(콘텐츠 1행 = 자료 1개)**로 작성되어 있습니다.

### 매핑 방향 (Claude Code가 결정 / 사용자와 협의)

| 방향 | 설명 | 영향 |
|---|---|---|
| **A. 묶음 모델로 통일 (권장)** | DDL을 `TB_EDU_CONTENT` (묶음 마스터) + `TB_EDU_CONTENT_ITEM` (세부항목) 으로 분리 | 기존 구현 보존, 운영 관점 자연스러움 |
| B. 단일 모델로 변경 | 기존 화면을 단일 자료 단위로 재구성 | 기존 구현 변경 부담 큼 |
| C. 하이브리드 | 묶음 개념 유지 + TBM 첨부는 세부항목 단위 | 복잡도 증가 |

**Claude Code 작업 시:**
- 기존 테이블 구조 확인 (마스터/세부항목 분리 여부)
- 사용자와 매핑 방향 협의
- 본 문서는 **방향 A를 가정**하여 작성됨

방향 A 채택 시 본 문서 §1~§3의 모든 "콘텐츠"는 **"교육자료 묶음 + 세부항목"** 으로 해석합니다.

## 1. W-01: 콘텐츠 라이브러리 목록

### 1.1 화면 구성

```
┌─────────────────────────────────────────────────────────────┐
│  TBM 교육자료 라이브러리                            [+ 등록]  │
├─────────────────────────────────────────────────────────────┤
│  [사업장 ▼] [카테고리 ▼] [미디어 타입 ▼] [검색어] [조회]  │
├─────────────────────────────────────────────────────────────┤
│  ┌────┬──────────┬──────┬──────────┬──────┬─────┬──────┐  │
│  │ NO │ 제목       │ 스코프 │ 카테고리   │ 항목수│ 등록일│ 액션  │  │
│  ├────┼──────────┼──────┼──────────┼──────┼─────┼──────┤  │
│  │ 1  │ 지게차 안전 │ 공통  │ 사고사례  │ 3    │ 5/1 │ ✏️🗑│  │
│  │ 2  │ 추락 방지  │ A공장 │ 일반      │ 2    │ 5/3 │ ✏️🗑│  │
│  └────┴──────────┴──────┴──────────┴──────┴─────┴──────┘  │
│  [< 이전]  1 2 3 4 5  [다음 >]                              │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 컴포넌트 구성

| 영역 | 컴포넌트 | 비고 |
|---|---|---|
| 헤더 | 페이지 타이틀 + "등록" 버튼 | 권한 있는 사용자만 등록 버튼 활성 |
| 필터 | 사업장 / 카테고리 / 미디어 타입 / 검색어 / 조회 버튼 | URL 쿼리 파라미터 동기화 (북마크 가능) |
| 그리드 | Vue3 + Element Plus 또는 기존 Prafta 그리드 컴포넌트 | 정렬, 페이지네이션 |
| 액션 | 행별 수정/삭제 버튼 + 클릭 시 W-03 상세 이동 | 권한 기반 활성/비활성 |

### 1.3 데이터 바인딩 (API)

**호출:** `GET /api/web/tbm/contents` (참조: `03_BACKEND_SPEC_WEB.md §4.1`)

**쿼리 파라미터 매핑:**
- 사업장 필터 → `siteCd` (없으면 자기 사업장 + 회사 공통 모두)
- 카테고리 필터 → 추가 파라미터 `categoryCd` (백엔드 사양 확장 필요)
- 미디어 타입 필터 → `contentTypeCd` (방향 A에선 세부항목 타입이라 묶음 필터엔 안 맞을 수 있음 — Claude Code 검토)
- 검색어 → `searchKeyword`
- 페이지 → `page`, `pageSize`

### 1.4 권한 및 가시성

| 사용자 | 가시 콘텐츠 | 액션 |
|---|---|---|
| master | 전체 회사 콘텐츠 (공통 + 모든 사업장) | 등록·수정·삭제 모두 |
| safe | 전체 회사 콘텐츠 | 등록·수정·삭제 모두 |
| 사업장 관리자 (커스텀 권한) | 회사 공통 + 자기 사업장 | 자기 사업장 콘텐츠만 등록·수정·삭제 |
| 999999 | 접근 불가 | 화면 진입 자체 차단 |

### 1.5 사용성 (UX) 요구사항

- **회사 공통 콘텐츠 시각 구분**: "스코프" 컬럼에 "공통" 배지 (다른 색)
- **카테고리별 색상**: 사고사례자료(빨강), 법정교육자료(파랑), 위험성평가(주황) 등
- **검색 시 디바운싱**: 500ms (불필요한 API 호출 방지)
- **삭제 시 확인 다이얼로그**: "정말 삭제하시겠습니까? 이 콘텐츠를 사용한 TBM 이력은 유지됩니다."
- **소프트 삭제**: `USE_YN = 'N'` 으로 처리, 물리 삭제 X

### 1.6 빈 상태 (Empty State)

검색 결과 없을 때:
```
"등록된 교육자료가 없습니다. [+ 등록] 버튼을 눌러 첫 자료를 등록하세요."
```

권한 없는 경우:
```
"교육자료를 등록할 권한이 없습니다. 안전관리자에게 문의하세요."
```

## 2. W-02: 콘텐츠 등록/수정

### 2.1 화면 구성 (모달 또는 별도 페이지)

본 화면은 **현재 Prafta 구현 화면을 기반**으로 보완 사항을 반영합니다.

```
┌─────────────────────────────────────────────────────────────┐
│  TBM 교육자료 등록                                    [X]   │
├─────────────────────────────────────────────────────────────┤
│  스코프      [○ 회사 공통  ● 사업장]  ⓘ 회사 공통은 safe만 │
│  사업장      [A공장 ▼]                                       │
│  제목 *      [_________________________________________]    │
│  카테고리 *  [사고사례자료 ▼]      사용여부 [사용 ▼]        │
│  설명        [                                          ]   │
│              [                                          ]   │
├─────────────────────────────────────────────────────────────┤
│  세부항목                                          [+ 행 추가]│
│  ┌─┬──┬────────┬──────┬──────┬─────────┬─────────┬────────┐│
│  │ │NO│ 미디어  │ 사용 │ 순서  │ 파일/URL │ 자료설명 │ 미리보기││
│  ├─┼──┼────────┼──────┼──────┼─────────┼─────────┼────────┤│
│  │☐│1 │동영상▼ │사용▼│  1   │[파일선택] │         │  [▶]   ││
│  │☐│2 │유튜브▼ │사용▼│  2   │[URL입력] │         │ [썸네일]││
│  └─┴──┴────────┴──────┴──────┴─────────┴─────────┴────────┘│
│                                                             │
│       [선택 행 삭제]  [초기화]  [저장]  [닫기]              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 보완 적용 사항 (현재 구현 대비)

| 보완 # | 항목 | 변경 |
|---|---|---|
| 1 | **스코프 선택** | 회사 공통 vs 사업장 라디오. 회사 공통 선택 시 권한 체크 (master/safe만) |
| 2 | **카테고리 vs 미디어 타입 명확화** | 마스터 = "카테고리" (사고사례자료 등), 세부항목 = "미디어 타입" (동영상 등) |
| 3 | **미디어 타입별 입력 활성/비활성** | 동영상/이미지/PDF → 파일 활성, URL 비활성. 유튜브 → URL 활성, 파일 비활성 |
| 4 | **정렬순서** | 드래그 앤 드롭 지원 (대안: ↑↓ 화살표). 직접 입력은 보조 |
| 5 | **파일 썸네일** | 동영상/이미지/PDF 등록 시 자동 썸네일 생성 + 미리보기 컬럼 표시 |
| 6 | **버튼 명확화** | "추가" → "행 추가", "삭제" → "선택 행 삭제", "저장" + "닫기" 분리 |

### 2.3 필드 정의

#### 마스터 영역

| 필드 | 타입 | 필수 | 검증 / 옵션 |
|---|---|---|---|
| `스코프` | 라디오 | Y | 회사 공통 / 사업장 |
| `사업장` | 셀렉트 | 사업장 선택 시 Y | 자기 회사의 사업장 목록 (외부 API) |
| `제목` | 텍스트 | Y | 최대 200자, 좌우 공백 trim |
| `카테고리` | 셀렉트 | Y | 시스템 코드 그룹 (예: `SYS_TBM_CONTENT_CAT`) |
| `사용여부` | 셀렉트 | Y | 사용(Y) / 미사용(N), 기본 Y |
| `설명` | 텍스트영역 | N | 최대 1000자 |

⚠️ "카테고리" 시스템 코드 그룹은 본 문서가 신규 제안. 기존에 있으면 그것 사용, 없으면 추가.

#### 세부항목 영역

| 필드 | 타입 | 필수 | 검증 |
|---|---|---|---|
| `체크박스` | 체크 | - | 다중 선택용 |
| `미디어 타입` | 셀렉트 | Y | VIDEO / YOUTUBE / IMAGE / PDF |
| `사용여부` | 셀렉트 | Y | Y / N |
| `정렬순서` | 숫자 | Y | 자동 계산 (드래그 시 갱신) |
| `파일` | 파일 업로드 | 조건부 | VIDEO/IMAGE/PDF 시 필수, 50MB 이내 |
| `URL` | 텍스트 | 조건부 | YOUTUBE 시 필수, URL 형식 검증 |
| `자료설명` | 텍스트 | N | 최대 200자 |
| `미리보기` | 표시용 | - | 썸네일 또는 아이콘 |

**파일 검증 상세:**
- VIDEO: mp4, webm, mov (영상 길이 자동 추출)
- IMAGE: jpg, jpeg, png, webp
- PDF: pdf (1페이지 썸네일 자동 생성)

**YouTube URL 검증:**
- `https://www.youtube.com/watch?v=...`
- `https://youtu.be/...`
- 둘 다 허용, 백엔드에서 표준 형식으로 변환 저장 권장
- YouTube oEmbed API로 썸네일 자동 가져오기 (선택)

### 2.4 데이터 바인딩 (API)

**등록:** `POST /api/web/tbm/contents` (multipart/form-data)
**수정:** `PUT /api/web/tbm/contents/{contentNo}`
**삭제:** `DELETE /api/web/tbm/contents/{contentNo}` (소프트 삭제)

세부항목 일괄 처리 패턴:
- 등록/수정 시 마스터 + 세부항목 전체를 한 번에 전송 (트랜잭션)
- 세부항목 추가/삭제/수정 별도 API 분리도 가능 (Claude Code 결정)

**multipart 요청 구조 예시 (방향 A 기준):**
```
POST /api/web/tbm/contents
Content-Type: multipart/form-data

scopeType: "SITE"           // COMMON 또는 SITE
siteCd: "A001"
title: "지게차 안전수칙"
categoryCd: "ACCIDENT_CASE"
useYn: "Y"
description: "라인 작업 시 필수 시청"
items[0].mediaTypeCd: "VIDEO"
items[0].useYn: "Y"
items[0].displayOrder: 1
items[0].description: "사고 영상"
items[0].file: <binary>
items[1].mediaTypeCd: "YOUTUBE"
items[1].useYn: "Y"
items[1].displayOrder: 2
items[1].description: "안전 교육 영상"
items[1].externalUrl: "https://www.youtube.com/watch?v=..."
```

### 2.5 저장 시 검증 로직 (프론트엔드)

```
1. 마스터 필드 필수값 검증 (제목, 카테고리, 스코프)
2. 스코프 = 공통 + 사용자 권한 < safe → 차단 ("권한이 없습니다")
3. 세부항목 최소 1개 존재 확인
4. 각 세부항목별:
   - 미디어 타입 ≠ YOUTUBE 인데 파일 없음 → 에러
   - 미디어 타입 = YOUTUBE 인데 URL 없음 또는 형식 오류 → 에러
   - 정렬순서 중복 자동 정렬 (드래그 결과 반영)
5. 저장 API 호출
6. 성공 시 토스트 + 목록 갱신
7. 실패 시 에러 메시지 표시 (백엔드 ApiException 메시지)
```

### 2.6 사용성 요구사항

- **자동 저장 알림**: 작성 중 페이지 이탈 시 "저장하지 않은 변경사항이 있습니다" 확인
- **파일 업로드 진행률**: 큰 영상 업로드 시 progress bar
- **드래그 앤 드롭 영역**: 파일 드래그로 업로드 가능
- **유튜브 URL 입력 시 자동 썸네일**: oEmbed API 호출
- **저장 후 동작 선택**: "저장 후 닫기" / "저장 후 계속 편집"

### 2.7 수정 모드 차이

| 항목 | 등록 모드 | 수정 모드 |
|---|---|---|
| 스코프 변경 | 자유 | **변경 불가** (혼란 방지) |
| 카테고리 변경 | 자유 | 자유 |
| 세부항목 추가/삭제 | 자유 | 자유 (단 기존 파일은 보존) |
| 사용여부 변경 | 자유 | 자유 (소프트 삭제 대체 가능) |

│  │ • 5월 1주차 TBM - 5/1 08:00 (참여 30명, 이수 28명)   │ │
│  │ • 4월 4주차 TBM - 4/29 08:00 (참여 28명, 이수 28명) │ │
│  │ [더 보기]                                              │ │
│  └──────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 데이터 바인딩

**호출:** `GET /api/web/tbm/contents/{contentNo}` (참조: `03_BACKEND_SPEC_WEB.md §4.2`)

응답:
- 콘텐츠 마스터 + 세부항목 전체
- 사용 이력 (최근 N건, 더보기로 페이징)

### 3.3 미디어 미리보기

| 미디어 타입 | 미리보기 동작 |
|---|---|
| VIDEO | 인라인 HTML5 video player, controls 표시 |
| YOUTUBE | YouTube iframe embed |
| IMAGE | 라이트박스 (클릭 시 확대) |
| PDF | PDF.js 인라인 뷰어 또는 새 탭 |

⚠️ 모든 미리보기는 **본인 회사·사업장 권한 범위 내**에서만 가능. 백엔드 권한 체크 필수.

### 3.4 사용 이력 영역

각 항목 클릭 시 해당 TBM 세션 상세(`W-13`)로 이동.

기존 Prafta Vue 컴포넌트 컨벤션 따라 작성. 권장 구조:

```
src/views/tbm/
├── content/

│   ├── ContentEditView.vue              # W-02 (모달 또는 페이지)

## 6. Claude Code 작업 시 우선 확인 사항

1. **기존 TBM 교육자료 테이블 구조** — 마스터/세부항목 분리 여부, 컬럼명, FK
2. **기존 카테고리 시스템 코드** — 사고사례자료 등이 어디 정의되어 있는지
3. **파일 업로드 기존 서비스** — 경로, MIME 검증, 썸네일 생성 유틸 유무
4. **기존 그리드 컴포넌트** — 사용 중인 라이브러리 (Element Plus, AG Grid, 자체 등)
5. **드래그 앤 드롭 라이브러리** — vuedraggable 등 기존에 쓰는 게 있는지
6. **유튜브 oEmbed 또는 썸네일 추출 정책** — 외부 API 호출 허용 여부

위 6개 확인 후, **차이가 있으면 사용자와 협의** 후 진행.
