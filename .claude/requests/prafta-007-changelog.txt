- 버그: 초과근무를 여러 번 입력하면 같은 시간대여도 계속 INSERT됨(중복).
  재현 — OT 2건 저장 → 팝업 재오픈 → 화면에서만 OT 삭제 → 신규 OT 재입력 → 또 INSERT.
- 수정: 초과근무 생성 API 호출 시 TB_USER_OVERTIME_MGMT를 ATTD_ID 기준으로 같은
  시간대 데이터 존재 여부 체크 → 없을 때만 INSERT.

2. 사용자 컨펌 사항 (요청서 21번 줄 "모호하면 질문" 지시 이행)
================================================================================
- P-1 "같은 시간대" 정의 → 시간 구간 겹침(overlap).
- P-2 중복 시 처리 → 전체 거부(에러).
- P-3 중복 판정 행 범위 → 활성 행만(DEL_YN='N' AND OT_STATUS<>'CANCELLED').
       취소/삭제 OT는 재등록을 막지 않음.
- P-4 ATTD_ID NULL 케이스 → 이 화면은 항상 ATTD_ID 보유 → ATTD_ID 기준으로만 구현.
- P-5 화면 삭제↔DB 삭제 → 이번 범위는 INSERT 중복 방지에 한정. 화면에서 지운 OT의
       DB soft-delete 동기화는 별도 작업.

3. 변경 내용 (백엔드만)
================================================================================
[prafta-009-001] 초과근무 중복 INSERT 방지

■ 버그 원인
  Attd07ServiceImpl.updateUserOvertimeRequests의 INSERT 루프가 요청된 모든 OT 구간을
  DB 기존 행 대조 없이 무조건 insertUserOvertime → 같은 OT 재저장 시 중복 INSERT.

■ 변경 파일 (4개, 모두 수정)
  - prafta-backend/.../web/attd/attd07/mapper/Attd07Mapper.java
      신규 selectOverlappingOvertimeCount(cmpnyCd,siteCd,userCd,attdId,reqStart,reqEnd).
  - prafta-backend/.../resources/com/prafta/web/attd/attd07/mapper/Attd07Mapper.xml
      신규 <select id="selectOverlappingOvertimeCount"> — ATTD_ID 기준 기존 활성 OT와
      시간 구간 겹침 COUNT. 표준 겹침식 `기존시작 < 요청종료 AND 요청시작 < 기존종료`.
      시각은 ACTUAL_START_DATE(8)+ACTUAL_START_TIME(4) CONCAT 12자리 문자열 비교.
      WHERE: CMPNY_CD→SITE_CD→USER_CD→ATTD_ID→시간대→DEL_YN='N'/OT_STATUS<>'CANCELLED'.
      전부 #{} 바인딩, SELECT * 미사용.
  - prafta-backend/.../web/attd/attd07/service/impl/Attd07ServiceImpl.java
      INSERT 루프 진입 전(단계 6-1)에 요청 OT 전 구간을 겹침 검사. 하나라도 겹치면
      ApiException(ATTD_409_002) throw → 전체 거부(부분 INSERT 원천 차단). 메서드는
      이미 @Transactional.
  - prafta-backend/.../common/error/attd/AttdErrorCode.java
      신규 ATTD_409_002 (HTTP 409 CONFLICT, "이미 등록된 시간대의 초과근무가
      존재합니다. 시간이 겹치지 않도록 입력해 주세요.").

■ 설계 메모
  - ACTUAL_END_DATE/TIME이 NULL인 기존 행(진행중 OT 등)은 유한 구간 겹침 판정이
    불가능해 검사 대상에서 제외. 본 endpoint가 INSERT하는 행은 ACTUAL_* 4개를 모두
    채우므로 재현 시나리오 차단에는 영향 없음.
  - 프론트 미변경: AttdDayDetailPop.vue fnApproveOvertime catch가 보안정책 SEC-013
    (백엔드 응답 메시지 직접 노출 금지)으로 OT 저장 에러를 일반 메시지로 일괄 처리.
    developer가 SEC-013 단독 변경을 피해 미변경. 요청서에 명시적 "고지 문구" 요구가
    없어 요구사항 충족에는 문제 없음(섹션 5 참조).

  사용자 확정 "활성 행" 정의(DEL_YN='N' AND OT_STATUS<>'CANCELLED')에 IN_PROGRESS
  처리가 없어 범위 밖. IN_PROGRESS도 겹침 차단 대상이어야 한다면 정책 재정의 필요.
