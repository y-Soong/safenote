# Attd_05.vue 근무계획 저장 구조 개선 — "변경된 셀만 저장(dirty 저장)" 요청의 건

## 1. 배경

근무계획관리(Attd_05) 화면에서 셀 하나의 근무타입만 바꿔도 저장 시 다량의 데이터가 저장되는 문제가 있었다.

- 직전 핫픽스(이번 세션에서 working tree 에 이미 적용됨)로 **조회/저장 범위를 "조회월 + 조회부서 사용자"로 제한**하여, 한 사용자 한 달 기준 최대 ~30건으로 축소됨.
  - 백엔드 `Attd05Mapper.selectSchedList` : 노드트리 + 하위포함/사용자명 + 조회월(`WORK_YMD LIKE`) 스코프 추가
  - 프론트 `Attd_05.vue / fnSave` : 체크된 사용자라도 조회월 셀만 전송하도록 필터 추가
- 그러나 여전히 **"조회월 그리드 전체를 재저장"** 하는 구조다(실제로 바꾸지 않은 셀도 함께 upsert).

이번 작업은 그 위에서, **실제로 변경된 셀(추가/수정/삭제)만 저장**하도록 개선하는 것이 목표다.

## 2. 목표 (요구사항)

1. 사용자가 이번 세션(조회 이후)에 **실제로 값이 바뀐 셀만** 저장 대상으로 전송한다.
   - 신규 지정(빈 셀 → 근무타입/연차), 값 변경(A타입 → B타입), **셀 비우기(값 있던 셀 → 빈 값)** 를 "변경"으로 본다.
   - **동일 값으로 재지정**(baseline 과 같은 값)은 변경으로 보지 않으며 전송하지 않는다. (결정 3)
2. 저장 범위는 **(변경된 셀) AND (해당 row 가 체크됨) AND (조회월)** 의 교집합이다. (결정 2)
   - 기존 "셀 값이 하나라도 바뀌면 그 row 자동 체크" 로직은 유지한다.
   - 예) 한 row 에서 5개 셀을 수정했고 그 row 가 체크되어 있으면, 그 **5개 셀(해당 날짜)만** 저장된다.
3. 변경분(업서트/삭제 통틀어)이 하나도 없으면 저장 API 를 호출하지 않고 "변경된 내용이 없습니다" 류 안내만 노출한다.
4. 저장 성공 후에는 재조회로 기준값(baseline)을 갱신하여, 직후 다시 저장해도 0건이 되도록 한다.

## 2-1. 셀 비우기 기능 (신규, 결정 1)

근무계획 화면은 현재 셀에 값을 "적용"만 가능하고 개별 셀을 다시 비우는 수단이 없다. 본 작업에서 셀 비우기를 신규 도입한다.

- **UX(확정 기본안)**: 툴바에 "지우기" 버튼을 추가하여, 드래그로 선택한 영역의 셀 값을 빈 값으로 만든다(기존 "적용" 버튼과 동일한 선택→실행 패턴). 비운 셀도 변경분이며 해당 row 는 체크된다.
- **저장 처리**: 비워진(baseline 엔 값이 있었으나 현재 빈) 셀은 저장 시 **삭제 대상**으로 전송한다.
- **백엔드 삭제 단위**: 기존 `delete-user-work-plans` 는 사용자+월 단위 삭제다. 본 작업은 **셀(사용자+근무일) 단위 삭제**가 필요하므로, 단건 삭제 경로를 신설하거나 기존 API 를 셀 단위로 확장한다(planner/developer 확정).
- **연차 셀 비우기 시 차감 복원(필수 정합성 요건)**: 비우는 셀이 법정연차(직접 차감으로 기록된 셀)였다면, 삭제와 함께 해당 직접 연차 사용 기록을 **취소/복원(차감 롤백)** 해야 한다. (저장 시 차감했던 `recordDirectLeaveUsage` 의 역연산. 관련 취소 API/로직은 leaveflow 영역에서 확인하여 연계.)

## 3. 현행 동작 (참고)

- `fnSearch` 가 서버 응답(`schedResultList`)을 `scheduleData`(`{ "${userCd}_${workYmd}": workPlanCd }`)에 적재.
- `fnApplySchType` / `fnApplyLeaveType` 가 드래그 선택 영역의 셀 값을 `scheduleData` 에 덮어쓰고, 해당 사용자를 `checkedRows` 에 자동 체크.
- `fnSave` 가 `scheduleData` 전체에서 (체크된 사용자 + 조회월) 셀을 모아 그대로 백엔드로 전송 → 변경 여부와 무관하게 재저장.
- 백엔드 `saveUserWorkPlans` 는 전송된 건마다 `TB_USER_WORK_PLAN` upsert(`ON DUPLICATE KEY UPDATE`). 법정연차 셀은 저장 시 `leaveFlowService.recordDirectLeaveUsage` 로 연차 차감.

## 4. 기대 효과

- 저장 건수/네트워크/DB 쓰기 최소화.
- **법정연차 셀 중복 차감 위험 제거** — 기존엔 조회월 내 기존 연차 셀까지 재전송되어 `recordDirectLeaveUsage` 가 불필요하게 반복 호출될 수 있었다(멱등키로 방어되더라도 호출 자체가 낭비/위험). dirty 저장 시 신규 적용된 연차 셀만 차감 로직을 탄다.
- `UPDATE_DATE`/`UPDATE_NO` 가 변경 셀에만 기록되어 감사 추적이 정확해진다.

## 5. 구현 방향(가이드 — planner/developer 가 확정)

- 조회 시점에 원본 스냅샷(baseline)을 별도 보관(`scheduleDataOrigin` 등 깊은 복사).
- 저장 시 `scheduleData` 와 baseline 을 비교해 **변경된 키만** 추출하여 전송.
- 저장 성공 → `fnSearch` 재조회로 baseline 자연 갱신(현재도 저장 후 `fnSearch` 호출함).
- 업서트(추가/변경) 전송분은 기존 `save-user-work-plans` API/매퍼 재사용 가능(전송 건수만 감소).
- 비우기(삭제) 전송분은 **셀 단위 삭제 경로**가 필요하다(2-1 참조). 단건 삭제 API 신설 또는 기존 `delete-user-work-plans` 셀 단위 확장 + 연차 차감 복원 연계.

## 6. 결정 사항 (확정)

1. **셀 비우기 지원** → 지원한다(2-1 참조). 툴바 "지우기" 버튼 + 드래그 선택 영역 비우기, 저장 시 셀 단위 삭제, 연차 셀은 차감 복원.
2. **체크박스(`checkedRows`) 의미 유지** → 기존 "값 변경 시 자동 체크" 로직 유지. 저장은 **변경 + 체크 + 조회월** 교집합. 체크 해제된 row 의 변경분은 저장하지 않는다.
3. **동일 값 재지정** → 변경으로 보지 않음(no-op). 해당 셀은 전송 제외하며, 전체가 no-op 이면 API 미호출.

## 7. 영향 범위 / 정책 출처

- 주 변경: `PRAFTA/prafta-web-frontend/.../src/views/attd/Attd_05.vue` (프론트 중심).
- 조건부 변경: 삭제 도입 시 `Attd05` 백엔드(controller/service/mapper) 일부.
- 정책서: 근태관리 정책서 — 근무계획(근무타입/연차 적용) 관련 섹션을 planner 가 INDEX 경유로 확인하여 출처 명시.
- 선행 전제: 직전 Attd_05 조회/저장 스코프 핫픽스가 적용된 상태(같은 working tree).

## 8. 수용 기준 (AC)

1. 조회 후 한 셀의 근무타입만 변경하고 저장 → **1건** 저장(서버 savedCount=1), 그 외 셀 미변경.
2. 한 row 에서 5개 셀 변경(해당 row 체크됨) 후 저장 → 그 **5개 셀(해당 날짜)만** 저장.
3. 변경 없이 저장 버튼 → 저장/삭제 API 미호출 + "변경된 내용이 없습니다" 안내.
4. **동일 값으로 재지정**한 셀만 있는 경우 → 변경 없음으로 간주, API 미호출.
5. 빈 셀에 법정 본연차 1건 신규 적용 후 저장 → 연차 사용 **1건만** 기록/차감(기존 연차 셀 재차감 없음).
6. 저장 직후 동일 화면에서 다시 저장 → **0건**(baseline 갱신 확인).
7. 체크되지 않은(또는 변경되지 않은) 다른 사용자/셀의 근무계획은 저장되지 않음.
8. **셀 비우기**: 값이 있던 셀을 "지우기"로 비우고 저장 → 해당 셀(사용자+근무일)이 `TB_USER_WORK_PLAN` 에서 삭제됨.
9. **연차 셀 비우기**: 법정연차가 적용돼 있던 셀을 비우고 저장 → 셀 삭제 + 해당 직접 연차 사용 기록 취소(차감 복원)되어 잔여 연차가 원복됨.
