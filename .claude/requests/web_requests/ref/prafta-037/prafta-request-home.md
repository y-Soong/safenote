## 1. 개요

### 1.1 배경
PRAFTA 모바일 앱의 **메인 홈 화면(랜딩)**을 신규로 구축한다. 사용자가 앱을 열었을 때 가장 먼저 보는 화면으로, **출퇴근 등록 / 본인 근태 요약 / 안전 활동 진입 / TBM 참석 / 공지사항 확인**의 5가지 핵심 액션을 단일 스크롤 화면에서 제공한다.

핵심 설계 원칙:
- **출퇴근 카드 최상단 고정**: 가장 빈번한 1일 1~2회 액션을 즉시 노출
- **차단 상태 명확화**: 출근 전에는 안전 활동·TBM 참석이 차단됨을 시각적으로 표시 (산업안전 정책서 §3 근거 — planner 매핑 필요)
- **카드 구조 일관성**: 5개 카드 모두 동일한 영역 위치·크기를 유지하고, **상태값과 활성·비활성만** 케이스별로 변경한다. 빈 상태가 발생해도 카드 영역과 버튼 위치는 절대 변하지 않는다.
- **사업장 컨텍스트 고정 표시**: 사용자는 소속 사업장만 사용 가능. 헤더는 현재 소속 사업장을 정적으로 표시하며 전환 기능 없음.

### 1.2 화면 위치
- **앱 네비게이션**: 하단 탭바 "홈" 탭 (앱 진입 시 기본 활성 탭)
- **파일 위치**: `prafta-web-frontend/src/views/home/HomeView.vue`

### 1.3 화면 구성 (단일 스크롤)
상단부터 다음 순서:
1. **헤더** — 좌측: 사업장명 + "소속" 배지(정적 표시) / 우측: 알림 아이콘 + 프로필 아바타
2. **인사말** — 날짜 + "오늘도 좋은 하루 되세요"
3. **출퇴근 카드** — 상태 배지 + 시간 텍스트 / 출근하기·퇴근하기 버튼 / 위치 표시
4. **근태 조회 카드** — 잔여 연차 + 승인 요청 2분할 KPI / 우상단 > 진입
5. **안전 활동 카드** — 안전점검 시작 + 위험성 발굴 2분할 / 우상단 > 진입
6. **TBM 참석 카드** — 메타 + 콜아웃 + 참석하기 버튼 / 우상단 > 진입
7. **공지사항 카드** — 제목 리스트 (최대 3행) / 우상단 > 진입
8. **하단 탭바** — 홈(활성) / 근태 / 안전 / TBM / 마이 5탭

### 1.4 시안 파일
구체적 UI는 `prafta_home_variations.html` 참조. 총 4개 케이스를 담고 있다:
1. **출근 전 · 안전/TBM 차단**
2. **근무중** — 사업장 내 정상 출근, TBM 참석 가능
3. **근무중 · 사업장 외 · TBM 참석 완료** — 외근 시점 + 오전 TBM 이미 완료
4. **근무중 · TBM 없는 날**

## 2. 카드 구조 일관성 원칙

### 2.1 모든 카드의 고정 영역

각 카드는 케이스와 무관하게 **동일한 영역과 버튼 위치**를 유지한다. 빈 상태·차단 상태·완료 상태 모두 카드 골격은 같고, 상태값(배지·콜아웃·아이콘)과 활성·비활성만 다르다.

| 카드 | 고정 구조 |
|---|---|
| **출퇴근** | (1) 상태 배지 + 시간 텍스트 / (2) 출근하기·퇴근하기 2분할 버튼 / (3) 하단 위치 표시 |
| **근태 조회** | (1) 타이틀 + 우상단 > 진입 / (2) 잔여 연차·승인 요청 2분할 KPI |
| **안전 활동** | (1) 타이틀 + 우상단 > 진입 / (2) (선택) 차단 배너 / (3) 안전점검·위험성 발굴 2분할 버튼 |
| **TBM 참석** | (1) 타이틀 + 우상단 > 진입 / (2) 메타 1행 / (3) 콜아웃 박스 / (4) 참석하기 버튼 |
| **공지사항** | (1) 타이틀 + 미열람 카운트 + 우상단 > 진입 / (2) 공지 리스트 (최대 3행) |

### 2.2 우상단 진입 패턴 (chevron-only)

근태 조회 / 안전 활동 / TBM 참석 / 공지사항 카드의 우상단 진입 버튼은 모두 **텍스트 없이 chevron(>) 아이콘 버튼만** 노출한다. 시안의 `head-chev` 클래스 참조. 동일한 패턴으로 통일하여 시각적 일관성을 유지한다.

- 아이콘 크기: 18×18px
- 컬러: `--color-text-tertiary` (#9CA3AF)
- 터치 영역: 최소 44×44px 보장 (시각 크기는 작아도 hit area 확장)
- aria-label: "자세히 보기" 또는 "전체보기"

## 3. 비즈니스 규칙 (정책서 출처 명시)

### 3.1 헤더 — 사업장 표시 정책

- 사용자는 **본인의 소속 사업장만 사용 가능**. 타 사업장 전환 기능 없음.
- 헤더 좌측은 정적 표시: 위치 아이콘 + 사업장명 + "소속" 배지
- 드롭다운·셀렉터·바텀시트 호출 없음

**[정책서 매핑 필요]** 공통 정책서 §7~§8(조직 관리) 또는 사업장 권한 정책에서 "사용자 앱은 소속 사업장만 사용"이라는 명시적 조항이 있는지 planner가 확인. 없으면 본 작업으로 정책 신설.

### 3.2 출퇴근 카드 — 5개 영역과 상태 매트릭스

#### 3.2.1 5개 영역 (고정)

| # | 영역 | 위치 |
|---|---|---|
| 1 | 상태 배지 | 카드 좌상단 |
| 2 | 시간 텍스트 | 상태 배지 우측 (같은 행) |
| 3 | 출근하기 버튼 | 카드 중앙 좌측 |
| 4 | 퇴근하기 버튼 | 카드 중앙 우측 |
| 5 | 하단 위치 표시 | 카드 하단 |

#### 3.2.2 케이스별 상태 매트릭스

| 영역 | 케이스 1 (출근 전) | 케이스 2 (근무중) | 케이스 3 (사업장 외) |
|---|---|---|---|
| 상태 배지 | "출근 전" Info Blue | "근무중" Primary Green | "근무중" Primary Green |
| 시간 텍스트 | "예정 09:30 ~ 18:00" tertiary | "출근 09:28" secondary | "출근 09:28" secondary |
| 출근하기 | **Primary 활성** | 비활성 | 비활성 |
| 퇴근하기 | 비활성 | **Primary 활성** | **Primary 활성** |
| 위치 표시 | "-" Neutral 톤 + 회색 아이콘 | "{사업장명}" Neutral 톤 + Primary 아이콘 | "사업장 외" Warning tint + Warning 아이콘 |

**케이스 1 == 퇴근 완료 후 동일**: 퇴근 처리 후에는 케이스 1 상태로 복귀하여 재출근이 가능하다. 정책서 §5.2 재출근 조건 근거.

#### 3.2.3 출근/퇴근 액션 시 확인 모달

산업안전 공통 정책서 §13.3에 따라 출퇴근 액션은 확인 모달을 거친다.

| 액션 | 모달 | 비고 |
|---|---|---|
| 사업장 내 출근 | 단순 확인 모달 ("사업장 위치에서 출근할까요?") | 가이드 §4.9.1 |
| 사업장 외 출근 | **[정책 확정 필요]** 지도 모달 또는 단순 확인 — 7.1 질문 사항 참조 |
| 사업장 내 퇴근 | 단순 확인 모달 (또는 모달 생략) — **[정책 확정 필요]** 7.2 질문 사항 참조 |
| 사업장 외 퇴근 | 지도 카드 포함 모달 ("현장 외 퇴근") | 가이드 §5.1.2 |

#### 3.2.4 시간 텍스트 표기 규칙

- **출근 전**: `예정 {시작} ~ {종료}` (예: `예정 09:30 ~ 18:00`). 컬러 tertiary
- **근무중**: `출근 {HH:MM}` (예: `출근 09:28`). 컬러 secondary
- 2구간 스케줄 처리는 본 작업 범위 외. **[정책 확정 필요]** — 7.3 질문 사항 참조

#### 3.2.5 위치 표시 규칙

- **출근 전**: `-` (위치 미사용 상태)
- **근무중 + 사업장 내**: 사업장명 표시 (예: `중곡사업장`)
- **근무중 + 사업장 외**: `사업장 외` Warning 톤

근태관리 정책서 §7.2 GPS 지오펜스 판정 결과를 따른다. **[정책 확정 필요]** §7.3 GPS 미확인 케이스의 위치 표시 처리 — 7.4 질문 사항 참조.

### 3.3 근태 조회 카드 — 2분할 KPI

#### 3.3.1 잔여 연차

- **표시 기준**: 이번 연도 기준 (1/1 ~ 12/31)
- **수치 형식**: `{잔여} / {총 부여}일` (예: `12 / 20일`)
- **데이터 소스**: `tb_user_leave_grant` (이번 연도 부여 총합) - `tb_user_leave_use` (이번 연도 사용 총합)
- **법정/법정 외 분류**: 메인 화면에서는 통합 잔여만 노출. 세부 분류는 진입 후 연차 신청 폼에서 표시 (`prafta-request-attendance-forms.md` §3.4.1 참조)
- **클릭 시**: 연차 신청 바텀시트 호출 (`AttdLeaveForm.vue`)

#### 3.3.2 승인 요청

- **표시 기준**: 본인이 등록한 요청 중 **`REQ_STATUS = 'REQUESTED'`(처리 대기)** 상태의 건수만 표시
- **승인 완료·반려 건은 표시하지 않음** (메인 화면은 "지금 처리되어야 할 것"만 노출). 결과 확인은 알림 센터에서 처리.
- **수치 형식**: `{N} 건 대기` (수치는 warn 컬러, "건 대기"는 tertiary)
- **데이터 소스**: `tb_user_attd_req` (USER_CD 일치 + REQ_STATUS = 'REQUESTED')
- **클릭 시**: 본인 요청 목록 화면으로 이동 (별도 화면, 본 작업 범위 외)

#### 3.3.3 우상단 > 진입

- "오늘 근태" 텍스트 없이 chevron만
- 진입 시: 근태 탭의 "오늘" 화면으로 이동 (`prafta-request-my-attendance.md` §4.2 참조)

### 3.4 안전 활동 카드 — 차단 정책

#### 3.4.1 활성·차단 조건

| 사용자 상태 | 안전점검 시작 | 위험성 발굴 |
|---|:---:|:---:|
| 출근 전 | 차단 | 차단 |
| 근무중 (사업장 내) | 활성 | 활성 |
| 근무중 (사업장 외) | 활성 | 활성 |
| 퇴근 완료 | **[정책 확정 필요]** — 7.5 질문 사항 참조 | **[정책 확정 필요]** |

**근거**: 산업안전 정책서 §3 "안전 기능은 소속 현장 출근 후에만 사용 가능". 차단 시 카드 상단에 잠금 배너 노출:

> 🔒 출근 후에 이용할 수 있어요

#### 3.4.2 안전점검 시작

- 사용자별로 할당된 점검 개소 없음. 사업장에 출근한 모든 근로자가 사용 가능
- 진입 시: 점검 개소 리스트 화면 (별도 작업)
- 산업안전 정책서 §5.4 안전점검 흐름

#### 3.4.3 위험성 발굴

- 사용자가 현장에서 발견한 위험 요소를 사진 + 텍스트로 즉시 등록
- 진입 시: 카메라 → 사진 촬영 → 텍스트 입력 → 등록 (별도 작업)
- 산업안전 정책서 §4 위험성평가 또는 별도 위험성 발굴 정책 — **[정책서 매핑 필요]**

#### 3.4.4 우상단 > 진입

- 진입 시: 본인이 여태 올린 안전점검 체크리스트 활동 + 위험성 발굴 건 통합 이력 화면 (별도 작업)

### 3.5 TBM 참석 카드 — 4가지 상태

#### 3.5.1 4가지 상태와 표시

| 상태 | 메타 | 콜아웃 | 참석하기 버튼 |
|---|---|---|---|
| **출근 전 (차단)** | 10:00 · 1구역 회의실 · 안전팀 박과장 | 🔒 출근 후 참석 가능 (Neutral) | 비활성 |
| **참석 가능** | 10:00 · 1구역 회의실 · 안전팀 박과장 | 🕐 늦지 않게 참석해 주세요 (Warning) | **Secondary 활성** |
| **참석 완료** | 10:00 · 1구역 회의실 · 안전팀 박과장 | ✓ {참석 시각} 참석 완료 (Success) | 비활성 |
| **TBM 없음** | "예정된 TBM이 없습니다" tertiary | 📅 오늘은 TBM 일정이 없어요 (Neutral) | 비활성 |

#### 3.5.2 참석 가능 판단

- 오늘 일자에 본인이 참석 대상자로 지정된 TBM 세션이 있고
- 본인이 출근 상태이며
- 아직 참석 처리되지 않은 경우

세션 시간이 임박했거나 지났더라도 참석 처리는 허용한다. **[정책 확정 필요]** 세션 종료 후 사후 참석 허용 여부 — 7.6 질문 사항 참조.

#### 3.5.3 우상단 > 진입

- 진입 시: 본인이 여태 받은 TBM 리스트 표시 (별도 작업)
- 출근 전이라도 chevron은 활성 (과거 이력 조회 가능)

#### 3.5.4 콜아웃 문구 규칙

- Warning 콜아웃의 시작 임박 문구는 **"늦지 않게 참석해 주세요"** 고정. 시안 초기 버전에 있던 "{N}분 후 시작" 같은 동적 카운트다운은 사용하지 않는다.

### 3.6 공지사항 카드 — 리스트형

#### 3.6.1 표시 정책

- 메인 화면에는 **최대 3행**까지 노출. 그 이상은 전체보기 진입 후 표시
- 한 행 = 한 공지의 제목만 (본문 발췌·요약 노출 안 함)
- 정렬: 중요 공지 우선 → 최신순

#### 3.6.2 행 구성 요소

각 행은 좌측부터:
1. **(선택) "중요" 칩** — 중요 공지에만 노출. Warning tint 배경
2. **제목** — 미열람: body-strong / 열람 완료: body, secondary 컬러
3. **시간 메타** — 상대 시간(3시간 전, 어제) 또는 절대 날짜(7일 이상)
4. **(선택) 미열람 점** — Danger Red 6×6 원

#### 3.6.3 미열람 카운트

- 카드 타이틀 우측에 빨간 원형 배지로 미열람 건수 표시
- 0건일 경우 배지 숨김

#### 3.6.4 우상단 > 진입

- 진입 시: 공지사항 전체 리스트 화면 (별도 작업)

### 3.7 인사말 영역

- 좌측 정렬, 2행 구조
- 1행: 날짜 (`YYYY년 M월 D일 (요일)`)
- 2행: **"오늘도 좋은 하루 되세요"** 고정 메시지. 사용자명을 포함하지 않는다 (프로필 아바타에서 식별).

**[검토 필요]** 시간대별·요일별로 메시지를 가변 처리할지 (예: 18시 이후 "오늘 하루도 수고하셨습니다") — 7.7 질문 사항 참조.

### 5.2 POST /api/app/attd/check-in

**용도**: 출근 등록 (확인 모달 확인 후)

```json

  "latitude": 37.5665,
  "longitude": 126.9780,
  "accuracy": 20

```

**처리**: GPS 지오펜스 판정 → `tb_user_attd_mgmt` INSERT (사업장 내/외 판정 결과를 IS_OFFSITE 컬럼에 저장). 근태관리 정책서 §7.2 참조.

### 5.3 POST /api/app/attd/check-out

**용도**: 퇴근 등록

**요청 Body**: §5.2와 동일

- 본 작업 요청서에 명시된 비즈니스 규칙(§3)은 시안 작성 시 검토된 내용이며, planner가 정책서 출처를 작업 로그 "상세 설명"에 명시해야 한다

## 6. DB 구조 검토 및 추가 작업 필요 사항

### 6.1 출퇴근 사업장 외 여부 컬럼

- 현재 `tb_user_attd_mgmt`에 사업장 외 출퇴근을 구분하는 명시적 컬럼이 있는지 확인 필요
- 없다면 `IS_OFFSITE` BOOLEAN 컬럼 신설 검토 (또는 "근무지 외" 태그를 별도 컬럼/플래그로)
- 근태관리 정책서 §7.2의 "근무지 외 태그로 기록" 구현체

### 6.2 TBM 참석 대상자·이력 테이블

- TBM 세션 마스터 (`tb_tbm_session`): 세션 ID / 일자 / 시간 / 장소 / 진행자 / 대상 사업장·부서
- TBM 참석 대상자 (`tb_tbm_target`): 세션 ID / 대상 사용자
- TBM 참석 이력 (`tb_tbm_attendance`): 세션 ID / 사용자 / 참석 시각 / 본인 체크 방식
- 기존 테이블 확인 후 신설 필요 여부 판단 — **[planner 확인 필요]**

### 6.3 공지사항 — 사용자별 읽음 처리

- 공지 마스터 (`tb_notice_mgmt`): 공지 ID / 중요 여부 / 제목 / 본문 / 게시 시각 / 대상 사업장·부서
- 사용자 읽음 이력 (`tb_notice_read`): 공지 ID / 사용자 / 읽은 시각
- 기존 테이블 확인 후 보강 — **[planner 확인 필요]**

### 6.4 위험성 발굴 — 별도 테이블 또는 위험성평가 통합

- 사용자가 현장에서 즉석 등록하는 위험성 발굴 건의 저장 구조
- 산업안전 정책서의 위험성평가(`tb_risk_assessment`)와 별도 도메인인지, 동일 도메인인지 확인 필요
- **[planner 확인 필요]** 산업안전 정책서 §4 매핑

## 8. 비기능 요구사항

### 8.1 디자인 시스템 준수
- 색상/폰트/간격은 모두 CSS 변수만 사용 (하드코딩 금지)
- 디자인 토큰은 PRAFTA 모바일 앱 디자인 가이드 §2 참조
- 모바일 first (360~414px 기준 폭, 시안은 390px 기준)
- 터치 영역 최소 44×44px (디자인 가이드 §7.1 준수)
- 인라인 SVG 아이콘 사용 (CDN 의존 금지 — 작업 지시서 `prafta-request-attendance-forms.md` §8.2 동일 원칙)

### 8.2 성능
- 홈 화면 진입 시 **단일 API 호출** (§5.1 `/api/app/home/summary`)
- 백엔드는 모든 카드 데이터를 한 번에 응답하여 클라이언트 측 다중 호출·로딩 스피너 노출 방지
- 출퇴근·TBM 참석 액션 후에는 해당 카드만 부분 갱신 또는 전체 재호출

### 8.3 접근성
- 색상으로만 정보 전달 금지 (예: 사업장 외 = 위치 톤 + 텍스트 변경 + 아이콘 변경)
- 시간 표시는 `tabular-nums` 적용으로 정렬 일관성
- chevron-only 진입 버튼은 모두 `aria-label` 명시 ("자세히 보기", "전체보기")

### 8.4 에러 처리
- 네트워크 오류 / 401 / 403 / 500 등 표준 패턴 (prafta 기존 화면 패턴 따름)
- GPS 권한 거부 시: 출퇴근 등록은 허용하되 위치 표시는 "GPS 미확인" 처리 — **[7.4 정책 확정 후 반영]**

### 8.5 카드 영역 일관성 원칙 (강제 규칙)
- **모든 카드는 케이스와 무관하게 동일한 영역 위치를 유지한다.**
- 빈 상태가 발생해도 카드 골격(타이틀·진입 버튼·하단 영역)은 유지하고 내용만 빈 상태 메시지로 교체한다.
- 차단 상태에서도 버튼은 동일 위치에 Disabled 상태로 유지한다.
- 위반 시 디자인·개발 합동 리뷰에서 반려 사유에 해당한다.

## 10. 결정 사항 요약 (시안 작성 시점)

본 시안은 사용자와의 다회 이터레이션을 거쳐 확정됨. 주요 결정 사항:

1. **메인 카드 5종 확정**: 출퇴근 / 근태 조회 / 안전 활동 / TBM 참석 / 공지사항. "오늘 할 일" KPI 4분할이나 "빠른 진입" 4분할 등 초기 안은 모두 제거.
2. **사업장 셀렉터 제거**: 사용자는 소속 사업장만 사용. 헤더는 정적 표시.
3. **인사말 단순화**: "안녕하세요, {사용자명}님" → "오늘도 좋은 하루 되세요" 고정. 사용자명은 우상단 아바타에서 식별.
4. **출퇴근 카드 5개 영역 고정**: 어떤 케이스든 5개 영역 위치·크기 불변. 상태값과 활성·비활성만 변경.
5. **케이스 단순화**: 초기 4~5개 케이스(출근 전 / 근무중 / 퇴근 완료 / 사업장 외 / GPS 미확인)에서 **3개로 통합** (출근 전 = 퇴근 후, 근무중, 근무중·사업장 외). 사업장 외는 별도 케이스가 아닌 근무중의 위치 변형.
6. **재출근 허용**: 퇴근 후 출근 버튼 재활성화. 1구간 스케줄 초과 시 초과근무 상신으로 이어짐 (근태 정책서 §5.2).
7. **시간 텍스트 단순화**: 좌우 분할 박스(`출근/퇴근 - -`) 제거. 단일 행으로 "예정 {시간}" 또는 "출근 {HH:MM}".
8. **위치 표시 단순화**: "마지막 갱신 9:40" 같은 부가 텍스트 제거. 표시는 사업장명·"사업장 외"·"-" 3가지로만.
9. **근태 조회 — 잔여 연차 통합 표시**: 법정/법정 외 분류는 메인에서 제거, 신청 폼에서만 분류.
10. **승인 요청 — 대기 건수만**: 반려·승인 건수 표시 제거. 메인은 "지금 처리되어야 할 것"만.
11. **공지사항 — 카드형 → 제목 리스트형**: 모바일 스크롤 부담 감소. 최대 3행.
12. **TBM 카드 — 4가지 상태 통일**: 헤더·메타·콜아웃·버튼 4단 구조 고정. "오늘의 TBM" → "TBM 참석" 타이틀 변경.
13. **TBM 콜아웃 — 동적 카운트다운 제거**: "{N}분 후 시작" → "늦지 않게 참석해 주세요" 고정 문구.
14. **버튼 라벨 변경**: 출근 → "출근하기", 퇴근 → "퇴근하기", TBM 참석하기 → "참석하기".
15. **우상단 진입 일관화**: 4개 카드(근태 조회·안전 활동·TBM 참석·공지사항) 모두 텍스트 없는 chevron(>) 아이콘 버튼으로 통일.
16. **출근 전 차단 명시**: 안전 활동·TBM 참석은 출근 전 사용 불가. 잠금 아이콘 + "출근 후 …" 안내로 시각화.
17. **확인 모달 패턴**: 출퇴근 액션은 확인 모달 거침. 사업장 내 = 단순 모달, 사업장 외 퇴근 = 지도 카드 포함 모달 (가이드 §5.1.2).
