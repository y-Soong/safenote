3 처리 방식 *

기존 부여 유지 + 누락분만 소급 부여 권장

기존에 부여된 연차는 그대로 유지하고, 변경된 입사일 기준으로 본래 받았어야 할 부여 중 누락분만 추가 부여합니다.

처리 동작: 기존 GRANT는 그대로 두고, 누락된 항목만 INSERT (IDEMPOTENCY_KEY로 중복 방지). 이미 발생한 부여 일수의 메타정보는 수정되지 않습니다.

이 케이스 결과: 월차 2일 + 본연차 15일이 신규 부여됩니다.

기존 부여 유지 + 신규 부여만 변경된 입사일로 계산

기존에 부여된 연차는 그대로 두고, 누락분은 추가 부여하지 않습니다. 변경된 입사일 기준의 다음 부여 시점부터 새로 적용됩니다.

처리 동작: TB_USER.HIRE_DATE만 업데이트. 누락된 부여는 무시. 다음 anniversary부터 정상 부여.

이 케이스 결과: 추가 부여 없음 · 다음 부여는 2027-03-01부터.

모든 부여 삭제 후 재계산 위험

기존 부여 기록을 모두 취소 처리하고, 변경된 입사일 기준으로 처음부터 다시 계산합니다. 입사일 입력 오류 정정 시에만 사용하세요.

처리 동작: 기존 GRANT는 STATUS='CANCELED'로 변경 (소프트 삭제, 감사 추적용으로 보존). 새 입사일 기준 GRANT 재발급. 기존 사용 이력(TB_LEAVE_USE)은 보존되며 새 GRANT의 USED_DAYS에 총량으로 합산.

이 케이스 결과: 기존 월차 9건 CANCELED → 월차 11일 + 본연차 15일 재발급.

참고: 이미 부여된 연차의 유효기간(만료일)은 발생일 기준으로 결정되어 보존되며, 입사일 변경 후에도 변경되지 않습니다.
