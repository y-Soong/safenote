## 연차 부여엔진 정밀화 · 자동화 (prafta-022 후속)

> 이 문서는 prafta-022(연차 부여엔진 수정)에서 **의도적으로 범위 밖으로 분리한 후속 작업**을 모아둔 요청서다.
> prafta-022는 보고된 두 버그(handlingType 미반영 / 정책 AXIS1 미반영)와 영향분석 실측화를 "최소 정합 범위"로 처리했고,
> 정밀 계산·정기 자동화·다년도 소급은 검증 부담이 커서 본 문서로 미뤘다.
>
> **착수 시점**: prafta-021 작업이 끝나면 이어서 바로 진행.
> **선행 의존**: prafta-022 작업 A에서 추출하는 공용 부여 엔진 `LeaveGrantEngineService`를 그대로 재사용한다(신규 엔진 만들지 말 것).
> **분해**: 착수 시 planner가 정책서 INDEX(`attd/08-leave.md` §8.5.2~§8.5.8) 경유로 정독 후 단위 작업으로 분해한다.
> **→ 분해 완료(2026-05-24)**: 단위 작업(A~H)·결정 로그·필요 DDL/마이그레이션은 **`prafta-023-plan.md`(마스터)** 참조. 사용자 논의로 **"C"(입사일 수정 처리방식 KEEP_AND_BACKFILL vs KEEP_AND_APPLY_NEW 동작 분기 확립)** 가 본 묶음에 합본되었다.

---

### 1. AXIS3=PRORATE 정밀 비례부여 + AXIS4 반올림 풀 매트릭스

- prafta-022에서는 첫해 방식(AXIS3) 중 `MONTHLY_ONLY`(1년 미만 월차) / `NEXT_YEAR_BULK`(차년도 회계연도 일괄)만 동작한다. `PRORATE`(비례부여)는 미구현(폴백 또는 안내 처리).
- 본 작업: 입사 후 잔여기간 비례 계산 `(잔여일수 ÷ 365) × 본연차일수`를 구현하고, AXIS4 반올림 4종(`CEIL` / `ROUND` / `FLOOR` / `HALF_DAY`)을 적용한다.
- 정책 매트릭스(§8.5.3): AXIS3=`PRORATE`일 때만 AXIS4 입력이 유효하고, 그 외 분기는 AXIS4=`CEIL` 강제. 검증 케이스가 많으므로 단위 테스트로 반올림 경계를 고정한다.
- 산출물: `LeaveGrantEngineServiceImpl`의 첫해 부여 산정 로직 확장 + 비례/반올림 유틸 + 테스트.

### 2. 자동 정기 부여 스케줄러

- 현재(prafta-022 기준)는 Attd_09 "정책 기준 부여" 버튼의 **수동 트리거**만 존재한다. 매년/매월 정책 기준 자동 부여 배치가 없다.
- 본 작업: 일배치 스케줄러가 활성 정책 기준으로 대상 직원에게 본연차/월차/근속가산을 자동 부여한다. `LeaveGrantEngineService`를 재사용한다.
- 멱등키 체계를 정식(§8.5.8 #1)으로 전환: 본연차 `{USER_CD}_{YYYY}_ANNUAL` / 월차 `{USER_CD}_{YYYYMM}_MONTHLY` / 근속가산 `{USER_CD}_{YYYY}_TENURE_BONUS`.
  - ※ prafta-022의 `_HIRE` 접미사 멱등키는 "수동 버튼 적용" 한정이었음. 스케줄러 도입 시 두 경로의 멱등키 충돌/중복 부여가 없도록 키 체계를 정리한다.
- 기존 `LeaveStatusScheduler`(만료 배치, @Scheduled 자정+5분)와 동일한 스케줄 패턴 참조.

### 3. BACKFILL 과거연도 백필 확장 (다년도)

- prafta-022의 `KEEP_AND_BACKFILL`은 당해 연도 누락분 중심으로만 보충한다.
- 본 작업: 입사일을 과거로 크게 당겨 과거 여러 연도분이 누락된 경우, 입사 이후 누락 연도 전체를 루프 백필한다(연도별 멱등키로 중복 차단).
- 기 발생 연차 사후 차감 금지(§8.5.8 #2) 절대 규칙은 그대로 유지.

### 4. EXPIRE_YN deprecation 동기 로직 / 트리거 (검토)

- §8.5.8 #4: STATUS 단일 진실원 전환 후 `EXPIRE_YN` 컬럼 deprecation은 별도 단계 작업으로 남아 있음.
- 본 묶음에 포함할지 착수 시 판단(독립 작업으로 분리 가능).

### 분리 근거 (요약)

위 항목은 모두 "정밀 계산 · 정기 자동화 · 다년도 소급"으로 보고된 버그의 직접 원인이 아니다. prafta-022는 "버그를 막고 정책이 반영되게" 하는 최소 정합 범위로 한정했고, 정밀도/자동화는 별도 검증 사이클(본 문서)로 분리해 prafta-022 착수 지연을 막았다.

상세 설계 근거와 작업표는 `prafta-022-plan.md` §"prafta-023 후속 분리 항목" 및 결정 로그 #8을 참조.
