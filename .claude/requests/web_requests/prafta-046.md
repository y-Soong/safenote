# prafta-046 — 노드–관리자 정합성 가드 ("관리자 없는 노드에 근로자 배정 차단")

> **작업 ID prefix**: `PRAFTA-046`
> **본 문서 위상**: 작업 요청서(분해 전). prafta-app-009 분해(2026-06-04) 중 파생. app-009 의 `'Y'`(자체근태승인) 케이스 전제("노드엔 Main/Sub 관리자가 항상 존재한다")를 **시스템 불변식으로 강제**하기 위한 웹/사용자 관리 영역 보완.
> **작업 영역**: `PRAFTA/prafta-backend` (web/user, common/login) + `prafta-web-frontend` (사용자 생성/수정·회원가입 노드 선택 UI). 모바일 앱 영역 아님.
> **선행 관계**: **본 작업이 prafta-app-009 의 선행**. 본 가드가 있어야 app-009 `'Y'` 케이스에서 승인자(노드 관리자) 부재가 구조적으로 발생하지 않는다.

---

## 0. 배경 — 왜 필요한가

prafta-app-009 에서 근태/OT/스케줄수정 결재를 노드 `tb_site_node.SELF_ATTD_APPRV_YN` 으로 분기하기로 결정(2026-06-04):

- `'Y'`(자체근태승인 ON): 해당 노드의 **Main/Sub 관리자 중 1인이라도 승인하면 완료**(OR 승인). 신청자 본인이 그 노드 Main/Sub 관리자면 **자동 승인**.
- `'N'`: 결재선(다단계) 승인.

이 설계는 **"`'Y'` 노드에는 Main 또는 Sub 관리자가 반드시 존재한다"** 를 전제한다. 그러나 검증 결과(2026-06-04), 이 전제는 **현재 데이터상으로만 참(운영 0건)** 이고 **시스템이 강제하는 불변식이 아니다.** 관리자 0명 + 근로자 ≥1명 노드가 운영자 실수로 생성될 수 있다.

### 0.1 현황 — "빼는 쪽"은 방어됨, "넣는 쪽"이 구멍

검증으로 확인된 노드–관리자 정합성 현황:

| 방향 | 경로 | 현재 상태 |
|---|---|---|
| **빼는 쪽** (관리자 이탈) | `baim06` 관리자 교체·삭제(`saveSiteNodeMainAdmin`/`saveSiteNodeSubAdmin`/`deleteSiteNodeAdmin`) | ✅ 그 노드에 근로자 잔존 시 차단(`COMMON_400_001`). |
| **빼는 쪽** | `user01.updateOneUserInfo`(187줄 `selectUserNodeAdminCheck`) | ✅ 노드 관리자인 사용자의 타 노드 이동·비활성 차단(`USER_400_001/002`). |
| **넣는 쪽** (근로자 투입) | `user01.createUser`(신규 생성, INSERT) | ❌ 노드 **존재만** 검증(`selectSiteNodeExists`), 관리자 유무 미검증. |
| **넣는 쪽** | `login.insertUserInfo`(회원가입 self-signup) | ❌ `NODE_CD` 지정받으나 관리자 유무 미검증. |
| **넣는 쪽** | `user01.mergeUserInfo`/`updateOneUserInfo`(노드 이동) | ❌ **떠나는** 노드만 방어, **들어가는** 노드 관리자 유무 미검증. |

→ "근로자를 관리자 0명 노드에 새로 투입"하는 경로만 안 막혀 있다. 본 작업은 이 **"넣는 쪽" 가드를 추가**하여 불변식을 완성한다.

### 0.2 노드 생애주기 (사용자 확정 2026-06-04)

본 작업이 막아야 하는 것과 막지 말아야 하는 것의 기준:

1. **노드 생성**: Main/Sub 관리자·소속 근로자 **모두 없어도 됨**(빈 노드 허용). `saveSiteNode` 현행 유지 — 관리자 필수화하지 않음.
2. **관리자 임명**: master/hr 등 권한자가 해당 노드에 Main 또는 Sub 관리자 임명(`baim06.saveSiteNodeMainAdmin`/`SubAdmin` → `updateUserNode` 로 관리자 본인 소속 변경). **이 경로는 가드 대상 아님**(노드가 관리자를 갖게 되는 유일한 정상 경로).
3. **근로자 배정**: **관리자가 임명된 뒤부터만** 근로자가 해당 노드에 소속될 수 있다. ← **본 작업이 강제하는 지점.**

## 1. 작업 범위

### (A) "넣는 쪽" 가드 추가 — 대상 노드 관리자 존재 검증

근로자가 노드 소속을 **신규 획득**하는 모든 경로에서, 대상 `NODE_CD` 에 `MAIN_ADMIN_CD` 또는 `SUB_ADMIN_CD` 가 존재하는지 검증하고, 없으면 차단한다.

가드 적용 대상 (전수 식별 완료):

| # | 경로 | 위치 | 처리 |
|---|---|---|---|
| A-1 | 관리자 단건/엑셀 사용자 생성 | `User01ServiceImpl.createUser` (부서 존재검증 `selectSiteNodeExists` 611줄 직후) | 노드 관리자 존재 검증 추가. 부재 시 신규 에러. 엑셀 행 단위도 동일(행별 에러 수집). |
| A-2 | 회원가입(self-signup) | `Login... insertUserInfo`(`UserJoinCommand`) 호출 서비스 | 가입 요청 `nodeCd` 의 관리자 존재 검증. 부재 시 가입 거부. |
| A-3 | 사용자 정보 수정 시 노드 이동 | `User01ServiceImpl.updateOneUserInfo`(183줄 노드변경 분기) | **들어가는(새) 노드** 관리자 존재 검증 추가. 기존 "떠나는 노드" 방어(`selectUserNodeAdminCheck`)는 유지. |

가드 **제외**(정상 경로/무관):
- `baim06.updateUserNode` (관리자 임명 — 노드가 관리자를 얻는 행위).
- `user01.withdrawMyAccount`(NODE_CD=NULL, 노드에서 빠짐) · `mypage01`(노드 미변경).

### (B) 검증 헬퍼

- 신규 mapper: `selectNodeHasAdmin(cmpnyCd, siteCd, nodeCd)` → `tb_site_node` 의 `NULLIF(TRIM(MAIN_ADMIN_CD),'') IS NOT NULL OR NULLIF(TRIM(SUB_ADMIN_CD),'') IS NOT NULL` 여부(1/0).
- 또는 `selectSiteNodeExists` 를 확장해 관리자 존재까지 한 번에 판정(존재+관리자 동시). **구현 시 결정.**
- ⚠️ 노드 `'*'`(전사/와일드카드) 등 특수 노드가 사용자 소속 `NODE_CD` 로 들어올 수 있는지 확인 후, 특수 노드는 가드 예외 처리(해당 시).

### (C) 에러코드 (신규)

- `UserErrorCode` 에 신규: 예) `USER_400_0xx` — "관리자가 지정되지 않은 노드에는 사용자를 배정할 수 없습니다. 먼저 노드에 담당 정/부 관리자를 임명하세요."
- 회원가입 경로(A-2)는 `LoginErrorCode` 또는 공통 에러 — 메시지는 가입자 친화적으로("선택한 부서는 현재 배정할 수 없습니다. 관리자에게 문의하세요.").

### (D) 프론트엔드 (선택 노드 필터)

- 사용자 생성/수정(`prafta-web-frontend` user 화면) 및 **회원가입 화면**의 노드 선택 드롭다운/트리에서, **관리자 미지정 노드를 선택 불가(비활성/제외)** 로 표시. UX 사전 차단.
- 단 백엔드 가드(A)가 **단일 진실**: 프론트 필터는 편의이고, 서버 검증이 최종 방어.

## 2. 데이터/마이그레이션

- **백필 불필요**: 현재 운영 데이터에 "관리자 0 + 근로자 ≥1" 노드 0건 확인(2026-06-04). 기존 데이터 정합성 깨짐 없음.
- 스키마 변경 없음(`MAIN_ADMIN_CD`/`SUB_ADMIN_CD` NULL 허용 그대로 — 빈 노드 생성을 허용해야 하므로 NOT NULL 화하지 않음).
- 마이그레이션: 0건(에러코드는 enum/메시지 정의이므로 SQL 무관) 또는 신규 에러 메시지를 코드성 테이블에 둘 경우만 1건.
