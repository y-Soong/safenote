\## ChkLst\_04.vue 점검 불량 관리 화면 신규 개발



1. TB\_CHKPT\_INSPECT\_ANSWER 테이블을 기준으로 INSPECT\_ANSWER\_TYPE이 N 인 불량 항목에 대해서 개선 여부를 관리하는 역할을 수행
2. 해당 화면에서 INSPECT\_ANSWER\_TYPE이 N 인 항목에 대한 개선을 했다고 해서 해당 값이 N > Y 로 변경되면 안됨
3. 신규 테이블에서 해당 불량 항목이 어떻게 관리 됐는지에 대한 내용만 기록하면 됨
4. 테이블에서 관리돼야 할 항목

   1. 조치여부

      1. 9번 항목에서 상세 내역이 입력된 항목은 조치완료, 그 외엔 미조치
   2. 사업장(수정x)
   3. 점검구분(수정x)
   4. 점검대상명칭(수정x)
   5. 점검항목명(수정x)
   6. 불량내용(버튼)

      1. 버튼명은 "상세"라고 한다.
      2. 해당 버튼을 누르면 팝업이 뜸, 해당 팝업에서 사용자가 불량항목이라고 체크하며 입력한 비고 내용 및 사진을 보여줌
   7. 점검자(수정x)
   8. 점검일자(수정x)
   9. 조치(버튼)

      1. 버튼명은 "입력"으로 한다.
      2. 해당 버튼을 누르면 팝업이 뜸, 해당 팝업에서 textarea로 불량에 대한 처리 상세 내역을 입력 후 저장
5. 조회조건으론 사업장(코드 버튼 명칭 구조), 점검구분(selectbox), 점검대상명칭(신규 팝업), 점검문항(신규 팝업), 조치여부(select)

   1. 점검대상명칭, 점검문항 신규 팝업 부분은 input, 버튼 구조로 화면에서 보여준다.

      1. input 태그는 비활성화 상태로 버튼을 누르면 나오는 팝업에서 return 받은 명칭을 넣어주면 된다.
      2. 점검대상 팝업에서는 ChkList\_01.vue 화면과 유사한 형태로 데이터를 조회해서 사용자에게 보여주고 그중 하나를 더블클릭 형태로 선택하게끔 처리하면 된다. (점검대상명칭칭, 관리자, 비고 정도만 팝업내 테이블에 나오면 됨)
      3. 점검문항 팝업에서는 ChkList\_02.vue 화면의 우측 그리드와 유사한 형태로 데이터를 조회해서 사용자에게 보여주고 그 중 하나를 더블클릭 형태로 선택하게끔 처리하면 된다.(점검항목명, 시행월 정도만 나오면 됨)
      4. 두 신규 팝업은 앞서 사업장과 점검구분을 골라야 팝업이 열리도록한다.



\## 규칙이 애매하거나 추가로 정의가 필요한 항목들은 채팅으로 질의
