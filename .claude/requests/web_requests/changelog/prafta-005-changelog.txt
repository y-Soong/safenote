1. 요청 요약
================================================================================
Attd_07.vue 화면 fnSearch 조회 쿼리가 TB_SCH_MGMT만 조인해, 근무일이 언제든 항상
"최신 스케줄"을 보여주는 버그. TB_SCH_MGMT(현재본) + TB_SCH_MGMT_HIST(이력본)를
결합해 각 근무일에 APPLY_DATE <= 근무일 인 가장 최근 버전이 적용되도록 수정.
예: SCH_CD '00005' APPLY_DATE 20260308·20260517 → 근무일 20260308~20260516은
20260308 버전, 20260517~ 는 20260517 버전.

■ 공통 수정 패턴 (effective-dating)
  - 기존 `LEFT JOIN TB_SCH_MGMT SCH`(현재본 1건, APPLY_DATE 조건 없음)를 제거.
  - TB_SCH_MGMT + TB_SCH_MGMT_HIST를 UNION ALL한 인라인 뷰로 대체. 현재본에는 가상
    HIST_IDX=2147483647 부여 → 동일 APPLY_DATE 중복 시 현재본 우선.
  - 동일 SCH_CD+APPLY_DATE는 MAX(HIST_IDX) 상관 서브쿼리로 1건만 채택.
  - 근무일별로 `SCH.APPLY_DATE = (SELECT MAX(APPLY_DATE) ... WHERE APPLY_DATE <= WP.WORK_YMD)`
    상관 서브쿼리 → 월별 그리드에서 일자마다 다른 버전이 적용됨.
  - SCH_TYPE은 TB_SCH_MGMT(현재본)를 SCH_CD로 별도 LEFT JOIN(SCHT)해 취득
    (selectMonthlyAttdList/selectDailyAttdDetails만; selectAllowedWindow는 SCH_TYPE 미사용).
  - 모든 조인/서브쿼리에 CMPNY_CD+SITE_CD 테넌트 격리, USE_YN='Y' 유지.
  - 각 select 결과 컬럼(이름·개수·순서) 불변 → Controller/Service/DTO 무변경.
