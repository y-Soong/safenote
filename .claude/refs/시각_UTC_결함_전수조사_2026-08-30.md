# 시각 UTC −9h 결함 전수조사 (2026-08-30)

## 0. 확정 진단 (운영 DB 실측)

- **운영 RDS MySQL: 세션/글로벌/시스템 타임존 전부 `UTC`.** 따라서 SQL `NOW()` / `CURRENT_TIMESTAMP` / DDL `DEFAULT CURRENT_TIMESTAMP` 로 기록되는 DATETIME 은 **UTC 벽시계**로 저장된다.
- **백엔드 JVM 은 `MainApplication` 에서 `TimeZone.setDefault(Asia/Seoul)`** → Java 에서 만들어 파라미터(`#{...}`)로 기록한 시각·일자 문자열(WORK_YMD, CHECK_IN_TIME 등)은 **KST**.
- 결과: **기록 주체에 따라 KST/UTC 가 테이블·컬럼 단위로 혼재** → "화면별로 맞는 게 있고 안 맞는 게 있는" 현상의 근본 원인.
- 실측 예: Tbm_04 "206-08-30 TBM 테스트 교육" — 실제 10:49 KST 종료, `ENDED_AT` 저장값 01:49(UTC).
- 검증된 사실: 전 resources 트리에서 `INSERT_DATE`/`UPDATE_DATE` 를 `#{}` 로 기록하는 구문 **0건** — 감사 컬럼은 예외 없이 NOW()=UTC 저장.

## 0-1. 표시 보정 표준 (환경 중립, 양 DB 실측 검증)

```sql
DATE_FORMAT(CONVERT_TZ(col, @@SESSION.time_zone, '+09:00'), '%Y-%m-%d %H:%i')
-- 일자 필터도 동일: DATE(CONVERT_TZ(col, @@SESSION.time_zone, '+09:00')) >= #{startDate}
```
- 운영(세션 UTC): +9h 변환 / 개발(세션 SYSTEM=KST): no-op.
- **NOW() 기록 컬럼에만 적용**할 것 — Java-KST 기록 컬럼에 적용하면 +9h 이중 밀림.
- `TIMESTAMPDIFF`(시각 차) / `ORDER BY`(단조성) 는 변환 불요.
- Platform_05 의 epoch(`UNIX_TIMESTAMP`)+FE 포맷 방식과 동등 정확(그쪽도 NOW() 기록 컬럼 한정).
- **적용 완료**: `web/tbm/tbm04/Tbm04Mapper.xml` 전 시각표시·일자필터 (2026-08-30).

## 5. 해결 전략 (사용자 결정 필요)

### A안 — 근본 해결: DB 세션 타임존 KST 전환 + 데이터 마이그레이션 (권장, 단 준비 필요)
1. JDBC URL 에 `connectionTimeZone=Asia/Seoul&forceConnectionTimeZoneToSession=true` 추가(또는 RDS 파라미터그룹 `time_zone=Asia/Seoul`) → 이후 `NOW()` 기록이 KST 로 통일. NOW() 당일판정·잠금·만료 결함이 전부 일괄 해소.
2. 전환 시점 이전에 NOW() 로 적재된 기존 데이터(본 문서 목록의 컬럼들)를 `+9h` 보정하는 마이그레이션 실행(전환 시각 마커 기준, Workbench).
3. 기존 보정 지점 재점검: `CONVERT_TZ(@@SESSION…)` 식(Tbm04) 은 전환 후 자동 no-op — 안전. Platform_05 epoch 픽스는 구데이터가 마이그레이션되면 정합.
- 리스크: 마이그레이션 대상 선정 오류 시 이중 보정. 배포·전환·보정 순서 조율 필요. 시행 전 별도 지시서로 분해 권장.

### B안 — 점진 보정: 결함 목록에 화면별 CONVERT_TZ 패치
- 데이터 무변경·즉시 적용 가능(Tbm_04 방식). 그러나 지점이 100+ 이고, **NOW() 당일판정/잠금해제(우선순위 1·2·7 등)는 표시 보정으로 못 잡는다** — 그쪽은 어차피 개별 수정 필요.

### 권장 조합
- 단기(즉시): 우선순위 1(비번 잠금)·2(근태 오늘 판정)·5(열람로그 적재)·7(일용직 만료일) 등 기능/보안 결함 개별 수정 + 사용자 체감 큰 화면(TBM 계열 — 완료, 결재/요청함, 공지) CONVERT_TZ 보정.
- 중기: A안 전환으로 일괄 종결(전환 후 CONVERT_TZ 지점은 no-op 라 회귀 없음).
