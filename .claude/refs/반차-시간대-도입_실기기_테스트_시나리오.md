## 0. 이 문서 사용법 · 전제 조건

### 0-1. 무엇을 판단하는 문서인가

이번 배포가 정상인지를 **이 문서 하나로** 판단한다. 시나리오마다 “무엇이 보이면 통과인지”를 숫자·문구까지 적었다.

```
### T-xx  제목
- 목적 / 검증 대상 (어느 커밋·어느 항목)
- 역할: 근로자 | 관리자 | 둘 다
- 전제(시드)
- 조작 순서
- OK  기대 결과 (무엇이 보이면 통과인지)
- NG  실패 시 의미 (어느 결함이 살아있다는 뜻인지)
- 정리(cleanup)
```

## 1. ★ 운영 DB 주의 — 이 테스트는 운영 데이터를 만든다

실기기 앱은 **`api.prafta.com`(운영)** 에 붙는다. 웹도 운영 화면을 연다.
따라서 이 문서의 모든 조작은 **운영 DB 에 실제 행을 만든다.**

★ **전제: 실사용자 0명.** 운영 데이터는 전부 테스트 데이터이며(서비스 신고 전, 2026-08-04 확인) 대기 중인 첫 고객이 아직 올라타지 않았다. 이 전제가 깨지면(첫 고객 고라이브 이후) **이 문서를 운영에서 그대로 수행해서는 안 된다.**

## 2. 사전 시드 준비 (여기서 한 번에 다 만든다)

★ **이 절을 먼저 끝내라.** 시나리오 도중에 시드를 만들면 계정 전환이 폭증한다.

### 2-1. 반차 경계 산출 규칙 (기대값 계산의 근거)

```
D  = 그날 실근로분 = 시그마( 구간 종료 − 구간 시작 − 구간 휴게분 )
H  = D / 2   (정수 절사)
경계 = 근무 시작부터 근로만 누적해 H 에 도달하는 시각 (휴게 시각이 있으면 그 구간은 건너뛰며 누적)

늦게 출근(시작기준) = [근무시작, 경계) 를 쉬고 경계부터 근무
일찍 퇴근(종료기준) = 경계까지 근무하고 [경계, 근무종료) 를 쉼
```

★ **D 는 `근무시간 길이 − 휴게시간(분)` 이다.** 휴게 “시각”은 D 계산에 안 쓰이고 **경계를 어디서 건너뛸지**에만 쓰인다.

### 2-2. ★ 시드 근무타입 5종 — 만드는 법

**경로**: 웹 로그인(H) → `근태 설정 > 근무타입 관리`(Attd_01) → `스케줄관리` 탭 → 등록 → `근무타입 생성` 팝업

입력 필드: `사업장` / `타입코드 *` / `적용일 *` / `구간수 *` / **구간1** `근무시간 *`(시작 ~ 종료) · `휴게시간(분단위)` · `휴게시간 시작` / **구간2**(구간수 2일 때) / `사용여부`

#### ★★ 입력 제약 3가지 (모르면 시드를 못 만든다)

| 제약 | 내용 |
|---|---|
| **분은 10분 단위만** | 시각 입력이 `:minute-step="10"` 이라 분은 `00 / 10 / 20 / 30 / 40 / 50` 만 고를 수 있다. `17:31` 같은 값은 **입력 불가** |
| **휴게분을 넣으면 휴게시작이 필수** | 휴게시간(분) ≥ 1 이면 `휴게시간 시작` 이 필수가 된다. 휴게 종료는 `시작 + 분` 으로 **자동 계산**되며 10분 단위 제약을 받지 않는다 |
| **★ 적용일이 배정 가능 하한** | 근무계획 배정 시 `근무일 < 적용일` 이면 **`근무타입 생성일 이전 날짜입니다.` 로 스킵**된다. 과거일 시드(`D1p`~`D4p`)에 배정하려면 **적용일을 그 날짜보다 앞으로** 잡아야 한다 |

→ **적용일은 “이번 달 1일”(또는 과거일 시드가 지난달이면 지난달 1일)로 넣는다.** “오늘”로 넣으면 과거일 배정이 전부 스킵된다.

#### 시드 정의

| 시드 | 목적 | 적용일 | 구간수 | 구간1 근무 | 구간1 휴게(분) | 구간1 휴게시작 | 구간2 근무 | 구간2 휴게(분) |
|---|---|---|---|---|---|---|---|---|

## 3-C. 판정 6경로 대조 ★★ (이번 작업의 핵심 합격 기준)

### ★★ C 계열은 하루에 다 끝낼 수 없다 (P0-5)

| 묶음 | 내용 | 조건 |
|---|---|---|
| **묶음 1** | C-1 → C-2 | **같은 사람·같은 날·같은 반차**로 연속 가능. C-1 후 근태 행만 삭제하고 1분 뒤 다시 출근 |

| **묶음 3** | C-4 (반차 2건) · C-8 (야간 2건) | **다른 사람(W3) 또는 또 다른 날** |

→ **W2·W3 을 확보하면 하루에 끝난다. 못 구하면 최소 3일이 필요하다.**
→ C-6(야간)·C-5(무회귀)는 실시간이 아니라 **과거일 시드 + 관리자 직접 입력**으로 한다.

### C-0  ★ 준비: 판정 전용 근무타입 `THP` 를 즉석에서 만든다

출퇴근은 **실시간으로만 찍힌다**. 그래서 **경계 시각이 “지금”이 되도록 근무타입을 역산**한다.

```
휴게 0분이면  경계 = 근무 시작과 종료의 정중앙
따라서       근무시간 = (원하는 경계 − 2시간) ~ (원하는 경계 + 2시간)
```

예) 경계를 **15:00** 으로 잡는다면

| 항목 | 값 |
|---|---|
| 타입코드 | `THP` |
| 적용일 | **이번 달 1일** (§2-2 제약 3) |
| 구간수 | 1 |
| 구간1 근무시간 | `1300 ~ 1700` |
| 구간1 휴게(분) | `0` |
| 산출 | D = 240, H = 120, **경계 = 15:00** |

준비 절차:
1. `Attd_01` 에서 `THP` 생성
2. `Attd_05` 에서 **오늘** 날짜에 W(그리고 W2·W3)의 셀에 `THP` 적용 → **원래 근무타입을 메모**
3. 각자 **오늘** 날짜로 반차 신청 → 확정 (W = 늦게 출근, W2 = 일찍 퇴근, W3 = 늦게 출근 + 일찍 퇴근 2건)

★ 소요 시간에 **반차 정리(3단계 결재)** 를 반드시 포함해 잡는다 — C 계열 종료 후 W·W2·W3 각각에 대해 삭제 발의 → 동의 → 확인이 필요하다.

## 3-D. 초과근무(OT) 허용 범위

> 검증 대상: 커밋 `74885198` HB-08(D5 교정) / 작업요약서 §5-3
> 서버 산식: **`허용 = 실근태 − (그 구간 스케줄 ∪ 그날 연차 면제 구간)`** — 차집합이 아니라 **합집합**을 뺀다. 구간(WORK_SEQ)별로 따로 계산한다.
> 시드: **과거일**(근태 직접 입력이 필요하므로 미래일에서는 불가 — §1-4)

### ★★ 화면의 `등록 가능` 칩은 서버 산식이 아니다 (P0-3)

```
화면 칩(웹 Attd_07 일자상세 · 앱 초과근무 신청 폼)
   = 프론트엔드가 자체 계산한  "실근태 − 스케줄"
   -> 연차 면제 구간이 들어가지 않는다

서버 검증(합집합)
   = OT 를 실제로 저장/승인할 때만 돈다  -> 범위를 벗어나면 ATTD_400_012
```

- **칩과 저장 결과가 달라도 정상이다.** 칩에 `15:00~19:00` 이 떠 있는데 저장이 거부되는 것이 **올바른 동작**이다.
- 따라서 **D 계열의 판정 수단은 칩이 아니라 실제 저장 시도 + 결과**다.
- 거부 문구: **`초과근무 시간이 스케줄 외 허용 범위를 벗어났습니다. 정규 근무 시간 외의 시간으로 입력해 주세요.`** (`ATTD_400_012`)
- 이 칩 불일치를 결함으로 보고하지 말 것(별건 — §8-B-6).

공통 조작 경로: 웹 `Attd_07 근무 관리` -> 대상 날짜 W 셀 **더블클릭** -> 일자상세 팝업 -> 우측 `초과근무` 블록 -> `+ N구간 초과근무 추가` -> 시각 입력 -> **`초과근무 저장`**

### D-1  ★★ D5 교정: 일찍 퇴근 반차 + 오후 재출근 (시드 교체됨)

- **목적**: 종전에 **240분 전액**이 OT 로 인정되던 구멍이 **60분**으로 교정됐는지
- **역할**: 관리자
- **★ 초판 정정**: 초판의 단일 구간 `15:00~19:00` 시드로는 **D5 결함 형상을 만들 수 없다**(1차에는 스케줄이 매칭돼 교정 전후 결과가 같다). **스케줄이 없는 2차 구간**이 있어야 한다
- **전제**
  - **과거일 `D1p`** 에 TH-A(09:00~18:00, 휴게 11:30~13:00) 배정 — 스케줄은 **1구간뿐**
  - `D1p` 에 **`일찍 퇴근`** 반차 확정 (쉬는 구간 = `14:15~18:00`)
  - `D1p` 근태를 **2구간으로** 직접 입력
    - **1차**: 출근 `09:00` / 퇴근 `14:15`
    - **2차**: 출근 `15:00` / 퇴근 `19:00`   <- 매칭 스케줄이 없는 구간
- **조작 · OK 기대 결과**

| # | 2차 구간에 등록 시도할 OT | 기대 |
|---|---|---|
| 1 | **`18:00 ~ 19:00`** | **저장 성공** (허용 60분) |
| 2 | **`15:00 ~ 19:00`** | **거부 — `ATTD_400_012`** |
| 3 | `15:00 ~ 16:00` | **거부 — `ATTD_400_012`** (연차로 쉬는 시간대) |

- **NG**: 2번이 **저장되면 D5 미해소** — 240분이 전액 수당으로 나간다. ★★ 롤백 검토 대상
- **참고**: 이때 화면 칩에는 `15:00~19:00` 이 그대로 떠 있다(FE 계산). 정상이다
- **정리**: 저장한 OT 삭제 -> 근태 2행 삭제 -> 반차 삭제

### D-2  ★회귀금지: 일찍 퇴근 반차 + 오전 조기출근 = OT 유지

- **목적**: 원 요청서 §1-3 이 깨뜨리지 말라고 못 박은 동작
- **전제**: `D1p` + `일찍 퇴근` 반차(쉬는 `14:15~18:00`), 근태 **1차 07:00 ~ 13:00** (단일 구간)
- **조작 · OK**

| 등록 시도 | 기대 |
|---|---|
| **`07:00 ~ 09:00`** | **저장 성공** (허용 120분) |
| `07:00 ~ 09:30` | 거부 — `ATTD_400_012` |

- **NG**: 첫 줄이 거부되면 **회귀** — 정당한 조기출근 OT 를 잃는다
- **정리**: OT·근태 삭제

### D-3  ★회귀금지: 종일 연차일 OT 차단 유지

- **전제**: 과거일 `D4p` 에 **종일** 연차 확정 + 근태 기록 존재
- **조작**: 일자상세에서 초과근무를 추가하고 `초과근무 저장`
- **OK**: **`연차일에 등록된 근무는 초과근무를 올릴 수 없습니다. 연차일자를 먼저 조정해 주세요.`** (`ATTD_400_151`)
- **NG**: 저장되면 회귀
- **주의**: 종일 연차일은 일자상세가 **읽기 전용**으로 열린다. 그러므로 **근태를 먼저 만들고 나중에 종일 연차를 확정**하는 순서로 시드를 만든다
- **정리**: 종일 연차 삭제

### D-4  ★ 야간 일찍 퇴근 반차 + 익일 재출근

- **목적**: 야간에서 합집합이 자정을 넘겨 정확히 계산되는지(정적 검증에서 180분 -> 30분 교정 확인)
- **전제**
  - **과거일 `D2p`** 에 TH-D(22:00~04:30) 배정
  - `D2p` 에 **`일찍 퇴근`** 반차 확정 (쉬는 구간 = `01:15~04:30`)
  - 근태 2구간 직접 입력
    - **1차**: 출근 `D2p 22:00` / 퇴근 `D2p+1 01:15`
    - **2차**: 출근 `D2p+1 02:00` / 퇴근 `D2p+1 05:00`
- **조작 · OK**

| 2차 구간에 등록 시도할 OT | 기대 |
|---|---|
| **`04:30 ~ 05:00`**(익일) | **저장 성공** (허용 30분) |
| **`02:00 ~ 05:00`**(익일) | **거부 — `ATTD_400_012`** |

- **NG**: 두 번째가 저장되면 야간 면제 구간이 **1440분 어긋난 자리**에 배치된 결함 재발
- **정리**: OT·근태 2행·반차 삭제

### D-5  ★회귀금지: 시간차는 불변

- **전제**: `D1p`(TH-A) 에 **시간차 1시간 `10:00~11:00`** 확정 + 근태 **1차 07:00 ~ 19:00**
  - ★ 시간차는 휴게를 가로지를 수 없다. TH-A 휴게가 11:30~13:00 이므로 `10:00~11:00` 은 통과한다
- **조작 · OK**

| **`18:00 ~ 19:00`** | 저장 성공 (둘 합쳐 180분) |
| `10:00 ~ 11:00` | 거부 — `ATTD_400_012` |
| `07:00 ~ 19:00` | 거부 (허용 구간이 둘로 쪼개져 있어 한 덩어리로는 불가) |

- **NG**: `10:00~11:00` 이 저장되면 회귀
- **정리**: OT·근태·시간차 삭제
- **비고**: §2-5 의 사용 단위 잠금 구성이면 시간차를 못 만든다 -> **N/A**

### D-6  앱에서 반차 쉬는 시간대에 OT 신청 시도

- **목적**: 신설 에러코드 `ATTD_400_196` 발동
- **역할**: 근로자(W)
- **전제**: D-1 상태(일찍 퇴근 반차, 쉬는 구간 14:15~18:00) + W 의 그날 근태 존재
- **조작**: 앱 `내 근태` -> 해당 일자 -> `초과근무 신청` -> 시간을 **15:00 ~ 17:00** 으로 입력하고 제출
- **OK**: **`연차로 쉬는 시간대에는 초과근무를 등록할 수 없어요. 실제 근무한 시간으로 조정해 주세요.`** (`ATTD_400_196`)
- **NG**: 제출이 성공하면 앱 가드 미적용
- **참고**: 폼의 `등록 가능 시간` 칩에는 그 구간이 보일 수 있다(FE 계산). 정상이다
- **정리**: 신청됐다면 관리자 반려

### D-7  2구간 스케줄 + 늦게 출근 반차 -> 구간 사이 공백 근무 (신규)

  - `D3p` 에 **`늦게 출근`** 반차 확정 (쉬는 구간 = **`09:00~18:30`** — 구간 사이 공백 12:00~18:00 을 포함한다)
  - 근태 2구간 직접 입력 — **1차**: `08:00 ~ 12:00` / **2차**: `14:00 ~ 16:00`
- **조작 · OK**

- **정리**: OT·근태 2행·반차 삭제

## 3-E. 결근 계상

> 검증 대상: 커밋 `74885198` HB-06(D2) / 작업요약서 §2-2
> 규칙: `결근분 = max(0, D − 반차 면제분)`. **출근 기록이 있는 날은 결근 0**.
>
> ★★ **반드시 과거일이어야 한다 (P0-2)** — 결근 집계 쿼리에 `근무일 <= 오늘` 필터가 있다. 미래일은 **항상 0** 이라 E-1 은 거짓 실패, E-2·E-3 은 진공 통과가 된다.
> ★ **표시 위치 = 웹 `Attd_11 월별 사용자 근태 판정` 의 `미출근` 컬럼(정수).** 배포검증서가 말한 `0.5일 (3시간 45분)` 문구는 **화면에 구현돼 있지 않다**(§8-A-1).
> ★ 그 사용자에게 **그 달의 다른 출근/초과근무 기록이 하나도 없으면 행 자체가 안 나온다.** 같은 달에 정상 근무 1건 이상을 함께 둔다.

### E-1  반차 + 무출근 -> 결근 계상

- **전제**: **과거일 `D1p`**(TH-A) 에 반차 확정 + **그날 출근 기록 없음** + 같은 달 다른 날에 정상 근무 1건
- **조작**: 웹 `Attd_11` -> 해당 월 조회 -> W 행 `미출근` 컬럼
- **OK**: `미출근` 이 **1 증가**(면제 225분 < 소정 450분 -> 결근분 225분 > 0)
- **NG**: 0 이면 결근이 통째로 빠진 것
- **정리**: 반차 삭제

### E-2  반차 + 절반 출근 -> 결근 0

- **목적**: 연차 0.5 + 결근 1 = 하루에 1.5일 이라는 이중 계상 소멸
- **전제**: **과거일 `D1p`** 반차(`늦게 출근`) 확정 + 근태 `14:15~18:00` 직접 입력
- **조작**: `Attd_11` 조회
- **OK**: `미출근` **증가 없음**
- **NG**: 증가하면 D2 미해소
- **정리**: 근태·반차 삭제

### E-3  종일 연차일 -> 결근 0 (회귀)

- **전제**: **과거일 `D4p`** 에 종일 연차 확정, 출근 없음, 같은 달에 다른 근무 1건
- **OK**: `미출근` 증가 없음
- **NG**: 증가하면 종일 제외 규칙이 깨진 것
- **정리**: 종일 연차 삭제

## 3-F. 주52시간 (Attd_15)

> 검증 대상: 커밋 `74885198` HB-07(D3)
> 규칙: `일자별 소정 = max(0, 계획 소정 − 반차 면제분)`. **종일 연차일은 소정 0**.
> 배지 경계(코드 직접 확인): `40시간 이하 = 정상` / `48시간 이하 = 주의` / `52시간 이하 = 위험` / `52시간 초과 = 초과`

### F-1 · F-2  한 주에서 세 상태를 연속으로 본다 (초판 재설계)

- **★ 초판 정정**: 초판은 전제·예시·배정표가 서로 어긋났다. **하나의 시드로 F-1·F-2 를 연속 측정**하도록 바꿨다
- **역할**: 관리자(H)
- **전제**: **과거일 `D1p` 가 속한 주의 월~일 7일 전부**에 W 에게 **TH-A(D=450)** 배정
- **조작**: 웹 `근태 관리 > 주52시간 관리`(Attd_15) -> 그 주 조회 -> W 행 `스케줄기준`

| 단계 | 시드 상태 | 기대 `스케줄기준` | 기대 배지 | 검증 항목 |
|---|---|---|---|---|
| ① 기준 | 연차 없음 | **52시간 30분** (3150분) | **`초과`** | — |
| ② 반차 | 그중 하루에 **반차** 확정 | **48시간 45분** (2925분) | **`위험`** | **F-1**: ①−② = **정확히 225분** |
| ③ 종일 | 반차를 지우고 하루를 **종일 연차** 확정 | **45시간** (2700분) | **`주의`** | **F-2**: ①−③ = **정확히 450분** (하루 전량) |

- **판정**
  - **F-1 통과** = ①−② 차이가 **225분**
  - **F-2 통과** = ③ 에서 종일 연차일이 **0분으로 계상**되고 배지가 **내려간다**
- **NG**
  - ② 에서 차이가 0 -> D3 미해소
  - ② 에서 차이가 450분 -> 반차를 종일로 잘못 처리
  - ③ 에서 차이가 0 -> 종일 연차 제외 미적용
  - **② 가 ③ 보다 작으면 역전 결함**(반차가 종일보다 많이 빠짐)
- **정리**: 연차 삭제 -> 그 주 배정 지우기

## 3-G. 겹침 검증 · 스케줄 잠금 · 사업장 이동

> 검증 대상: 커밋 `74885198` HB-02·HB-09(D4) / 작업지시서 §9-1 · Q2. 시드: **미래일**

### G-1  반차가 시간차와 겹치면 차단 (D4)

- **전제**: `D1`(TH-A) 에 **`늦게 출근`** 반차 확정(쉬는 구간 `09:00~14:15`)

  - 대조군: **`15:00~16:00`** 시간차는 겹치지 않으므로 통과해야 한다(단 하루 1.0 초과 가드 `ATTD_400_111` 에 걸릴 수 있음)

- **비고**: 사용 단위 잠금 구성이면 **N/A**(§2-5)
- **정리**: 신청분 반려/삭제

### G-2  미결 반차일 근무계획 **비우기** 차단

- **전제**: `D1` 에 반차 **신청(미결)** 상태 (결재 사용)
- **조작**: 웹 `Attd_05` -> `D1` 셀 선택 -> `지우기` -> `저장`
- **OK**: 그 셀이 **스킵**되고 사유가 표시된다

  - 이미 `반차` 를 고른 상태에서 `D6` 로 바꾸면 **자동으로 `종일` 로 되돌아간다**
- **NG**: 반차 칩이 활성인 채로 남아 신청 시 `ATTD_400_110` 이 뜨면 F-4 미해소
- **★ 로딩 중 오탐 주의**: 날짜 변경 직후 수백 ms 는 칩이 **활성인 것이 정상**(낙관 enable). 응답 도착 후 비활성이면 통과

### J-2  휴무·미배정일 종일 연차 안내 — **차단이 아니라 안내** (F-5)

- **조작**: 앱 연차 신청 폼 -> 일자 `D6` -> `사용 단위` **`종일`** 선택
- **OK**

  - **`신청하기` 가 활성이고, 제출하면 성공한다**
- **NG**
  - 안내가 안 뜨면 F-5 미해소. ★ 회사 정책이 `1일 (전일)` 일 때 특히 잘 드러난다(그 구성에서 종전에는 영구 미노출)
  - 제출이 차단되면 **과잉 구현**(차단 금지가 확정 사항)
- **정리**: 신청분 반려/삭제

- **NG**: 닫은 뒤 화면이 얼어붙으면 **잠금 해제 누수** — 과거 2회 재발한 결함

### K-3  프리셋 순서 보존

## 3-M. 근태 겹침 가드 (선행 작업 `74a89a25`) + 반차와의 상호작용

> 규칙: **이웃날(D-1 / D+1)의 퇴근 미입력 근태는 자기 근무일을 넘어 이웃날을 침범하지 않는다.**
> 당일(같은 날) 퇴근 미입력은 **종전대로 무한대** 취급(같은 날 이중 출근 방지).
> 퇴근이 출근보다 이르거나 같은 **길이 0/역전 근태는 겹침 판정에서 제외**한다.
> 시드: **과거일**(근태 직접 입력 필요)

### M-1  ★★ 재현 -> 해소: 전날 미마감이 오늘을 봉쇄하지 않는다

- **전제**
  - **과거일 `D`** 를 하나 정한다(예: `D4p`). `D-1` 에 W 의 근태 1건: 출근 **22:01**, **퇴근 비움**
  - `D` 에는 근태 없음
  - W 가 앱에서 `D` 에 대해 **근태 보정 요청** `09:03 ~ 18:59` 제출
- **조작**: M 이 앱 `관리자 모드 > 승인관리` 또는 웹 `Attd_10` 에서 **승인**
- **OK**: **승인 성공.** `ATTD_400_113` 이 뜨지 않는다
- **NG**: `다른 근무 구간과 시간이 겹칩니다.` 가 뜨면 clamp 미배포
- **정리**: `D` 근태 삭제 -> **`D-1` 미마감 근태 반드시 삭제 또는 퇴근 입력**

### M-2  ★ 앱 승인상세의 `앞뒤 근무일 근태` 섹션 (이번 번들 신규)

- **역할**: 관리자(M) — 앱
- **전제**: M-1 의 시드 상태(승인 전)
- **조작**: 앱 `관리자 모드 > 승인관리` -> 그 **근태 보정** 요청 -> 상세 진입
- **OK**
  - `요청 내용` 아래 **`앞뒤 근무일 근태`** 섹션
  - 항목: **`8월 2일 (D-1)`** `1차` `22:01 ~ —` + **`퇴근 미입력`** 배지
  - 하단 안내: `퇴근이 기록되지 않았거나 퇴근 시각 확인이 필요한 앞뒤 근무일이 있어요. 웹 근태관리에서 해당 날짜의 근태도 함께 정정해 주세요.`
- **NG**: 섹션이 없으면 **앱 번들에 이 화면이 안 들어간 것**(= 구 번들). 이웃날 근태 0건이면 **안 보이는 게 정상**

### M-3  웹 일자상세의 같은 섹션

- **조작**: 웹 `Attd_07` -> `D` 셀 더블클릭 -> 일자상세 팝업 좌측
- **OK**: **`앞뒤 근무일 근태 (1)`** 섹션 + `8월 2일 (D-1) 1차 22:01 ~ — [퇴근 미입력]`
- **NG**: 없으면 웹 미배포(웹은 이미 운영 배포됐으므로 나와야 한다)

### M-4  ★회귀금지: 같은 날 이중 출근은 여전히 차단

- **역할**: 근로자(W)
- **전제**: 오늘 출근만 하고 **퇴근을 찍지 않은** 상태
- **조작**: 앱 홈에서 다시 `출근`
- **OK**: **차단된다**(문구는 `같은 날 1차 근무(출근 HH:MM)의 퇴근이 기록되지 않았습니다…` 또는 직전 미퇴근 가드 문구 — **어느 쪽이든 출근이 성공하면 실패**)
- **NG**: 출근이 성공하면 당일 무한대 취급이 잘못 완화된 것
- **정리**: 퇴근 찍기 또는 근태 행 삭제

### M-5  길이 0 근태 후 당일 재출근 허용 (B-11 종결)

- **조작**: 앱에서 `출근` -> **곧바로** `퇴근`(같은 분) -> 다시 `출근`
- **OK**: 세 동작 모두 **성공**
- **NG**: 마지막 출근이 `다른 근무 구간과 시간이 겹칩니다` 로 막히면 미배포
- **★ 배지 확인 위치(초판 정정)**: `퇴근 확인 필요` 배지는 **앞뒤 근무일 섹션에만** 있다(당일 구간은 서버가 제외한다). 따라서 **그 다음 날의 일자상세를 열어 `D-1` 항목**에서 확인한다
- **정리**: 근태 행 삭제

### M-6  ★회귀금지: 정상 마감된 오버나이트는 다음날과 겹치면 여전히 차단

- **전제**: `D-1` 근태 = 출근 `D-1 22:00`, 퇴근 **`D 06:00`**(정상 마감)
- **조작**: `D` 에 근태 `05:00 ~ 14:00` 을 직접 입력하고 저장
- **OK**: **차단**. 문구에 **날짜·차수·시각** 포함 — 예 `8월 2일 1차 근무(22:00~익일 06:00)와 시간이 겹칩니다. 겹치지 않는 시간으로 조정해 주세요.`
  - 이어서 `07:00 ~ 16:00` 으로 바꾸면 **저장 성공**(경계 인접 허용)
- **NG**: 05:00 이 저장되면 이중 산입이 열린다
- **정리**: `D`, `D-1` 근태 삭제

### M-7  원인별 문구 4경로

| 경로 | 유발 방법 |
|---|---|
| 앱 셀프 출근 | M-4 |

- **OK**: 4경로 모두 **날짜 + 차수 + 시각**이 담긴 문구. **사람 이름·사번은 들어가면 안 된다**
- **NG**: `다른 근무 구간과 시간이 겹칩니다.` 만 나오면 문구 분기 미배포

### M-8  ★ 두 작업의 상호작용 — 미마감 이웃날 + 야간 반차 (신규)

- **목적**: 이번 배포에 함께 들어간 **두 작업이 서로를 깨뜨리지 않는지**. 초판에는 상호작용 시나리오가 0건이었다
- **역할**: 둘 다
- **전제**
  - **과거일 `D2p`** 에 TH-D(22:00~04:30) 배정 + **`늦게 출근`** 반차 확정(쉬는 `22:00~01:15`)
  - **`D2p - 1`** 에 W 의 근태 1건: 출근 `22:01`, **퇴근 비움**(미마감)
  - W 가 앱에서 `D2p` 에 대해 **근태 보정 요청** `01:15 ~ 04:30`(익일 시각) 제출

- **OK**

  - 승인은 됐는데 `지각` 이면 반차 야간 프레임 결함

## 3-N. 인가 게이트 (security H-1)

> 검증 대상: 커밋 `74885198` — `Attd_08` 에 서버 부서 관리 권한 게이트 신설 + 화면 프리필

### N-1  ★ 부서관리자가 Attd_08 에 들어가도 403 얼럿이 안 떠야 한다

- **NG**
  - 진입 즉시 403/권한 없음 얼럿 -> 게이트와 기본값 충돌
  - 부서를 비운 채 조회가 되어 **전 직원 목록이 보이면 인가 구멍**

### N-2  master / hr 는 전사 조회 정상

- **역할**: H
- **조작**: `Attd_08` 에서 부서를 비운 채 `조회`
- **OK**: 사업장 전체가 정상 조회(부서 강제 없음)
- **NG**: `소속 부서를 선택해 주세요.` 가 뜨면 전사 권한 판정 오류

### N-3  GPS 궤적 열람 권한 (초판 보강)

- **목적**: 권한 없는 관리자가 남의 부서 GPS 를 못 보는지
- **전제**: 외근(GPS 보유) 근태 기록이 있는 사용자 X. **M 은 X 의 부서 관리자가 아니어야 한다**
- **조작**
  1. **H** 로 `Attd_08` -> X 조회 -> 결과 행의 `상세` 클릭 -> GPS 궤적 확인
  2. **M** 으로 같은 시도(부서 선택으로 X 가 안 나오면, 조회 자체가 막히는 것으로 통과)
- **OK**: H 는 열린다. M 은 **X 를 조회조차 못 하거나, 열람 시 권한 거부 안내**가 뜬다
- **NG**: M 이 남의 부서 GPS 를 그대로 볼 수 있으면 인가 누락
- **비고**: 외근 기록이 없으면 **N/A**

## 3-O. 일용직 회귀

> ★ **코드로 확인한 사실: 일용직(`EMPLOYMENT_TYPE=DAILY`)에게 연차 개념은 없다.**
> 앱은 일용직에게 잔여연차 카드·연차 요약·연차 결재선·근태조회 카드·근태 요청 진입점을 **전부 숨긴다**. 서버도 일용직 OT 등록을 `ATTD_400_152` 로 차단한다.
> 따라서 **A~L 의 연차 시나리오는 일용직에 해당 없음**. 아래는 **회귀 확인 전용**이다.

### O-1  일용직 QR 출퇴근 회귀

- **역할**: 관리자(M) + 일용직(D)
- **조작**
  1. M 이 앱 `관리자 모드 > 현장 처리` -> 상단 세그먼트 **`출근`** -> D 의 QR 스캔
  2. 세그먼트를 **`퇴근`** 으로 바꾸고 같은 QR 재스캔

## 3-P. 잔여연차 사용 · 가불

### P-2  잔여 부족 시 거부

- **전제**: 잔여가 0.5일 미만인 연차 종류
- **조작**: 그 종류로 반차 신청
- **OK**: **`잔여 연차가 부족합니다.`** (`ATTD_400_051`)
- **NG**: 신청이 되면 잔여 검증 회귀
- **비고**: 그런 종류를 만들 수 없으면 **N/A**

### P-3  가불(미래 연차 당겨쓰기) 동의 흐름

- **전제**: **시스템 법정 연차 + 가불 허용 정책 + 잔여 부족** 3조건 동시 성립(하나라도 아니면 토글이 안 뜬다)
- **조작**: 연차 신청 폼에서 반차 선택 -> `미래 연차를 당겨 사용(가불)` 체크
- **OK**: `가불 가능 한도` / `만료(소멸)` / `결재 승인 후 확정돼요…` 안내가 뜨고 신청이 진행된다. **반차 파트 선택이 초기화되지 않는다**
- **NG**: 토글을 켜면 반차 파트가 리셋되거나 신청이 실패
- **비고**: 조건이 안 맞으면 **N/A**

### P-4  가불 반차 삭제 시 회수 (신규)

- **목적**: 가불로 당겨 쓴 반차를 삭제하면 **미사용분이 회수**되는지
- **역할**: 둘 다
- **전제**: P-3 으로 가불 반차 1건 확정. 삭제 **전** 잔여/가불 값을 기록
- **조작**: 웹 `Attd_13` 에서 그 반차를 **삭제 발의** -> 근로자 동의 -> 관리자 확인
- **OK**: 앱 연차 현황에서 **가불 잔액이 원래대로 복구**되고 `사용` 값에서 그 반차가 빠진다
- **NG**: 가불이 회수되지 않고 남으면 원장 정합 결함
- **비고**: P-3 이 N/A 면 함께 **N/A**

### 6-C. PUSH 확인의 전제

- 관리자 **M 의 기기에 활성 토큰**이 있어야 도착한다. 설치만 하고 로그인/알림 권한을 안 주면 발송은 되지만 수신이 없다.
- PUSH 는 **근로자 소속 노드의 main/sub 관리자**에게만 간다. M 이 W 의 부서 관리자가 아니면 안 온다.
- **근태 레코드 1건당 1회만** 발송된다(멱등). 재시험하려면 근태 행을 삭제하고 새로 만들어야 한다.
