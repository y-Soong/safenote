**범례**
- 🟢 정책서로 확정된 규칙
- 🔵 세션에서 사용자가 확정한 결정
- ⚠️ 정책 미확정 · 현행 동작만 존재

A~D는 공식 정책서(`.claude/context/policies/`)에 근거가 있어 **확정 규칙**입니다. E~F(안전 활동)는 **통합 정책서가 없어** 코드·구현 기록에서 역추출한 현행 동작이라, 정책서화하려면 항목별 확인이 필요합니다.

> **⭐ 자주 오해하는 규칙: "휴가일엔 연차를 못 쓴다"?**
> **아닙니다.** 반대로 **연차 사용일에도 출근은 원칙적으로 가능**합니다(확인 후 진행). 오직 **연차 사용촉진(1·2차)으로 지정된 종일 법정연차**일(비휴일)만 출근이 차단됩니다(노무 수령 거부). 또 "회사 휴일(공휴일)"과 "연차 사용일"은 서로 다른 개념입니다. → 자세히는 [C-4](#c-4-연차일-출근-노무-수령-거부--핵심).

## A. 계정·조직·권한 (공통 기반)
🟢 정책서 기반 · PRAFTA·SAFETY NOTE 공통 기반. 출처: `common/`

### A-1 회원가입·로그인·인증
- 정규 회원가입 필수 입력 = 회사코드·아이디(4~10자)·비밀번호(6~15자)·이름·휴대폰·사업장·생년월일. 이메일·성별은 선택. *출처: common/03 §3.1*
- 가입 시 이용약관·개인정보·위치기반 동의는 필수, 마케팅은 선택. 정규 가입은 슬롯 체계와 무관. *출처: common/03 §3.1*
- 로그인은 아이디/비밀번호 + "아이디 저장". 최초 로그인 시 권한에 따라 진입 화면이 분기. *출처: common/03 §3.2*
- 계정 찾기·비밀번호 재설정은 이름+휴대폰 본인인증 후 진행, 재설정 후 즉시 변경 권장. *출처: common/03 §3.3*
- **액세스 토큰 유효 1시간 · 리프레시 토큰 48시간**. 액세스 만료 시 리프레시 유효하면 앱 재실행으로 자동 갱신, 리프레시까지 만료 시 재로그인. *출처: common/03 §3.4*
- 로그아웃·세션/브라우저 종료 시 선점(처리 잠금) 즉시 해제. *출처: common/03 §3.4*

### A-2 계정 상태 (활성화·미사용·탈퇴)
- 세 상태 — **활성화**(전 기능), **미사용**(관리자 비활성화·로그인 차단), **탈퇴**(로그인 차단·이력만 조회). *출처: common/03 §3.5*
- 상태 변경(활성/미사용/탈퇴)은 감사 로그 대상. *출처: common/11 §11.3*

### A-3 사용자 트랙 (정규직 / 일일계정)
- 두 독립 트랙 — 정규 사용자(가입·영구·슬롯 무관) / 일일계정(비정규·유효기간 내 한시·슬롯 점유·만료 시 삭제). *출처: common/04 §4.1~4.2*
- 일일계정 등록 = ①직접가입(URL/QR로 본인 가입) ②관리자 QR 발급. *출처: common/04 §4.3*
- 일용직은 예정 스케줄이 없어 표준화·지각·조퇴 판정이 적용되지 않고, 실근태만 표시(없을 수 있음)를 정상 처리. *출처: common/04 §4.3*

### A-4 일일계정 슬롯 관리
- 사업장별 슬롯 N개 사전 할당, 슬롯 1개 = 일일계정 1개 임시 자리. 모두 점유되면 신규 발급 차단. *출처: common/05 §5.2*
- 전사 슬롯 총량 = 계약 요금제. 마스터관리자가 사업장별 배분(상한=잔여 요금제, 하한=현재 점유 수). *출처: common/05 §5.3*
- 슬롯 구성 = 사업장·슬롯번호·슬롯구분(self/qr)·상태(빈/사용중)·점유 유지(on/off)·점유자·이력. 발급 채널은 사업장 "계정 등록" 토글로 on/off. *출처: common/05 §5.4~5.5*
- **수명 1일** — 발급 당일 자정까지, 자정 배치가 점유 유지 OFF 슬롯을 일괄 만료(계정 삭제+빈 자리 복귀). 화면 표기 24:00, 실제 배치 익일 00:00. *출처: common/05 §5.6.1*
- "점유 유지" ON 슬롯은 만료 배치 제외(다일 고용). 만료 삭제 계정은 복구 불가, 활동 이력은 보존. *출처: common/05 §5.6.2~5.6.3*
- 점유 이력은 최대 1개월(−30일)까지 최신순, 이름·연락처는 마스킹(김○○ / 010-****-1234). *출처: common/05 §5.6.4*
- 사업장 종료일 경과 시 슬롯 비활성화 + 점유 계정 자동 삭제 + 상단 배너. *출처: common/05 §5.7*

### A-5 사업장 관리 (구성·GPS 허용범위)
- 필수 = 사업장번호·명·주소(지오펜스 중심 좌표)·사용여부. 선택 = GPS 허용범위·사업개시/종료일. *출처: common/06 §6.1*
- **GPS 허용범위 = 사업장별 지오펜스 반경(m)**. 0·미설정이면 그 사업장은 지오펜스 판정 미사용. *출처: common/06 §6.2*

### A-6 조직 관리 (조직도·담당 정/부·자체근태승인)
- 조직도는 사업장 단위 독립, 최상위=사업장. 모든 사용자는 정확히 1개 노드 소속(1인 1소속). *출처: common/07 §7.1*
- 노드마다 담당 정(필수)·부(선택) 지정, 지정자의 소속 부서는 그 노드로 자동 변경. *출처: common/07 §7.2*
- 담당 정/부 = 그 노드 소속자에 대한 근태·휴가 승인·안전관리 권한. 복수면 병렬 처리(1명이 처리하면 종결), 동시 처리는 선점으로 방지. *출처: common/07 §7.2*
- **자체근태승인여부** ON = 노드 담당 정/부가 자기 노드 근태 직접 승인 / OFF = 상위 노드로 위임. *출처: common/07 §7.3*
- 소속 사업장 변경은 임의 수정이 아니라 **소속이동(예약제)**으로만 처리한다 → 상세는 A-6b. *출처: WEB_001*

### A-6b 소속이동 (사업장 간 이동) — 예약 → 발효 → 사후 처리
- **즉시 변경이 아니라 예약제** — 관리자(master/HR)가 이동일(**내일 이후만** 지정 가능)을 정해 예약하고, 실제 발효는 **이동일 자정 배치**가 일괄 처리한다. 사용자관리에서 사업장·부서를 직접 고치는 기능은 제거됨(소속이동으로 일원화). 대상은 정규직만(일용직 제외). *출처: WEB_001 확정*
- **예약 불가 5종** — 대상자가 ①사업장 대표관리자 ②조직 노드 담당 정/부 ③점검 담당자 ④교대팀 소속 ⑤(신 사업장 근무시간이 시각을 커버하지 못하는) 미래 시간차 연차 보유 중 하나면 예약이 차단된다(해소 후 가능). 동일인 중복 예약도 차단. *출처: WEB_001-1*
- 예약 등록 즉시 대상자에게 푸시 발송 + 앱 로그인 시 안내 팝업 1회 노출(확인 처리). 안내에는 "진행 중인 결재는 종료 처리됩니다" 고지가 포함된다. *출처: WEB_001-3*
- 발효 시점에 **재검증**(이동할 사업장·부서 실재 + 5종 불가사유 재검사) — 실패하면 그 예약만 발효 실패(사유 기록)로 남고 다른 예약엔 영향 없다. *출처: WEB_001-2*
- 🔵 **[세션·검증됨]** **발효 시 대기 요청 자동 정리** — 이동자가 **신청자든 결재자든** 관련 대기 요청(연차·근태보정·초과근무·스케줄수정)은 전부 자동 반려/종결되고, **연차는 차감이 원복**된다(이동자가 결재자였을 뿐인 제3자 신청 건 포함). 2026-07 라이브 검증 완료. *출처: WEB_001 확정 + QT-11-7 수정 + F1 공유*
- 🔵 **[세션]** **근무계획 이관** — 구 사업장의 발효일 이후(미래) 근무계획은 삭제되고, 신 사업장 기본근무로 발효일부터 연말까지 새로 생성된다(양쪽 중복 방지). 부서만 이동(사업장 동일)이면 삭제하지 않는다. *출처: 2026-07 F7*
- **과거 데이터는 보존** — 발효일 이전의 근태·연차·근무계획은 구 사업장 소속으로 그대로 남고, 화면에서는 사업장 필터로 분리 조회된다(이동 전 데이터 불변). 예: 7/19 이동자라면 7/18까지는 구 사업장, 7/19부터는 신 사업장으로 귀속. *출처: E2E QE-6-4 검증*
- ⚠️ **[현행동작]** **과거 근무계획(스케줄) 수정은 사실상 불가** — 스케줄관리 화면에서 과거 일자 배정·수정은 조용히 건너뛰어진다(silent skip, 명시 정책 없음). 반면 과거 **근태(실적)**는 근태 보정 요청으로 마감 전까지 수정 가능(B-11). *출처: E2E 관찰*
- ⚠️ **[현행동작]** 예약은 정적이다 — 예약 후 이동일에 휴일이 지정되거나 스케줄이 바뀌어도 예약 화면은 감지·경고하지 않는다(발효 시점 재검증만 수행). *출처: E2E QE-6-3*
- ⚠️ **[미결]** 예약 상태의 사용자를 비활성 처리해도 예약이 자동 취소되지 않고 고아로 남는다(정리 정책 미정). *출처: BACKLOG B-13*
- ⚠️ **[기지 결함]** 발효 후 기존 로그인 토큰이 즉시 회수되지 않아, 최대 1시간(액세스 토큰 수명) 동안 구 사업장 소속으로 근태가 기록될 수 있다(미해결). *출처: QT-11-8*

### A-7 권한 체계 (3축 AND·사이트 스위처·마스터)
- **최종 권한 = 세 축의 교집합(AND)** — ①화면 권한(Role×CRUD×플랫폼) ②사업장 권한 ③조직 스코프. 하나라도 막히면 불가. *출처: common/08 §8.1*
- 기본 제공 = 마스터관리자·HR·산업안전관리자 3종 시드. 마스터관리자는 권한 자유 생성·수정(단 마스터 권한은 삭제·비활성 불가). *출처: common/08 §8.2*
- 사업장 권한 = 접근 가능 사업장 매핑(소속은 자동, 그 외는 명시 부여). 복수 보유자는 앱 사이트 스위처로 전환, 전환 시 데이터 완전 격리. *출처: common/08 §8.3*
- 소속 사업장 조회 범위 = 자기 노드+하위, 관리 권한은 담당 정/부만. 타 사업장은 전 부서 조회+부여된 CRUD로 결정. 사업장 간 위계 필드 없음. *출처: common/08 §8.4*
- 마스터관리자는 스코프를 넘어 전 사업장·부서·화면 접근(기본 전 사업장 자동 매핑). *출처: common/08 §8.5*

### A-8 선점 (처리 잠금)
- 관리자가 처리 건을 열면 선점, 선점 중 타 관리자는 읽기만 가능. 완료·로그아웃·세션/브라우저 종료 시 즉시 해제, 타임아웃·강제해제 없음. *출처: common/09 §9.2*
- 적용 = 스케줄 수정·초과근무·연차·근태 보정·시정조치·위험성평가 검토 등 복수 관리자 승인 화면. 마감·해제 같은 단독 액션은 비대상. *출처: common/09 §9.3~9.4*

### A-9 알림 / 공지
- 채널 3종 — 푸시·인앱(배지/토스트)·이메일. *출처: common/10 §10.1*
- 트리거 = 요청 등록→승인권자 / 처리→요청자(사유 포함) / 예정일 도래→리마인더. 오발송 방지(스코프 위반 시 차단·중복 방지). *출처: common/10 §10.2~10.3*

### A-10 보안·개인정보·위치정보·감사로그
- 원칙 = 목적 제한·최소 수집·최소 권한·이력 보존. *출처: common/11 §11.1*
- 위치정보는 출퇴근 시점에만 최소 처리(상시 추적 금지). GPS 미확인은 등록 허용하되 "확인 필요" 관리, 상세 위치 조회는 별도 권한. *출처: common/11 §11.2*
- 감사 로그(누가/언제/무엇을/왜) 대상 = 권한·사업장권한 변경, 조직 변경, 사용자 상태 변경, 다운로드, 상세 위치 조회, 중요 삭제, 일일계정 액션. *출처: common/11 §11.3*
- ⚠️ **[미확정]** PII 암호화 방식·공통 마스킹 규정 본문·보존기간 수치는 정책서에 원칙만 있고 구체 값 미명시(슬롯 이력 기본값만 제시). *출처: common/11 §11*

### A-11 이용약관
- 4종 — 이용약관(필수)·개인정보(필수)·위치기반(필수)·마케팅(선택). 버전 관리, 개정 시 신규 버전 등록·이력 보존. *출처: common/12 §12.1~12.2*
- 필수 약관 개정 시 기존 사용자 재동의 요청, 동의 이력(사용자·약관·버전별 시각) 보존. *출처: common/12 §12.2*

## B. 근태 (출퇴근·근무)
🟢 정책서 기반 · 출처: `attd/` + 2026-07 결함수정(F3·F4)

### B-1·2 근무 유형 · 교대 근무 타입
- 근무 유형 = 근무코드(사업장 내 고유)·근무구간(1/2구간)·근무시간·휴게시간(자동 공제)·사용여부·기본근무여부. 자정 경계 근무 허용, 2구간은 겹침 금지(구간1 종료 ≤ 구간2 시작). *출처: attd/03 §3.1~3.3*
- 근무 유형 삭제는 배정 근로자 없을 때만, 그 외 비활성화. 마감 기간은 소급 미적용, 변경 이력 보존. *출처: attd/03 §3.3*
- 교대 근무 = 근무 유형을 반복 주기로 조합, 적용 시 스케줄 자동 생성. 패턴 수정은 마감 제외·미래만 반영. 각 구간도 1일 2구간 제한. *출처: attd/04 §4.1~4.3*

### B-3·4·5 출퇴근 횟수 · 재출근 · 2구간 선택
- **하루 출근/퇴근은 스케줄 구간 수와 무관하게 최대 2회**. 2회 초과 시도는 차단하고 "초과근무 상신으로 처리" 안내. *출처: attd/05 §5.1, §5.3*
- 재출근(2번째 출근)은 반드시 이전 퇴근 완료 후에만 가능. 이전 퇴근 없이 재출근 시도는 차단(근태 보정으로 해소). *출처: attd/05 §5.2*
- 2구간 스케줄은 출근 시 사용자가 1/2구간 직접 선택(선택=WORK_SEQ). 순서 자유(2구간 먼저·1구간 단독도 허용), 누락분은 마감/보정으로 처리. *출처: attd/05 §5.5*
- **두 구간 동시 열림 금지** — 진행 중(미퇴근) 구간이 있으면 다른 구간 출근 차단(`ATTD_400_081`). 이미 등록한 구간 재출근 금지(`088`). *출처: attd/05 §5.5*

### B-6 GPS 지오펜스 · 미확인 · 외근
- 사업장 GPS 허용범위 기준 판정. 내부=정상, 외부="근무지 외" 태그로 기록하되 정산값 자동 변경 안 함. *출처: attd/07 §7.2*
- GPS 수신 불가·권한 거부여도 출퇴근 등록은 허용하되 **"GPS 미확인(확인 필요)"** 상태 — 근태 마감 차단 사유, 마감 전 보정으로 해소 필수. *출처: attd/07 §7.3*
- ⚠️ **[현행동작]** 지오펜스 밖 출근을 차단이 아니라 **사유 필수 "외근 출근 등록"**으로 우회 허용. 스펙/결함 여부·부정출퇴근 모니터링 연계 여부 미결. *출처: BACKLOG B-12*

### B-7 구간 시각 겹침 금지
- 같은 근무일 안에서 다른 근무 구간(WORK_SEQ)의 출퇴근 시각은 겹칠 수 없음(인접 경계는 허용). 앱 셀프·웹 보정 승인·웹 직접수정 전 경로에서 차단(`ATTD_400_113`). *출처: attd/07 §7.6*
- 근무 계획(스케줄)도 앞뒤 날짜와 시각 겹침 금지(야간 오버나이트가 핵심). 근무일별 최신 적용본(effective-dating)으로 해석, 웹 Attd_05 직접저장·Attd_07 승인에서 차단(`ATTD_400_115`). *출처: attd/07 §7.6.1*

### B-8 오류/누락/중복 · 스케줄 없는 날
- 출근만/퇴근만·순서 이상·3회 이상 기록은 근태 보정으로 확정, 원본 로그는 삭제 없이 보정 이력만 추가. *출처: attd/07 §7.4*
- 스케줄 없는 날도 출퇴근 등록 허용(하루 2회 제한), 그날 근무는 전량 추가근무로 취급 — 상신·승인 필수, 미승인 시 마감 차단. *출처: attd/07 §7.5*
- ⚠️ **[현행동작]** 길이 0 근태(출근=퇴근 동일 분)면 그날 재출근이 영구 차단되고 오도성 얼럿("다른 구간과 겹칩니다")이 뜬다. 차단 유지 여부·문구 개선 미결. *출처: BACKLOG B-11*

### B-9 스케줄 관리 (자동생성·덮어쓰기·경합방지)
- 관리자가 기본 스케줄 설정 → 시스템이 연간 일괄 생성. 기본 스케줄 변경 시 마감 제외·미래에 일괄 반영. *출처: attd/06 §6.1~6.2*
- 🔵 **[세션]** 자동 스케줄 생성 시 **휴일(특정일+반복 휴일)을 제외**(주말뿐 아니라 회사 지정 휴일 포함). 생성 시점 기준이며 과거분 소급 없음. *출처: 2026-07 F3*
- 🔵 **[세션]** 대기 스케줄 수정요청이 있는 날은 관리자가 직접 변경할 수 없고, **잠금 + 사유 alert**로 안내(요청 먼저 처리해야 함). *출처: attd/06 §6.5, 2026-07 F4*
- 미래 덮어쓰기 시 미래 휴가 데이터는 유지. 수동 수정분은 덮어쓰기/유지 옵션 선택. 스케줄은 1일 2구간·겹침 금지. *출처: attd/06 §6.3, §6.6*

### B-10 근태 계산 (표준화·초과근무·휴게공제)
- 정규 근로시간은 스케줄 구간 기준. 실제 출근이 빨라도 정규 시작은 스케줄 시각, 늦으면 지각. 실제 퇴근이 늦어도 정규 종료는 스케줄 시각, 빠르면 조퇴. *출처: attd/10 §10.1*
- **시간 표준화** — 시작/종료 단위 각각 설정(없음/5/10/15/30분). **시작은 올림, 종료는 내림**(예: 30분 단위에서 08:45 출근→09:00). 실제 시각은 유지, 계산에만 반영, 변경 이력 자동 기록. *출처: attd/10 §10.2*
- 초과근무 인정 = 정규 구간 밖 초과분에서 면제 시간 제외 후, 추가근무 표준화 단위로 산정. **인정 범위 = raw 실근태 − 스케줄**(표준화 스케줄 아님). *출처: attd/10 §10.3, 메모리 ot_window_raw*
- 자동 휴게 공제만 운영(수동·예외 승인 없음), 기준 = 정규 근무시간(추가근무 제외), 근무 유형별 설정값. *출처: attd/10 §10.4*

### B-11·12 근태 보정 · 초과근무 사후 상신 기한
- 보정 대상 = 누락/중복/순서 오류/3회 이상, 시간휴가 구간 오류, 일자 귀속(교대/자정), GPS 미확인 해소. 과거·현재만 신청 가능(미래 차단), 진행 중·마감 후 불가. *출처: attd/11 §11.1~11.2*
- 보정 필수 입력 = 대상/일자/구간·수정 내용·사유·증빙. 승인/반려 사유 필수, 이력 보존, 선점 적용. *출처: attd/11 §11.3*
- **초과근무 사후 상신 기한 = 사업장별 근태 마감 전까지**. 과거의 "D+5일" 방식은 폐기. *출처: req-approval/03 §3.2*

### B-13·14 스케줄 마감 · 근태 마감
- 스케줄 마감 = 조직(노드)+월 단위로 스케줄 확정, 마감 후 생성/수정 제한. 마감 권한 보유자만, 변경은 해제→수정→재마감. 스케줄 마감은 근태 마감의 선행 조건. *출처: attd/12 §12.1~12.3*
- 마감 순서 = 스케줄 마감 → 근태 마감. 마감 후 정산이 급여/인사 기준. *출처: attd/13 §13.1~13.2*
- **근태 마감 차단 3조건** = ①미결(대기) 요청 ②GPS 미확인 미해소 ③미승인 추가근무. 각각 승인/반려·보정으로 해소. *출처: attd/13 §13.3*
- 마감 화면 = 조직 트리·월 선택·차단 사유별 미결 현황·바로가기·마감/해제·이력. 마감/해제는 별도 권한(공동 처리 비대상). *출처: attd/13 §13.4*
- ⚠️ **[미확정]** 마감월 OT 신청·승인 게이트 대칭성, 마감월 확정연차 취소·변경 허용 여부는 미결. 마감월 과거일 휴일 지정은 현재 허용(휴일관리는 마감과 독립). *출처: BACKLOG B-7~B-9*

### B-15·16 근태 현황 조회 · 알림
- 마감 전 정산 프리뷰·실시간 현황 관리자 화면 — 사업장·조직·기간 필터, 정규/비정규 분리, 상태별 집계, 사용자 드릴다운, 엑셀 다운로드. *출처: attd/14 §14.1~14.2*
- 알림 트리거 = 요청 등록→승인권자 / 처리→요청자 / 출퇴근·GPS 미확인 안내 / 마감 D-3·D-1 리마인더. *출처: attd/15 §15.1*

## C. 휴가·연차
🟢 정책서 기반 · 출처: `attd/08-leave.md` + 2026-07 결함수정(F2)

### C-1·2 연차 타입 관리 · 법정 부여(7축·촉진)
- 연차 타입(종일·반차·반반차·시간차·하계 등)을 회사가 정의 — 타입 구분(사용자 신청/관리자 부여)·유급/무급·법정/약정·사용 단위·자동부여 기준일·결재 단계·증빙 필수 여부. *출처: attd/08 §8.1*
- 법정 시스템 시드 6종(연차·월차·근속가산·사용촉진·일괄선부여·생일)은 수정·삭제 불가(읽기 전용). *출처: attd/08 §8.5.5*
- 법정 연차 부여 = 회사 단위 **7축 조합 1개**로 정의, 매일 자동 배치, **회사당 활성 정책은 항상 1개**. 7축 = 부여기준·회계연도 시작·첫해 처리·비례 반올림·근속가산·유효기간(12개월 고정)·사용촉진 운영. *출처: attd/08 §8.5.2*
- 1년 미만 근로자는 매월 만근 1일씩 **최대 11일**(법정 의무, 축과 무관). 첫해 월차는 "입사일+1년−1일"에 일괄 소멸. *출처: attd/08 §8.5.4*
- 사용촉진(7축 ⑦=Y)으로 지정된 연차는 출근 차단(노무 수령 거부) 대상 → C-4. *출처: attd/08 §8.5.2, §8.3.1*

### C-3 부여 보호 · 이월/가불 · 입사일 변경
- **기부여 보호(절대 규칙)** — 한 번 발생한 연차는 사후 차감하지 않음(정책·입사일 변경에도). 취소는 삭제가 아니라 "취소 상태"로 소프트 처리, 사용 이력은 절대 삭제 안 함. *출처: attd/08 §8.5.6, §8.5.8*
- 모든 자동 부여는 멱등키로 중복 방지(연 본연차 1회·월 월차 1회·연 근속가산 1회). 부여 상태 4종 = 사용중/소진/만료/취소. *출처: attd/08 §8.5.8*
- 입사일 변경 = 부족분만 보전(권장·절대 안 줄임)/신규만 새 기준/전체 재발급 3방식, 영향 스냅샷+사유 필수 보관. *출처: attd/08 §8.5.6*
- ⚠️ **[미확정]** 연차 가불(마이너스 잔여·이월)은 별도 기획(메모리)에만 있고 통합 정책서 본문에 조문 없음. *출처: 메모리 com-011*

### C-4 연차일 출근 (노무 수령 거부) — ⭐ 핵심
- **연차 사용일에도 출근은 원칙적으로 허용**(확인 팝업으로 안내 후 진행). 자발/약정/포상/비법정 연차, 촉진과 무관한 연차, 촉진이어도 휴일과 겹친 연차, 반차·시간차일 출근은 모두 허용. *출처: attd/08 §8.3.1 / F2*
- **단, 사용촉진(1·2차)으로 확정된 "종일 법정 연차"일(비휴일)만 출근 차단**(노무 수령 거부) — 이 경우 확인 팝업이 아니라 차단 얼럿. 식별 = 촉진 1/2차 + 법정 연차(월차 제외) + 당일 비휴일. *출처: attd/08 §8.3.1 / F2*
- 과거의 "연차일 출근 = 전면 차단" 서술은 개정·폐기됨. 지금은 "촉진 지정분만 차단"이 정식 규칙. 차단은 화면 우회해도 서버가 최종 판정. *출처: attd/08 §8.3.1 / F2*
- 시간 단위 휴가로 승인된 시간대 안에서는 출근·재출근 차단(얼럿만). *출처: attd/08 §8.3.2*

### C-5·6 휴가 신청 · 시간차 환산
- 관리자는 스케줄 화면 "연차 타입 적용"으로 등록, 근로자는 앱에서 신청. 근로자 신청 조건 = **해당 일자에 출근 기록 없음 + 마감 전**(시간 방향·스케줄 유무 무관). *출처: attd/09 §9.4*
- 스케줄 없는 날은 종일 연차만 신청 가능(반차·시간차 불가). 승인 시 차감·출근 차단, 반려 시 미적용. *출처: attd/09 §9.4*
- 사용 단위 = 종일(항상)·반차(0.5일)·시간차(2h/1h/30분). **0.25·0.125 같은 고정 분수는 폐지** → 그날 소정근로시간 기준 동적 환산. 1일 환산 시간은 사용자 스케줄에 비례 자동 계산. *출처: attd/08 §8.5.9*
- 시간→일수 환산은 유한소수로 떨어지게 분모 제한(반올림 오차 방지). 휴게 가로지르는 시간대 선택 불가, 시작 시각은 근무 시간 내로 제한. *출처: attd/08 §8.4~8.5.9*

### C-7 휴일 사후 지정 × 기존 연차 · 잔여 가드
- 🔵 **[세션]** **이미 확정·사용 완료된 연차일이 나중에 휴일로 지정돼도 시스템은 자동 조정하지 않음**(자동 복원·통지·소급 재계산 없음). 화면엔 "연차+휴일" 병기, 필요 시 관리자가 수동 취소/복원. 관리자 자동차감 배정일도 동일 원칙. *출처: BACKLOG A-1·A-2 (G1/G2/G5)*
- 연차 승인 화면은 잔여(부여/사용/잔여)와 충돌(스케줄/휴가/출근)을 영향도로 표시, 부족·충돌 시 경고. *출처: attd/09 §9.6*
- ⚠️ **[미확정]** 종일 연차 확정일이 낀 근무타입 적용일 변경 차단 여부(현재 시간차만 차단), 마감월 확정연차 취소·변경 허용 여부는 미결. *출처: BACKLOG B-5, B-8*

## D. 요청·승인
🟢 정책서 기반 · 출처: `request-approval/` + attd/09 + 2026-07 F1

### D-1 요청 승인 관리 화면 (4탭)
- 통합 승인 화면 = 접수함 + 상세 패널 2분할, **4개 탭(스케줄 수정 / 근태 보정 / 초과근무 / 연차)**, 각 탭에 대기 건수 배지. *출처: req-approval/05 §5.1, §5.3*
- 리스트 컬럼 = 선택/요청자/요청일시/대상 일자/요약/상태/마감(D-N). 마감 D-1↓ 위험(빨강)·D-3↓ 주의(주황). 필터 = 조직·사용자·상태(기본 대기)·기간(기본 30일)·정렬(최신순). *출처: req-approval/05 §5.4~5.5*
- 상세 패널 6섹션 = 메타·검증/제약·Before/After·사유/증빙·관리자 결정·처리 이력. 새 요청 도착 시 즉시 삽입 대신 "새로고침" 토스트. *출처: req-approval/05 §5.7, /07 §7.8*

### D-2·3 스케줄 수정 · 근태 보정 결재
- 스케줄 수정 신청 조건 = 해당 일자 스케줄 존재 + 마감 전(시간 방향 무관). 처리 = 승인/조정 후 승인/반려(사유 필수). 대기 중 관리자 직접 수정 잠금, 승인 시 재계산. *출처: req-approval/06 §6.1*
- 근태 보정 신청 = 마감 전까지만(마감 후 "해제→수정→재마감"). 승인 시 원본 로그 보존+보정 이력만 추가. 조정 후 승인 시 "1일 2구간·2회 출근" 인라인 검증. *출처: req-approval/06 §6.2*
- GPS 미확인이 섞인 보정 승인 시 자동 해소 + "GPS 미확인 해소" 칩 표기. *출처: req-approval/08 §8*

### D-4 초과근무 상신 결재
- 초과근무는 사후(과거·현재)만 — 사전(미래) 차단. 조건 = 해당 일자 출근 기록 1건 이상 + 마감 전, 오늘 근무 중이면 상신 불가. *출처: attd/09 §9.3*
- **사후 상신 기한 = 해당 일자 근태 마감 전까지**("D+5일" 폐기). *출처: req-approval/03 §3.2*
- 유형(연장/야간/휴일)을 저장·표시하지 않고 **단일 '초과근무'로만 관리**(OT_TYPE 폐기). 발생 케이스는 시나리오 설명일 뿐. *출처: attd/09 §9.3.4*
- 처리 = 승인/조정 후 승인(시스템 계산값 기본채움)/반려. 마감 도달 시 차단하고 "근태 보정으로 예외 처리" 링크. *출처: req-approval/06 §6.3, /07 §7.4*

### D-5 연차 상신 결재
- 조건 = 해당 일자 출근 기록 없음 + 마감 전(시간 방향·스케줄 무관). 스케줄 없는 날은 종일만(반차·시간차 불가). *출처: attd/09 §9.4*
- 처리 = 승인/반려뿐(연차는 시간 조정 불가). 승인 시 휴가 적용·출근 차단(일 단위=전일, 시간 단위=구간만). *출처: req-approval/06 §6.4*
- 연차 타입 결재 단계에 따라 1~N단, HR 최종 승인 ON이면 마지막이 HR. 다단은 현재 단계 승인권자에게만 노출. 잔여·충돌 영향도 표시. *출처: req-approval/06 §6.4*

### D-6 승인/반려 공통 규칙
- 승인/반려 사유 필수(반려 10자 이상), 이력 보존. 사후 상신은 사업장 마감 전까지, 마감 후 미결 남으면 자동 마감 금지·지연 표시(강제 마감 없음). *출처: attd/09 §9.5, req-approval/03 §3.2*
- 선점 = 상세 진입 즉시 잠금("처리중 — 관리자명"), 완료·종료 시 즉시 해제. 본인 결재 = 자체근태승인 ON 노드의 본인 건 자동 승인, 상위 공동 처리에선 본인 건 자동 승인 금지. *출처: req-approval/07 §7.2~7.3*
- 충돌 경고(스케줄↔연차↔출퇴근), 시간 조정 후 승인(스케줄/보정/초과만, 연차 제외), 일괄 처리(동일 탭·대기·차단행 제외, 행 단위 성공/실패 분리). *출처: req-approval/07 §7.5~7.7*
- 🔵 **[세션]** **사용자 비활성/탈퇴 시 그가 신청자·결재자인 대기 요청은 자동 반려**(양방향). 잔존 대기요청이 월 마감을 영구 차단하던 교착을 해소. *출처: 2026-07 F1*

- 점검 답 = Y(양호)/N(불량) 두 값. **점검 수행일은 서버가 KST 기준 강제**(현장 즉시 점검이라 과거 지정 불가, 기기 시계·타임존 오류 차단). *출처: 메모리 chklst_workdate*
- 문항 시행일은 일 단위(YYYYMMDD), "시행일이 오늘 이하"인 문항만 점검 대상. 문항 변경 이력(등록/수정/중지/재사용)을 스냅샷으로 남겨 "점검 의무 유무" 증빙. *출처: 메모리 chklst_strdate*
- 확인서 셀 회색 처리 = 셀 일자가 시행일 이전 or 그 시점 문항이 "사용중지"였던 구간(이력 기반). "등록일 이전이면 회색" 규칙은 폐기. *출처: 메모리 chklst_strdate*
- 불량 관리 — **조치해도 원래 답(N)을 Y로 바꾸지 않음**(원천값 불변), 조치는 별도 테이블에만 기록. "조치 여부"는 조치행 존재로 파생. 사진 첨부 지원. *출처: 메모리 050_chklst_defect*
- ⚠️ **[알려진 취약]** 앱 점검 저장이 체크포인트·문항의 사업장 소속·존재를 검증하지 않아 실적 날조·동료 답변 덮어쓰기 가능성 보고(수정 여부 미확인). *출처: 메모리 chklst_workdate*

### F-4 사고관리 (실제 재해)
- ⚠️ **[미커밋]** 재해 1건 등록 시 사고일 기준으로 근태·순회점검·위험성평가·TBM·아차사고 5개를 **스냅샷(확정 사본)**으로 묶어 맥락 구성. 조회 기간 = 점검 1주·위험성평가 3개월·아차사고 3개월·TBM 당일. *출처: 메모리 048_accident*
- 재해자 = 정규직+일용직 모두(사업장 소속 검증). 재해등급(중대/일반산재/신고제외)·처리상태(접수/처리중/종결). 법정 기한 = 발생일 + 1개월. *출처: 메모리 048*
- 웹 관리자 전용, 쓰기는 역할셋 서버 강제(삭제=master/system, 등록·저장=master/hr/safe/system). *출처: 메모리 048*

### F-5 공지사항 · 자료실
- 공지 대상 = 전사(ALL)/사업장(SITE)/부서(NODE). **전사 발행은 master 전용**. 로그인 직후 팝업 캐러셀, 확인 상태(확인/다시 안 봄/열람) 관리. *출처: 메모리 047_notice*
- 공지 수정/삭제는 편집 비번(BCrypt)으로 보호(master 면제, 단 생성은 master도 비번 필수). 첨부 다운로드는 노출 대상 검증(IDOR 차단). *출처: 메모리 047*
- 자료실 = 공지 테이블 공유하되 타입으로 분기, 회사 전체 공통(사업장·부서 귀속 없음). 접근·수정·삭제는 master/hr/safe. *출처: 메모리 053_archive*
- ⚠️ **[정책 공백]** 신규 첨부 업로드 공통 EP 부재로 신규 첨부 등록 비활성, 편집비번 brute-force 가드 미비. *출처: 메모리 047*

### F-6 하도급 (회사 간 연동)
- 🔵 **[세션·미커밋]** 관계는 회사 대 회사 **양방향**(원청/하청 역할 고정 폐기), 방향은 연동 건별 "제공→수신" 속성. 수립 = 회사코드 정확 일치 입력 → 상대사 수락(권한 master/system). *출처: 메모리 subcontract*
- 연동 방식 = **미러(복제+동기화)** — 제공사 사업장·근무타입을 수신사 아래 복제·잠금(수정 불가), 원본 수정 시 전파. 미러 사업장은 셀프가입 불가, 소속이동으로만 배치. *출처: 메모리 subcontract B·C*
- 근태·위험성평가·아차사고 공유 = **요청→승인→스냅샷**(승인 시점 고정, 실시간 배제=파견법 리스크 회피). 근로자 제3자 제공 동의자만 스냅샷 포함(제외자 표기). *출처: 메모리 subcontract D*
- 순회점검 결과 = 쓰기 전파(write-through), 충돌은 "후행 덮어쓰기 + 저장 확인팝업 + 선행자 성명 표시". n차 체인 = 인접 차수만 가시(상위엔 1차로 접힘). *출처: 메모리 subcontract T6·H*
- **연동 해지 = 독립화** — 미러의 출처 링크만 해제해 수신사의 일반 사업장으로 전환(근로자 회수 없음, 스냅샷 소유 유지). 연동 종료 ≠ PRAFTA 사용 종료. *출처: 메모리 subcontract H③*
- ⚠️ **[법률 자문 대기]** 제3자 제공 동의의 위탁/제공 구분, TBM 콘솔의 협력사 직원 성명 표시 근거, 릴레이 번들에서 동의 철회자 데이터 확산. *출처: 메모리 subcontract T4*

### F-7 일용직 계정 · 입장 승인제
- 일용직도 앱 로그인해 정규직과 동일 안전활동(출퇴근·점검·위험성평가·TBM·공지) 사용. 단 정규 쓰기 EP 5종(연차·근태보정·초과·소속이동)은 서버 차단. *출처: 메모리 daily_user_login*
- 만료·비활성 = 로그인 전면 불가(`WORK_EXPIRE_DATE` 경과 시 자정 배치가 만료 처리). *출처: 메모리 daily_user_login*
- 🔵 **[세션·최신]** 과거 "무마찰 재입장"은 **공식 폐기** → **입장 승인제**. 신규가입 또는 만료 후 로그인 시 **승인요청**이 생성되고(계정상태 '04'), 관리자가 웹/앱에서 승인해야 로그인 가능. 일괄 승인 UI 제공, 거부 시 블랙리스트 등록 바로가기. *출처: 메모리 daily_contract_sign*
- 슬롯 점유는 **승인 후 첫 로그인 시점**(승인 시점 아님), 미사용 승인은 당일 자정 만료. *출처: 메모리 daily_contract_sign*
- 블랙리스트 = 관리자가 휴대폰+사유 등록 시 그 번호 셀프가입·재활성 차단(해제된 번호는 통과). *출처: 메모리 daily_blacklist*
- ⚠️ **[현행]** 전일 미퇴근(출근O·퇴근X) 상태로 다음날이 되면 안전활동이 "근무 중에만" 열리도록 게이팅. *출처: 메모리 com_003*

### F-8 일용직 근로계약서 서명
- **계약 구조 = 근로일 당일 1일 단위**(미래 종료일을 박제하지 않음). 오버나이트는 시업일의 1근로일이며, 서명은 승인 사이클당 1회로 하되 갱신 조항으로 일별 성립을 커버한다. *출처: 메모리 daily_contract_sign*
- **계약 성립 요건 = "회사의 노무 수령"**. 로그인·슬롯 점유·체크인만으로는 계약이 성립하지 않는다(명시). 증빙 체인 = 관리자 승인(회사 승낙) → 서명(근로자 동의) → 체크인(일별 성립). *출처: 메모리 daily_contract_sign*
- **서명은 승인 사이클당 1회**. 재서명 트리거 = ①재입장 ②계약서 버전 변경. 계약서 양식은 사업장+버전 단위로 관리한다. *출처: 메모리 daily_contract_sign*
- 서명본 = 서버 합성 + `SHA-256` 무결성, **추가전용(append-only)**. 계약서 양식이 미등록인 사업장은 서명 게이트만 건너뛴다(가입·입실은 진행). *출처: 메모리 daily_contract_sign*
- **[법정]** **계약서 교부 의무**(근기법 §17②) = 앱에서 본인 계약서 열람 필수. **3년 보존**(§42) = 탈퇴 후에도 서명본을 삭제하지 않는다(개인정보 파기 대상에서 제외). 계약 문안은 노무사 검토 권고. *출처: 메모리 daily_contract_sign*
- 🔵 **[세션 확정]** 관리자 QR('02')로 입실하는 근로자의 서명은 **오프라인 서면 계약으로 처리**(시스템 후속 과제 아님). *출처: 메모리 daily_contract_sign R3*
- ⚠️ **[보안 결정 반영]** 계약서 합성본은 무인증 정적 서빙(추측 가능 URL)에 두지 않고 **별도 보호 저장소(uploads-secure)에 분리 저장**(정적 마운트 밖 = URL 도달 불가). 서명 강제 전면 전환(FILE_SIGN_ENFORCE)은 별도 과제. *출처: 메모리 daily_contract_sign SEC-1*
- ⚠️ **[미커밋]** 구현·검증 완료(2026-07-17)이나 **미커밋**, 계약서 관련 마이그레이션(DDL·상태코드·파일타입) 일부 미적용 상태. 라이브 반영은 배포 후 재확인 필요. *출처: 메모리 daily_contract_sign*
