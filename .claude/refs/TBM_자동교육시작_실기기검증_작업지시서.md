- 작성일: 2026-08-23
- 영역: 백엔드(스케줄러, 무수정) + 웹(`Tbm_02.vue`/`TbmSessionConsole.vue`, 관리자 콘솔) + 앱(`TbmEntryView.vue`/`TbmBeforeStartView.vue`, 실기기)
- 모(母)지시서: `.claude/refs/스케줄러_전면_활성화_작업지시서.md` §4-2 #6, §8-3 3차. 8/23 야간 배치 실측 때 대상 세션이 0건이라 **미검증으로 남은 항목**을 실기동으로 채우는 절차서다.
- 대상 계정: **파마리서치**(`CMPNY_CD=DpqyoXhpHsAKhHxymCZP`) — ★실 계약고객(`CONTRACT_YN=Y`), 계정 8명(사업장 00001에 master 1명+일반 4명, 00002에 일반 3명), TBM 이력 0건(첫 사용).

## §0. ⚠️ 위험 고지 (반드시 숙지 후 진행)

이 테스트는 **운영(prod) 백엔드 + 실제 설치된 앱 + 실 계약고객 계정**으로 진행한다. 사용자가 이미 이 환경으로 진행하기로 확정했으나, 아래는 실행 전 재확인 사항이다.

1. **실 PUSH 발송**: 15분 경과 시 입실한 계정의 실제 폰에 `[TBM 교육 시작]` PUSH가 간다. 테스트 대상 계정이 실제 파마리서치 직원이 쓰는 폰이라면 그 직원에게 예고 없는 알림이 갈 수 있다 — 가능하면 관리자/테스트 목적을 아는 사람의 기기로 진행할 것.
2. **정책 문서상 기본값 OFF가 확정 정책**(`policies/safety/02-tbm-session.md` §2.2 "[보류 기능]"). `TBM_AUTOSTART_ENABLED=true`로 켜는 것은 **테스트 환경을 위한 일시적 오버라이드**이며, 상시 운영 전환 승인이 아니다. 검증 후 계속 켜둘지/끌지는 §5에서 별도 결정한다.
3. 늦게 입실하는 사람은 자동 전이 이후 입실이 막힌다(정책 §2.2 부작용) — 테스트 중 다른 파마리서치 사용자가 실수로 이 세션에 들어오지 않도록 유의.
4. 테스트 세션은 파마리서치의 **실 TBM 이력 1호**로 남는다 — §5 정리 단계에서 취소/삭제 여부를 결정한다.

## §1. 사전조건

| 확인 항목 | 방법 |
|---|---|
| `TBM_AUTOSTART_ENABLED=true` | ✅ **이미 적용됨**(08-22 토글 일괄반영에 포함, 서버 파일 71행 확인) — 별도 조치 불필요. 8/23 야간에 로그가 0건이었던 건 게이트가 꺼져서가 아니라 **OPENED 상태 세션 자체가 없어서**(들어와서 처리할 대상이 없으면 로그 자체를 안 남김) |
| 15분 임계 자체는 SQL에 하드코딩(`Tbm02Mapper.xml` `PREP_START_AT <= NOW() - INTERVAL 15 MINUTE`) — **단축 불가**, 실제 15분 대기 필요 | 사전에 시간 확보(관리자+테스터 동시 15분+α 대기) |
| GPS 검증: 세션은 기본 `GPS_VERIFY_TYPE_CD='AUTO'`, 반경 100m — 관리자 GPS와 워커 입실 GPS가 100m 이내여야 함 | 관리자·테스터가 같은 장소에 있거나, 세션 생성 시 GPS 수동확인 옵션을 켤 것(화면에서 선택 가능한지 §2에서 확인) |
| 파마리서치 계정 2개 확보 | ①관리자용: site 00001의 master 계정(TBM 세션 열기 권한 필요 — 이 회사엔 master 외 safe/hr 역할이 없음) ②참석자용: site 00001의 일반사용자 계정 중 1명(테스터 본인 실기기에 로그인) |

## §2. 절차

### 2-1. 웹 — 관리자: 교육준비 시작
1. 파마리서치 **master 계정**으로 웹 관리자 로그인.
2. TBM 메뉴 → `Tbm_02.vue`(세션 목록) → 신규 세션 생성 또는 DRAFT 세션 선택 → `TbmSessionConsole.vue` 팝업 진입.
3. **"교육준비 시작"** 버튼 클릭(`fnPrepare`) → `POST /webApi/tbm02/prepare-session` → 상태 `OPENED` 전이, **입실비밀번호(6자리)** 발급, `PREP_START_AT`=지금.
4. 콘솔에 "자동 교육시작까지" 카운트다운(900초=15분)이 뜨는지 확인 — 발급된 입실비밀번호를 참석자에게 전달.

### 2-2. 앱(실기기) — 참석자: 입실
1. 파마리서치 **일반사용자 계정**으로 실기기 앱 로그인.
2. TBM 진입 화면(`TbmEntryView.vue`)에서 **입실 비밀번호 입력**란에 2-1에서 받은 6자리 입력 → 입실 처리(`POST /appApi/tbm/enter`, GPS 동봉).
   - ⚠️ 화면에 "QR 스캔으로 입실" 버튼이 보이지만 **미구현 스텁**이다("QR 입실은 준비 중입니다" 토스트만 뜸) — 반드시 **비밀번호 입실**로 진행한다.
3. 입실 완료 후 `TbmBeforeStartView.vue`(대기 화면)로 이동 확인.

### 2-3. 대기 — 15분
- 이 앱 화면은 **폴링·푸시 자동감지가 아니다**. 15분 전에 "새로고침" 버튼을 눌러도 세션 상태는 갱신되지 않는다(참석자 목록만 갱신).
- 15분 경과 전까지는 그냥 대기(웹 콘솔 카운트다운으로 시간 확인).

### 2-4. 15분 경과 후 — 자동전이·PUSH 확인
1. **웹 관리자 콘솔**: 카운트다운 0 도달 시 콘솔이 세션 상세를 1회 자동 재조회한다 — 상태가 `IN_PROGRESS`로 바뀌는지 확인(§4-2 #6 판정 근거).
2. **앱(참석자 실기기)**: `[TBM 교육 시작]` / "참여 중인 TBM 교육이 시작되었습니다." PUSH 수신 확인(§8-3 3차 판정 근거) — 캡처.
3. PUSH를 탭하면 라우팅되는지 확인. 만약 탭 없이 확인하려면 `TbmBeforeStartView`에서 **"시작하기"** 버튼을 눌러 `GET /appApi/tbm/sessions/{sessionCd}/state`가 `IN_PROGRESS`를 반환하고 `TbmInProgressView`로 이동하는지 확인.

## §4-1. 실기기 검증 결과 (2026-08-23, 파마리서치 실계정·실기기)

**§3 완료 기준 충족**: OPENED→IN_PROGRESS 자동 전이 정상 작동(15분 경과 후 확인), 실기기 PUSH 수신 확인.

검증 중 결함 2건 발견 → **수정 완료(compileJava·backend test 전체 통과, 미배포)**.

1. **관리자 콘솔 카운트다운 즉시 만료 표시(전 플랫폼 공통, iOS/Android 무관)**
   - 원인: `AppAdminTbmServiceImpl.computePrepAutoStartAt()`가 `prepAutoStartAt`을 타임존 표기 없이 반환. `PREP_START_AT`은 DB 서버 `NOW()`(운영 EC2/RDS 시스템시각=UTC) 기준인데, 클라이언트(`AdminTbmPrepView.vue`)가 이를 기기 로컬시각(KST)으로 오인 파싱 → 실제보다 9시간 이른 시각으로 계산돼 세션 생성 직후부터 카운트다운 없이 "곧 교육이 시작돼요..." 표시.
   - 실제 15분 자동전이(서버 내부 판정, `PREP_START_AT`·`NOW()` 전부 DB 서버 기준 동일 프레임)에는 영향 없음 — 순수 표시 버그였음.
   - 수정: `computePrepAutoStartAt()` 반환값에 `Z`(UTC 명시) 접미사 추가. 프론트(`target.replace(' ','T')`)는 무수정으로 정상 파싱됨(`prepAutoStartAt` 소비처가 이 파일 1곳뿐임을 확인).
   - 파일: `AppAdminTbmServiceImpl.java:1880-1898`.

2. **자동전이(IN_PROGRESS) 이후 기입실 근로자 재진입 불가(TBM_409_030)**
   - 원인: `AppTbm01ServiceImpl.enter()`의 `STATUS_OPENED` 단일 검증이 기입실 멱등 분기보다 앞에 있어, 세션이 `IN_PROGRESS`로 전환되는 순간부터 **이미 입실한 근로자의 재인증(교육중 탭 재진입)까지 함께 차단**됨. 데이터 유실은 없음(`TB_TBM_ATTENDANCE` 정상 유지) — 재진입 API 호출 자체가 항상 409로 막히는 문제.
   - 수정: 상태 게이트를 (OPENED∪IN_PROGRESS 살아있으면 통과) → 비밀번호 검증(기존 순서 유지, 우회 방지) → 기입실 멱등 분기(OPENED/IN_PROGRESS 무관 통과) → **신규 입실만** OPENED 단독 재검증(지각 신규입실 차단 정책 §2.2 그대로 유지) 순으로 재배치.
   - 파일: `AppTbm01ServiceImpl.java:186-215`.

**잔여**: 배포(웹 무변경, 백엔드만 — `deploy-backend.ps1`) + 배포 후 재검증(같은 세션 또는 신규 세션으로 재진입 확인) 사용자 승인 대기.

## §5. 정리(필수)

1. 테스트 세션 취소 또는 삭제(고객 이력에 테스트 흔적 최소화) — 웹 콘솔에서 세션 취소 처리.
2. `TBM_AUTOSTART_ENABLED`를 검증 후에도 계속 켜둘지 끌지 **사용자 결정** — 계속 켜두면 파마리서치 외 다른 실 고객사에도 즉시 적용됨을 인지할 것(회사별 게이트가 아니라 전역 게이트).
3. 결과를 메모리 `project-prafta-scheduler-inventory-and-prod-gates`에 반영, 모지시서 §8-3 3차 항목 체크.
