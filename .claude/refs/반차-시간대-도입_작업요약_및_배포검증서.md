## 1. 개요

### 1-1. 무엇을 했나

반차(사용단위 `'01'`)에 **실제 시각**을 부여하고, 그 시각을 근태 판정 전 영역에 반영했다. 동시에 반반차(`'05'`)를 폐지해 사용단위를 **종일 / 반차 / 2시간 / 1시간 / 30분 5종**으로 정리했다.

### 1-2. 왜 필요했나

반차는 신청 시 시각을 기록하지 않았다(`TB_USER_LEAVE_USE.START_TIME/END_TIME` = NULL). 차감 계산(`dailyStd / 2`)은 있었으나 **근태 집계 쿼리가 그 값을 아무도 읽지 않았다.** 결과적으로 반차일이 근태상 "평범한 근무일"로 취급되어 아래 5개 결함이 있었다.

### 1-3. 왜 지금이었나

- 운영 데이터가 **전부 테스트 데이터**(서비스 신고 전) → 과거 데이터 백필이 발생하지 않는 유일한 시점
- 반반차 운영 사용 **0건**, 반반차를 켠 회사 **0곳** → 마이그레이션·공지 불요
- iOS 심사 승인·앱스토어 등록 완료(2026-08-07), **실사용자 0명**, 대기 중인 첫 고객 1곳 → 리팩터링 비용이 가장 싸고 대안 비용이 가장 비싼 시점

## 2. 작업 전 → 작업 후

### 2-1. 핵심 규칙 — 반차 경계 산출

**"근로 누적 시간"으로 자른다. 휴게는 누적에서 제외되므로 경계 시각이 그만큼 뒤로 밀린다.**

```
그날 실근로분 D = Σ(구간 종료 − 구간 시작 − 구간 휴게)
반차 면제분 H  = D / 2   (정수 절사 — 차감 leaveMinutes 와 동일 규칙)
경계          = 근무 시작부터 근로를 누적해 H 에 도달하는 시각 (휴게 구간은 건너뛰며 누적)

시작기준 반차 = [근무시작, 경계) 를 쉬고 경계부터 근무   → "늦게 출근"
종료기준 반차 = 경계까지 근무하고 [경계, 근무종료) 를 쉼 → "일찍 퇴근"
```

**산출 예시 (검증 실측값)**

| 스케줄 | D | H | 경계 |
|---|---|---|---|
| 09:00~18:00, 휴게 11:30~13:00 | 450 | 225 | **14:15** |
| 09:00~18:00, 휴게분 60 · **휴게시각 NULL** (운영 최다 패턴) | 480 | 240 | **13:00** |
| 09:00~14:00 + 18:00~22:00 (2구간) | 540 | 270 | **13:30** |
| 22:00~04:30 (야간) | 390 | 195 | **01:15 (익일)** |
| D = 451 (홀수) | 451 | **225** (절사) | 12:45 |

### 2-2. 결함 D1~D5 해소

| ID | 작업 전 | 작업 후 |
|---|---|---|
| **D1** | **지각·조퇴 100% 오판정 + 관리자 PUSH 오발송.** 시작기준 반차자가 13:00 출근 → "지각 240분", 종료기준 반차자가 13:00 퇴근 → "조퇴 300분" | 반차 시각을 반영한 유효 소정 구간으로 판정. **6개 판정 경로 전부 동일한 답**(§6). 허위 PUSH 소멸 |
| **D2** | **결근 오계상.** 반차 쓰고 나머지 절반 무단 이탈 시 `연차 0.5일 + 결근 1일` = 하루에 1.5일 계상 | **결근을 분(minutes)으로 계상.** `결근분 = max(0, D − 면제분)`, 출근기록 있으면 0. 표기는 `0.5일 (3시간 45분)` |
| **D3** | **주52 소정 과대.** 반차일도 480분 전량 계상. **종일 연차일도 전량 계상** | `일자별 소정 = max(0, planned − 면제분)`. 종일 연차일도 제외 |
| **D4** | **반차 구간 근무의 무검증 공존.** 시각이 없어 검증 술어를 만들 수 없었음 | 겹침 검증에 반차 편입(`ATTD_400_112`) |
| **D5** | **2구간 OT 전량 인정.** 종료기준 반차 후 15:00~19:00 재출근 시 스케줄 NULL → **240분 전액 OT**(실제 연장 60분) | `allowed = actual − (schedule ∪ leaveExempt)` **합집합** 연산으로 **60분**만 인정 |

★ D5 는 지시서 문언("스케줄 구간에서 반차 쉬는 구간을 **제외**")대로 하면 고쳐지지 않는다. 2구간 스케줄이 `null` 이라 뺄 것이 없고, 빼면 OT 가 오히려 늘어난다. **필요한 연산은 합집합이다.**

### 2-3. 반반차 폐지

- `TB_LEAVE_USAGE_POLICY.USAGE_UNIT` 허용값에서 `QUARTER_DAY` 제거, 서버가 `HALF_DAY` 로 **축소 정규화**(`FULL_DAY` 로 떨어뜨리면 기존 반차까지 막힌다)
- 코드값 `SYS025 '05'` → `USE_YN='N'` **비활성만, 행 삭제 금지**(과거 데이터 조회 시 코드명 필요)
- 신청·검증 경로에서 `'05'` 제거, **조회·표시 경로는 방어적으로 존치**
- 클라가 `'05'` 를 직접 제출해도 `ATTD_400_102` / `ATTD_400_054` 로 거부(fail-closed 확인)

## 7. 결함 발견·수정 이력 — 같은 계열이 3라운드 반복된 이유

배포 전 검증 시 **왜 이 작업이 4라운드나 돌았는지** 알아야 판단이 되므로 남긴다.

### 7-1. 결함 계열의 뿌리

```
연차 시각을 절대 시각으로 환산하는데 그날 스케줄을 프레임으로 쓰지 않았다.
```

`'2200'~'0200'` 은 "종료 < 시작"이라는 신호가 있어 자정 넘김을 알 수 있다.
그러나 **`'0115'~'0430'`(양 끝이 모두 자정 이후)은 행 안에 신호가 없다.** 그 정보는 스케줄에만 있다.

### 7-2. 반복 경과

| 라운드 | 결함 | 지점 | 조치 |
|---|---|---|---|
| 1차 sec | **M-1** | Attd_13 이동이 `END_DATE` 를 평탄화 → 면제구간 소실 → OT 과다 | Q5 저장 규약 정정으로 소멸 |
| 2차 qa·sec **독립 동시 발견** | **N-1** | 야간 **종료기준** 반차 stamp 가 **정확히 1440분 앞** | 스케줄 프레임 필수화 |
| 2차 sec | N-2 | 겹침 SQL wrap 비대칭 | SQL 삭제 → Java 이관 |
| 2차 qa | N-2 | 앱 지각 판정·**허위 PUSH** (야간 시작기준) | 프레임 이식 |
| 4차 qa | NF-1·NF-2 | **판정 경로 3곳이 더 있었다** | 전부 편입 |

### 7-3. 어떻게 끊었나

3차에서 개별 패치를 중단하고 **구조를 바꿨다**:

1. **단일 진입점** — `exemptStampRange(leaveStart, leaveEnd, List<ScheduleSegment>)`. 내부는 기존 `alignLeave`(당일/익일 후보 중 스케줄 겹침이 큰 쪽 채택) 재사용
2. **스케줄 프레임을 필수 위치 인자로** — 스케줄 없이 환산하는 오버로드를 **남기지 않았다**(남기면 다음에 또 그걸 쓴다)
3. **소비처 전수 감사 후 이관** — qa 가 developer 의 배제 판정을 신뢰하지 않고 재감사(`TB_USER_LEAVE_USE` 참조 매퍼 37개 추적) → 우회 경로 0 확인
4. **fail-open → fail-closed** — 스케줄을 못 얻으면 스킵(= OT 과다 인정)하던 것을 **그날 OT 거부 + WARN** 으로 전환

★ 해법은 원래 코드베이스에 있었다. `alignLeave` 가 지각·조퇴 경로를 정확히 처리해 왔고, **그 유틸을 안 거치는 소비처만 뚫렸던 것**이다.

개발·운영 양쪽 적용 확인. 재확인이 필요하면:

```sql
-- 전부 0 이어야 한다
SELECT COUNT(*) FROM TB_USER_LEAVE_USE      WHERE USE_UNIT_TYPE='05' AND DEL_YN='N';
SELECT COUNT(*) FROM TB_LEAVE_USAGE_POLICY  WHERE USAGE_UNIT='QUARTER_DAY';
SELECT COUNT(*) FROM TB_LEAVE_TYPE_MGMT     WHERE USE_UNIT_TYPE='05';

-- 'N' 이어야 한다
SELECT USE_YN FROM TB_SYST_VAL_D WHERE SYST_VAL_CD='SYS025' AND SYST_VAL_D_CD='05';

-- 컬럼 정의가 아래와 같아야 한다 (MODIFY COLUMN 으로 인한 정의 유실 확인)
--   USAGE_UNIT     varchar(20) NOT NULL DEFAULT 'FULL_DAY'  utf8mb4 / utf8mb4_unicode_ci
--   ALLOW_QUARTER  char(1)     NOT NULL DEFAULT 'N'         utf8mb4 / utf8mb4_unicode_ci
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, CHARACTER_SET_NAME, COLLATION_NAME
  FROM INFORMATION_SCHEMA.COLUMNS
 WHERE TABLE_SCHEMA=DATABASE() AND TABLE_NAME='TB_LEAVE_USAGE_POLICY'
   AND COLUMN_NAME IN ('USAGE_UNIT','ALLOW_QUARTER');
```

★ Workbench 에서 `UPDATE ... WHERE USAGE_UNIT = 'QUARTER_DAY'` 는 **Error 1175**(safe update mode)가 난다. KEY 컬럼이 아니기 때문이다. **선행조건이 0이면 그 두 UPDATE 는 건너뛰면 된다**(0행 갱신). 굳이 실행하려면 `SET SQL_SAFE_UPDATES=0/1` **세션 토글만** 쓰고 Preferences 영구 해제는 하지 말 것.

### 10-2. ★ 운영 DB 확인 — 미실행 (사용자 조치)

**fail-closed 전환 때문에 필요하다.** 아래가 0행이 아니면 그 사용자에 한해 OT 등록이 거부된다.

```sql
-- "확정 부분연차인데 그날 스케줄이 없는" 행 — 0행이어야 한다
SELECT L.CMPNY_CD, L.SITE_CD, L.USER_CD, L.START_DATE, L.USE_UNIT_TYPE, L.START_TIME, L.END_TIME
  FROM TB_USER_LEAVE_USE L
  LEFT JOIN TB_USER_WORK_PLAN P
    ON P.CMPNY_CD=L.CMPNY_CD AND P.SITE_CD=L.SITE_CD
   AND P.USER_CD=L.USER_CD  AND P.WORK_YMD=L.START_DATE
  LEFT JOIN TB_SCH_MGMT M
    ON M.CMPNY_CD=P.CMPNY_CD AND M.SITE_CD=P.SITE_CD AND M.SCH_CD=P.WORK_PLAN_CD
 WHERE L.DEL_YN='N' AND L.LEAVE_STATUS='CONFIRMED'
   AND L.START_TIME IS NOT NULL AND L.END_TIME IS NOT NULL
   AND L.USE_UNIT_TYPE IN ('01','02','03','04')
   AND (P.USER_CD IS NULL OR P.WORK_PLAN_CD IS NULL OR P.WORK_PLAN_CD=''
        OR M.SCH_CD IS NULL OR M.FST_SCH_STR_TIME IS NULL OR M.FST_SCH_STR_TIME=''
        OR M.FST_SCH_END_TIME IS NULL OR M.FST_SCH_END_TIME='');
```
**개발 DB 는 0행 확인 완료.** 0행이 아니면 그 날짜의 스케줄을 먼저 복구할 것.

## 13. F-7 잔여 문구 정정 (2026-08-08, 미배포)

실기기 시나리오 작성 중 발견. **`Attd05ServiceImpl` 한 곳이 아니라 3곳**이었고, F-7 이 고친 헬퍼 자신이 같은 결함을 갖고 있었다.

### 원인 — 이번 작업이 전제를 깼다

미결 잠금 술어는 `REQ_TYPE='05' AND REQ_STATUS='01' AND START/END_TIME NOT NULL` 이다.
설계 당시 주석은 이렇게 적고 있었다:

> 시각 보유 = **시간차만** — 반차·반반차·종일 신청은 시각 미기록이라 자연 제외 (F-F 실측 술어)

**반차에 경계 시각을 부여한 이번 작업이 이 전제를 무효화했다.** 미결 반차가 술어에 걸리기 시작했고, 술어는 그대로 두는 것이 맞다(미결 반차도 스케줄을 잠가야 한다). 틀린 것은 **안내 문구**뿐이다.

F-7(2026-08-06)은 `ATTD_400_164` 의 **확정** 분기만 고쳤다. **미결** 분기와 `Attd_05` 직접 저장 경로는 손대지 않았다. 그래서 "반차로 막힌 관리자가 존재하지 않는 시간차를 찾는" 동일 오안내가 **이번 배포부터 미결 반차에서 재발**할 상태였다.
