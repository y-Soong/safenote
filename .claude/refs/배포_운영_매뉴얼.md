```

    ↓ 검증 완료 시
```

## 1. 백엔드 배포 (Spring Boot → EC2)

### 표준 절차 (스크립트 — 권장)

```powershell
cd C:\PRAFTA\PRAFTA\prafta-backend
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-backend.ps1
```

옵션:
| 옵션 | 용도 |
|---|---|
| `-Ref origin/develop` | 특정 브랜치 배포 (개발 WAS 생기면) |
| `-Ref <커밋해시>` | 특정 커밋 배포 = **이전 버전 롤백 수단** |
| `-UseWorkingTree` | (비상용) 로컬 작업 트리 그대로 배포 |

스크립트가 자동으로: fetch → worktree 빌드 → `.new` 업로드 → 기존 JAR `.prev` 백업 → 재기동 → 헬스체크 → **실패 시 자동 롤백** → 커밋 해시 기록.

결과 해석:
- 초록 "배포 완료" = 끝.
- 노랑 "롤백 성공" = 신규 버전 문제로 이전 버전 자동 복구됨. 서비스는 정상. 로그로 원인 확인.
- 빨강 "수동 조치 필요" = 롤백도 실패. 아래 완전 수동 절차로 대응.

⚠️ **신규 마이그레이션 SQL 이 있으면 반드시 백엔드 배포 전에 §4 절차로 선적용** (Flyway 도입 전까지).

## 3. 앱 배포 (Flutter APK + 내장 Vue)

앱은 Flutter 셸 + 내부 webview Vue(`prafta-app-frontend`) 하이브리드. Vue 콘텐츠는 원격 호스팅(`app.prafta.com`)이며 **2026-08-20 롤아웃 3단계(매니페스트 `enabled:true` = 전원 원격) 전환 완료**다. 따라서 **Vue 쪽 수정은 §3-1 원격 배포만으로 반영**되고 APK/AAB 재빌드가 필요 없다. 셸(Flutter/`lib/`) 수정만 스토어 재배포 대상이다. 앱 내 번들(`assets/vue_app/`)은 원격 장애 시 폴백 바닥이므로 **스토어 릴리즈 빌드 직전에만** 동기화한다.

### ⚠️ 한시 운영 규칙 — 일용직 계약서 PDF 양식 (2026-07-28 ~ 앱 스토어 배포 수렴 시점)

**앱 스토어 배포가 수렴하기 전까지 운영에서 일용직 계약서를 PDF 로 올리지 말 것.** 대상 행위 3종 전부:

| 금지 대상 | 화면 |
|---|---|
| 신규 **등록** | User_07 계약서 관리 → [등록] |
| **교체**(새 버전) | User_07 → [등록] (활성 존재 시) |
| **정정**(파일 제자리 교체) | User_07 → [정정(버전 유지)] |

이유: 구버전 앱은 PDF 를 읽을 수 없어 서버가 **전 페이지를 세로로 이어붙인 단일 PNG** 로 폴백 변환한다(그래야 구버전 앱 사용자의 로그인이 막히지 않는다). 이 변환이 20페이지 문서에서 단건 100MB 이상 힙 + 수 초 CPU 를 쓰고 **동시성 제한이 없다**. 출근 시각(07~08시) 동시 로그인과 겹치면 백엔드(t3.small, 기본 최대 힙 약 512MB) 전체가 지연·OOM 될 수 있다.

폴백은 **PDF 양식을 등록한 사업장에서만** 개입한다 → PDF 를 올리지 않으면 이 부하는 아예 발생하지 않는다. 이미지 양식·기존 서명본은 영향 없다.

- 근거: `작업지시서_계약서-멀티페이지-PDF지원.sec.md` SEC-2 / `작업지시서_계약서-승인시점-버전확정.sec.md` SEC-10
- 해제 조건: 앱 AAB 스토어 배포 후 구버전 사용자가 수렴하면 해제. 또는 폴백 결과 캐시·세마포어를 코드에 반영하면 조기 해제 가능
- 참고: **정정도 금지 대상**이다. 정정 EP 는 등록과 같은 업로드 검증을 재사용하므로 PDF 가 통과하며 형식 변경을 막는 코드 게이트가 없다(SEC-10)

### 표준 절차

```powershell

powershell -ExecutionPolicy Bypass -File .\scripts\build-apk.ps1 -BaseUrl "https://api.prafta.com"
# 산출물: build\app\outputs\flutter-apk\app-release.apk (~63MB)
```

- `build-apk.ps1` 이 Vue 빌드→assets 동기화→APK 빌드를 처리. Vue 만 갱신하려면 `scripts\sync-vue-app.ps1` 참조.
- ⚠️ `-BaseUrl` 누락 금지 — APP_BASE_URL 이 주입 안 된 APK 는 서버에 붙지 못한다.
- ⚠️ `assets/vue_app/` 하위를 직접 편집 금지 — 항상 `prafta-app-frontend` 에서 빌드 후 동기화.

## 3-1. 앱 프론트(웹뷰 콘텐츠) 원격 배포 (★2026-08-04 신설)

웹뷰 콘텐츠(`prafta-app-frontend`)를 `app.prafta.com`(S3+CloudFront)에 원격 호스팅한다. 셸은 기동 시 매니페스트(`app-manifest.json`)를 읽어 원격/번들을 판정하고, 원격 실패 시 앱 내 번들로 자동 폴백한다. 배경·롤아웃 단계·테스트는 `.claude/refs/앱_웹뷰_원격로딩_전환_작업지시서.md` §4·§7-8 참조.

> **현 상태: 롤아웃 3단계 완료 — 매니페스트 `enabled:true` (전원 원격).** 2026-08-20 전환, iOS·안드 실기기 검증 통과. 아래 명령으로 배포하면 사용자 앱 재기동 시 즉시 반영된다.
>
> ★ 전체 배포 시 스위치를 생략하면 **라이브 `enabled` 값을 승계**한다(스크립트가 배포 전 라이브 매니페스트를 조회). 종전처럼 생략이 곧 `enabled:false` 가 아니다 — 평상시 콘텐츠 배포가 전 사용자를 번들로 되돌리던 사고 경로를 막기 위한 변경(2026-08-20). 의도적 전환은 `-RemoteEnabled` / `-RemoteDisabled` 를 명시한다.

### 평상시 배포 (git 커밋된 코드만 나감 — 스크립트 권장)

```powershell
cd C:\PRAFTA\PRAFTA\prafta-app-frontend\prafta-app-frontend
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-app-web.ps1 -DistributionId E20RXW16D6VDSN
```

- 옵션은 웹 배포와 동일(`-Ref`, `-UseWorkingTree`, `-SkipInvalidation`) + `-RemoteEnabled`/`-RemoteDisabled`(매니페스트 `enabled` 명시 전환, 생략 시 라이브 값 승계) + `-ManifestOnly`(아래 킬 스위치).
- 스크립트가 자동으로: worktree 에서 `npm ci`+빌드 → `__APP_BUILD__` 배포 식별자 주입 → `app-manifest.json` 생성 → S3 업로드(index.html·매니페스트=no-cache, 해시 청크=장기캐시) → CloudFront 무효화 → 라이브 검증 → 배포 이력 기록.
- `-DistributionId` 는 기본값이 `E20RXW16D6VDSN` 이다(2026-08-20 반영 — 종전 빈 기본값이라 킬 스위치 명령이 무효화를 건너뛰던 결함). 매니페스트는 `no-store` 여도 CloudFront 가 캐싱하므로 **무효화 없이는 엣지에 구 매니페스트가 남는다.**
- 반영 확인: 앱 마이페이지 하단 빌드 정보의 `remote/bundle` 표기 + 배포 해시.

### 킬 스위치 (원격 긴급 중단 — 앱 업데이트 불필요)

원격 배포에 문제가 생기면 매니페스트만 즉시 재배포해 **전 사용자를 번들 폴백으로 되돌린다**:

```powershell
cd C:\PRAFTA\PRAFTA\prafta-app-frontend\prafta-app-frontend
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-app-web.ps1 -ManifestOnly -DistributionId E20RXW16D6VDSN
```

- `-ManifestOnly` = 빌드·에셋 업로드 생략, 매니페스트만 `enabled:false` 로 재배포(수 초 내 반영). 앱은 재기동 시 번들로 폴백한다.
- 원격 재개: `-ManifestOnly -RemoteEnabled` (킬 스위치만 다시 ON).

### 롤백 3단계

| 상황 | 조치 | 소요 |
|---|---|---|
| 원격 Vue 에 결함 | 이전 커밋 재배포: `deploy-app-web.ps1 -Ref <이전커밋해시> -DistributionId E20RXW16D6VDSN` | 수 분 |
| 원격 자체가 불안정 | 킬 스위치: `-ManifestOnly` (→ `enabled:false`) | 즉시 |
| 매니페스트/호스트 장애 | 앱이 자동으로 번들 폴백 | 자동 |

⚠️ **셸(Flutter)의 로딩 로직 자체가 결함이면 위 3단계로는 못 되돌린다 — 앱 업데이트(스토어 배포)가 필요하다.** 셸 로딩 로직 변경은 반드시 지시서 §7 테스트 전량 통과 후 배포할 것.

## 4. DB 운영 (RDS MySQL)

### 접속 방법

RDS 는 퍼블릭 액세스가 없다. **백엔드 EC2 를 경유**해서만 접속:

```bash
ssh -i C:/Users/dudjs/.ssh/prafta-key.pem ec2-user@3.38.237.103
mysql prafta        # 접속정보는 ~/.my.cnf 에 저장돼 있어 인자 불필요
```

- Workbench 접속: **Standard TCP/IP over SSH** — SSH 호스트 `3.38.237.103:22`/`ec2-user`/pem 키, MySQL 호스트 `prafta-db.cj2yeu0mepo8.ap-northeast-2.rds.amazonaws.com:3306`, 계정 `prafta`. 연결 이름을 "PRAFTA-운영(주의)" 처럼 명확히 할 것.
- 로컬 개발 DB 와 운영 DB 는 별개다. Claude 세션의 MCP `prafta-mysql` 은 **로컬 DB** 를 본다 — 운영 DB 를 보고 있다고 착각하지 말 것.

### 스키마 변경(마이그레이션 SQL) 적용 절차

1. **사전 스냅샷**: RDS 콘솔 → `prafta-db` → 작업 → 스냅샷 생성 (되돌릴 지점 확보)
2. SQL 파일 업로드: `scp -i <키> migration.sql ec2-user@3.38.237.103:/tmp/`
3. 적용: `mysql prafta < /tmp/migration.sql`
4. 검증 후 `/tmp` 의 SQL 파일 삭제
5. 백엔드가 새 스키마를 요구하면 **백엔드 배포와 순서 조율** (통상: 하위호환 스키마 먼저 적용 → 백엔드 배포)
※ Flyway 도입은 보류됨(2026-07-20 결정 — Workbench 직접 연결 + 안전장치로 운영). 스키마/데이터 변경은 본 수동 절차 또는 Workbench 터널 접속으로 처리한다.

### 주의사항 (과거 사고 이력 기반)

- `lower_case_table_names=1` 파라미터 그룹(`prafta-mysql80-params`) 필수 — **인스턴스 생성 시에만 지정 가능**. 인스턴스 재생성할 일이 있으면 반드시 이 파라미터 그룹으로.
- 함수/프로시저 로드는 `log_bin_trust_function_creators=1` 필요 + 덤프의 `DEFINER` 절 제거 필요.
- 백업: 자동 백업 보존 **1일** (무료 플랜 제한 — 유료 전환 시 7일로 확대 예정). 중요 작업 전에는 수동 스냅샷을 찍을 것.

## 5. AI 스택 운영 (EC2 `prafta-ai` — 평소 중지)

### 시연 때 켜기

1. EC2 콘솔 → `prafta-ai` → **인스턴스 시작**
2. **1~2분 대기** → 끝. (docker 자동기동 + `restart: unless-stopped` + TEI 모델 캐시 → pgvector·TEI 자동 준비, 백엔드 재연결 자동 — 설정 변경·재기동 불필요)
3. 확인(선택): 백엔드 EC2 에서 `curl -s http://172.31.52.160:8090/health` (TEI)

### 시연 끝나면 끄기

- EC2 콘솔 → `prafta-ai` → **인스턴스 중지** (디스크 요금 ~$4/월만 발생)
- ⚠️ **종료(Terminate) 아님!** 중지(Stop)만 할 것.

### 참고

- 프라이빗 IP `172.31.52.160` 은 stop/start 해도 불변 — 백엔드 설정 변경 불필요.
- LLM(HCX) 호출만 끄고 싶으면: 백엔드 시크릿 `AI_LLM_ENABLED=false` + 백엔드 재기동
- 스택 위치: AI EC2 `/home/ec2-user/prafta-ai-stack/` (docker-compose). 코퍼스 50,378청크 적재됨.
- 회사별 AI 토큰 쿼터(월 80만 기본)는 07-19 배포 완료 — sysadmin Platform_03 에서 관리. 소진 회사는 AI 4종 차단됨.

## 6. 인증서·인프라 유지보수

### HTTPS 인증서 (Let's Encrypt, origin.prafta.com)

- **자동갱신**: `certbot-renew.timer`(systemd) + **DNS-01**(Cloudflare API hook) — 2026-07-19 구성. 80 포트 불필요.
- 상태 확인:
  ```bash
  sudo certbot certificates                  # 만료일 확인
  systemctl list-timers | grep certbot      # 타이머 동작 확인
  sudo certbot renew --dry-run              # 갱신 사이클 검증 (실제 갱신 안 함)
  ```
- 구성 요소: 훅 `/usr/local/bin/certbot-cf-{auth,cleanup}.sh`, 토큰 `/etc/letsencrypt/cloudflare-token`(600, 로컬 사본 `C:\PRAFTA\secrets\cloudflare-dns-token.txt`)
- Cloudflare 토큰을 재발급(폐기)하면 갱신이 깨진다 — 재발급 시 서버 토큰 파일도 교체할 것.
- ⚠️ pip 로 certbot 플러그인 설치 금지(2026-07-19 사고 — awscli·certbot 동반 파손됨. hook 방식이 정답).

### CloudFront / 보안그룹 — 건드리면 안 되는 것

| 웹 배포 | `E37OL8Q9Q1FSLZ` (prafta.com) | 오류페이지 404/403→/index.html+200 유지 (SPA) |
