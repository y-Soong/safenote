## 1. ★최우선 — 운영 DB 취약점 점검 (5분)

**배경**: 회원가입 요청에 권한을 실어 보내면 그대로 계정 권한이 되는 취약점이 **운영에 살아 있었다**.
`authCd:"master"` 로 가입하면 회사 전체 권한 계정이 완성됐다(승인제 이전엔 즉시 활성화라 곧바로 장악 가능).
→ **이번 배포로 차단 완료**(가입·재가입·승인 3경로 전부 일반 등급 고정 + 요청 필드 제거).

**개발 DB 점검 결과: 악용 흔적 없음.** 권한 상승 계정은 전부 초기 시드(3) + 프로비저닝/관리자 생성분.
**운영 DB 에서 아래 쿼리로 직접 확인할 것:**

```sql
SELECT CMPNY_CD, USER_CD, USER_ID, AUTH_CD, ACCOUNT_STATUS, INSERT_NO, INSERT_DATE
FROM tb_user
WHERE AUTH_CD <> '99999'
ORDER BY INSERT_DATE DESC;
```

**판독법**
- `INSERT_NO` 가 관리자 USER_CD(숫자) → 관리자가 User_01 에서 만든 계정. 정상.
- `INSERT_NO='SYSTEM'` + 초기 구축 시점(2026-04~06) → 시드 계정. 정상.
- `INSERT_NO='SYSTEM'` + **최근 날짜** + `master`/`hr` → ⚠️ **셀프가입 경유 의심. 즉시 보고 필요.**

발견 시 조치: 해당 계정 `AUTH_CD='99999'` 로 정정 + 접속 이력 확인.
