## 0. 왜 다시 해야 하나 (1차 시도 결과 해석)

**1차 시도(08-19)**: 근로자의 근태 생성 요청 푸시를 관리자 폰에서 탭 → 앱은 열렸으나
사용자(근로자) 메인화면으로 진입. 해당 승인 화면도, 관리자 모드 메인도 아니었음.

**판정: 버그 아님. 그러나 B-6 통과로 인정 불가.**

`pushRouteBridge.js` 의 라우팅 분기는 **2개 타입만** 처리한다.

```js
switch (data.type) {
  case 'TRANSFER_RESERVED':  → 소속이동 안내 시트
  case 'SELFJOIN_PENDING':   → /AdminSelfJoin
  default:                   → console.log('미지원 푸시 type') 후 무시   ← 1차 시도가 여기
}
```

백엔드가 실제 발송하는 타입은 6종 이상이며, 라우팅이 있는 건 위 2종뿐이다.

| 타입 | 라우팅 |
|---|---|
| `TRANSFER_RESERVED` | ✅ |
| `SELFJOIN_PENDING` | ✅ |
| `ATTD_LATE_EARLY_DETECTED` | ❌ |
| `LEAVE_DIRECT_SET` | ❌ |
| `RISK_ASSESS_REQUESTED` | ❌ |
| `SHIFT_SCH_CHANGED` | ❌ |
| 승인 결과(`ApprovalResult*`) | ❌ |

### ★판정 불가인 결정적 이유

1차 시도의 결과는 아래 두 경우를 **구분하지 못한다**.

| | 콜백 상태 | 화면 결과 |
|---|---|---|
| **(가) 정상** | `__onPushOpened` 호출됨 → `default:` 분기 → 무시 | 메인화면 |
| **(나) 고장** | `__onPushOpened` 아예 미호출(원격 Vue 에 부재/등록 실패) | 메인화면 |

**둘 다 동일한 화면**이 나온다. 지시서 §7 판정 원칙("화면이 뜨는가가 아니라 **어떻게** 떴는가")이
경고한 상황이다. → **라우팅이 실재하는 타입으로 재시험해야 한다.**

### 1차 시도로 확인된 것 (유효분)

- 푸시 탭 시 앱이 **콜드 스타트로 정상 기동**(크래시·흰 화면 없음) — B-6 의 절반은 확인됨

## 1. 시험 전 확인 — 앱을 다시 빌드해야 하는가?

### 답: **폰에서 30초 만에 확인 가능하며, 대개 재빌드 불필요하다.**

**확인 방법**: 앱 → **마이페이지 하단 버전 표기**를 본다.

**★판정은 오직 `· bundle` / `· remote` 접미의 유무로 한다. 버전 숫자는 판정과 무관하다.**

| 표기 | 의미 | 조치 |
|---|---|---|
| `PRAFTA v1.0.1 · bundle` | ✅ **원격로딩 셸 탑재됨** (현재 번들 모드) | **재빌드 불필요** — §2 로 진행 |
| `PRAFTA v1.0.1 · remote · b1c3b226` | ✅ 원격로딩 셸 + 이미 원격 모드 | 재빌드 불필요 |
| `PRAFTA v1.0.0` **(접미 없음)** | ❌ **구셸** — 머지(`712a5f0`) 이전 빌드 | **재빌드·재설치 필요** |

원리(`MyPageView.vue:390-399`):

```js
const shell = getShellInfo()
if (!shell) return 'PRAFTA v1.0.0'         // ← 구셸: __SHELL__ 부재 → 고정 문자열 반환하고 끝
const ver = shell.appVersion ? `v${shell.appVersion}` : 'v1.0.0'
parts.push(`PRAFTA ${ver}`)
if (shell.loadSource) parts.push(shell.loadSource)   // 'bundle' | 'remote'
if (buildCommit) parts.push(buildCommit)             // 원격 산출물에만 주입됨
```

> ⚠️ **`v1.0.0` 이라는 숫자가 두 경로에서 나온다** — 구셸 폴백값이자 `appVersion` 부재 시 기본값.
> 그래서 숫자만으로는 구분할 수 없다. **구셸은 구조상 `· bundle` 이 붙을 수 없으므로**,
> 접미가 보이면 그 폰은 이미 시험 대상 자격을 갖춘 것이다.
>
> 참고: 현행 `pubspec.yaml` = `version: 1.0.1+4` → 정상 표기는 **`PRAFTA v1.0.1 · bundle`**.

### 재빌드가 필요한 경우

```
cd C:\PRAFTA\PRAFTA_FLUTTER\safenote
flutter build apk --release --dart-define=APP_BASE_URL=https://api.prafta.com
```

> ⚠️ **`APP_BASE_URL` dart-define 누락 금지.** 누락 시 상대경로 폴백으로 원격 오리진에서
> 전 API 404 가 된다(§6-1 추가 발견). iOS 는 Codemagic 동일 define 으로 빌드.

## 2. 시험 구조 — 2단계로 나눠 판정한다

```
[Phase 1] 번들 모드 (현재 상태 그대로)   ← 기준선 확보. 빌드·배포 변경 없음
    ↓ 통과 시
[Phase 2] 원격 모드 (enabled:true 일시 전환)  ← B-6 실판정
```

**Phase 1 이 필요한 이유**: Phase 2 가 실패했을 때 "원격 전환 탓"인지 "라우팅 자체가 원래 안 되는지"를
가릴 수 없다. 먼저 번들에서 되는 걸 확인해 두면 Phase 2 실패 시 원인이 원격 전환으로 특정된다.

### ★순환 구조에 대한 참고

B-6 은 원격 모드에서 판정해야 하는데, 원격 모드는 `enabled:true`(3단계 전환)가 필요하다.
따라서 **Phase 2 자체가 3단계 전환의 리허설**이다. 켜고 → 시험하고 → (실패 시) 즉시 끄면 된다.
전환/회귀 각각 수 초이며, 원격으로 서빙되는 Vue 는 **번들과 동일 커밋**(`b1c3b226`)이라
화면 내용은 달라지지 않는다. 바뀌는 것은 "어디서 받아오는가"뿐이다.

## 3. 시나리오 선택 — `SELFJOIN_PENDING` 권장

| 타입 | 트리거 | 수신자 | 기대 결과 | 판정 난이도 |
|---|---|---|---|---|
| **`SELFJOIN_PENDING`** ★권장 | 셀프가입 신청 발생 | 해당 사업장 **관리자** | **`/AdminSelfJoin` 화면으로 진입** | **쉬움** — 다른 화면이라 눈에 바로 보임 |
| `TRANSFER_RESERVED` | 소속이동 예약 | 대상 **근로자** | 메인화면 + **소속이동 안내 시트 표시** | 보통 — 시트를 놓치면 애매 |

**전제 조건 (엄수)**
- **로그인 상태여야 한다.** `TRANSFER_RESERVED` 는 토큰 부재 시 라우팅을 명시적으로 스킵하며,
  `SELFJOIN_PENDING` 도 화면 진입 후 서버 인가를 받아야 목록이 보인다.
- **앱이 완전히 종료된 상태**에서 탭한다(백그라운드 아님) — B-6 은 콜드 스타트 경로 시험이다.

## 4. 실행 절차

### Phase 1 — 번들 모드 기준선 (현재 상태, 변경 없음)

| # | 행동 | 확인 |
|---|---|---|
| 1 | 관리자 폰에서 앱 실행 → **마이페이지 버전 표기 확인** | `bundle` 표기 있음 (없으면 §1 재빌드) |
| 2 | 관리자 계정 **로그인 상태** 확인 | 로그인됨 |
| 3 | 앱을 **완전 종료** (최근 앱 목록에서 스와이프 제거) | — |
| 4 | 셀프가입 신청 발생시켜 푸시 수신 | 알림 도착 |
| 5 | **알림 탭** | ✅ **`/AdminSelfJoin` 화면 진입** |

**Phase 1 실패 시**: 원격 전환과 무관한 기존 결함이다. 여기서 중단하고 원인 조사.

### Phase 2 — 원격 모드 실판정 ★

| # | 행동 | 확인 |
|---|---|---|
| 1 | 원격 활성화 (아래 명령) | 매니페스트 `enabled:true` |
| 2 | 폰에서 앱 **완전 종료 후 재실행** | — |
| 3 | 마이페이지 버전 표기 확인 | ✅ **`remote` + 배포해시** 표기로 변경됨 |
| 4 | 앱을 **완전 종료** | — |
| 5 | 셀프가입 신청 발생시켜 푸시 수신 → **알림 탭** | ✅ **`/AdminSelfJoin` 화면 진입** |
| 6 | (안드로이드·iOS 각각 수행) | 양 플랫폼 통과 |

**원격 활성화**
```powershell

powershell -ExecutionPolicy Bypass -File .\scripts\deploy-app-web.ps1 -ManifestOnly -RemoteEnabled
```

**즉시 회귀 (이상 시 / 시험 후 되돌릴 때)**

## 5. 판정 기준

| 결과 | 판정 | 다음 조치 |
|---|---|---|
| Phase 1 ✅ + Phase 2 ✅ (양 플랫폼) | **B-6 통과** | `enabled:true` 유지 → **3단계 전환 완료**. 수일 관찰 |

이 로그가 보이면 (가)/(나) 구분이 가능해져, 라우팅 없는 타입으로도 판정할 수 있다.

## 6. 별도 기록 — 푸시 라우팅 미구현 4종 이상

이번 조사에서 드러난 사안으로, **원격 로딩 전환과는 무관한 별건**이다.

백엔드 발송 타입 6종 이상 중 라우팅이 있는 것은 2종뿐이다. 나머지(`ATTD_LATE_EARLY_DETECTED`,
`LEAVE_DIRECT_SET`, `RISK_ASSESS_REQUESTED`, `SHIFT_SCH_CHANGED`, 승인 결과)는 알림을 탭해도
메인화면으로만 떨어진다. 사용자 체감상 **"알림을 눌렀는데 그 화면이 안 열린다"** 가 된다.

`pushRouteBridge.js` 의 `routeByPushType()` 에 case 를 추가하는 구조라 확장은 어렵지 않으나,
**대상 화면 결정·인가 처리·payload 에 필요한 식별자(예: 승인 대상 reqId) 동반 여부**를
타입별로 정해야 한다. 착수 시 별도 요청서로 분리 권장.
