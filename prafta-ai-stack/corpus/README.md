# corpus/ — 원본 자료 스테이징

작업지시서(`.claude/refs/작업지시서_AI코퍼스_수집적재_파이프라인.md`) §2 구조를 따르는 자료 보관소.
**지금 단계는 "받은 원본을 안전하게 쌓아두는 것"까지**다. 실제 전처리/청킹/적재 파이프라인은
미결정 항목(§7) 확정 후 별도 착수한다.

## 어디에 무엇을 넣나

```
corpus/
├─ raw/         ← ★여기에 받은 원본 파일을 그대로 넣는다 (무변경). git 제외됨.
├─ registry/    ← sources.xlsx(출처·라이선스 대장) + api_access.xlsx(활용기간 등). 사람이 채운다.
├─ processed/   ← 마스킹·정제 중간 산출물. 파이프라인이 생성. git 제외됨.
└─ chunks/      ← 청킹 결과(적재 직전). 파이프라인이 생성. git 제외됨.
```

- **raw/ 에만 넣으면 된다.** processed/·chunks/ 는 파이프라인이 자동 생성하므로 비워둔다.
- raw/·processed/·chunks/ 는 `.gitignore` 로 **커밋 차단**돼 있다(PII·용량). 안심하고 넣어도 된다.

## 파일 이름 규칙 (권장)

작업지시서 예시대로 `{데이터셋ID}_{자료명}_{기준일}.{확장자}` 형식:

```
raw/15108262_건설안전사고사례_20250630.csv
raw/15140383_SIF_아카이브_20260401.xlsx
```

- 맨 앞 숫자 = **data.go.kr 데이터셋 ID**. 이걸 SOURCE_ID로 고정하면 자료가 버전 갱신돼도
  같은 ID로 추적된다(SIF는 실제로 4,432→6,032건 증분 이력 있음).
- ID를 모르면 일단 알아보기 쉬운 이름으로 넣어도 된다. 정식 매핑은 registry 채울 때 확정.

## 형식 메모

- CSV: 한글 공공데이터는 대개 **cp949(euc-kr)** 인코딩. 그대로 넣으면 됨(파이프라인이 인코딩 처리).
- XLSX: SIF처럼 시트가 여러 개면 그대로. 파이프라인이 시트별로 분기 처리.
- 원본은 **절대 수정하지 말 것**(하드가드: raw 무변경). 열어보고 싶으면 사본으로.

## ⚠️ 주의 (넣기만 하고, 아직 처리는 안 함)

- **라이선스 판정은 사람이 채팅에서 확정**해야 처리된다(하드가드 #1). 파일을 넣는 것과
  무관하게, `registry/sources.xlsx` 에 `license_checked=TRUE` 가 없으면 파이프라인이 건너뛴다.
- 즉 지금은 자유롭게 raw/ 에 쌓아두면 되고, 어떤 자료를 실제 적재할지는 나중에 함께 정한다.
